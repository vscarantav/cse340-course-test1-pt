Fundamentos do SQL: Chaves, Restrições e Conceitos Básicos

Antes de mergulharmos nas diversas categorias de linguagem SQL e operações CRUD, é essencial entender alguns conceitos fundamentais que formam a base do projeto de banco de dados relacional. Nesta tarefa de leitura, exploraremos conceitos-chave de banco de dados, incluindo chaves primárias, chaves estrangeiras e restrições no PostgreSQL.

Tabelas

Em um banco de dados relacional, os dados são organizados em tabelas (também chamadas de relações). Cada tabela consiste em linhas (registros) e colunas (campos). Pense em uma tabela como algo semelhante a uma planilha, onde cada coluna representa um atributo ou dado específico, cada linha representa um único registro ou entidade, e a interseção de uma linha e coluna contém um valor de dado específico.

Aqui está um exemplo de uma simples students tabela no PostgreSQL: 


        CREATE TABLE students (
            student_id SERIAL,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL,
            email VARCHAR(100),
            date_of_birth DATE,
            enrollment_date DATE DEFAULT CURRENT_DATE
        );

Neste exemplo, student_id, first_name, last_name, etc. são colunas. SERIAL, VARCHAR(50), DATE, etc. são tipos de dados. NOT NULL e DEFAULT CURRENT_DATE são restrições que impõem regras específicas sobre os dados.

Chaves

As chaves são elementos essenciais em bancos de dados relacionais que garantem que cada registro possa ser identificado de forma única e que os relacionamentos entre tabelas sejam mantidos adequadamente. Elas desempenham um papel crítico na aplicação da integridade dos dados, prevenindo registros duplicados ou órfãos e definindo como os dados em diferentes tabelas estão conectados. Compreender as chaves é fundamental para projetar bancos de dados confiáveis e eficientes.

Chaves Primárias

Uma chave primária é uma coluna ou combinação de colunas que identifica exclusivamente cada linha em uma tabela. As chaves primárias são fundamentais para o projeto de banco de dados, pois garantem que cada registro possa ser identificado de forma única, fornecem uma maneira de referenciar registros específicos e impõem a integridade dos dados, evitando entradas duplicadas.

No PostgreSQL, podemos definir uma chave primária ao criar uma tabela: 


        CREATE TABLE students (
            student_id SERIAL PRIMARY KEY,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL,
            email VARCHAR(100)
        );
Características da Chave Primária

Uma chave primária deve ser única (cada valor deve ser diferente de todos os outros valores na coluna), não nula (o valor não pode ser vazio ou nulo), e imutável (uma vez atribuído, o valor não deve mudar, o que é uma boa prática, embora não seja estritamente imposto pelo banco de dados).

O SERIAL tipo de dado no PostgreSQL cria automaticamente uma sequência que gera valores inteiros únicos, tornando-o ideal para chaves primárias. É equivalente a: 


        student_id INTEGER NOT NULL DEFAULT nextval('students_student_id_seq')

Você também pode criar uma chave primária composta usando várias colunas: 


        CREATE TABLE course_enrollments (
            student_id INTEGER,
            course_id INTEGER,
            enrollment_date DATE,
            PRIMARY KEY (student_id, course_id)
        );

Chaves Estrangeiras

Uma chave estrangeira é uma coluna ou grupo de colunas em uma tabela que referencia a chave primária de outra tabela. As chaves estrangeiras criam relacionamentos entre tabelas, garantem a integridade referencial e evitam ações que destruiriam os links entre as tabelas.

Veja como criar uma chave estrangeira no PostgreSQL: 


        CREATE TABLE courses (
            course_id SERIAL PRIMARY KEY,
            course_name VARCHAR(100) NOT NULL,
            department VARCHAR(50),
            credits INTEGER
        );

        CREATE TABLE enrollments (
            enrollment_id SERIAL PRIMARY KEY,
            student_id INTEGER NOT NULL,
            course_id INTEGER NOT NULL,
            grade CHAR(2),
            FOREIGN KEY (student_id) REFERENCES students (student_id),
            FOREIGN KEY (course_id) REFERENCES courses (course_id)
        );

Neste exemplo, student_id na enrollments tabela é uma chave estrangeira que referencia a student_id chave primária na students tabela. Isso cria um relacionamento no qual cada matrícula deve estar associada a um aluno válido.

Integridade Referencial

As chaves estrangeiras mantêm a integridade referencial garantindo que você não possa adicionar um registro à tabela filha (enrollments) se a chave referenciada não existir na tabela pai (students), e você não pode excluir um registro da tabela pai se ele for referenciado por registros na tabela filha (a menos que especifique uma ação como CASCADE).

Restrições

Restrições são regras aplicadas a colunas de tabelas para impor a integridade dos dados. Elas ajudam a garantir que apenas dados válidos, consistentes e confiáveis sejam armazenados em seu banco de dados, impondo requisitos ou restrições específicas sobre os valores que podem ser inseridos.

Restrição NOT NULL

A restrição NOT NULL garante que uma coluna não pode ter um valor nulo, o que significa que um valor deve ser fornecido. 


        CREATE TABLE students (
            student_id SERIAL PRIMARY KEY,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL,
            email VARCHAR(100)
        );

Neste exemplo, first_name e last_name não podem ser nulos, mas email pode ser nulo.

Restrição UNIQUE

A restrição UNIQUE garante que todos os valores em uma coluna sejam diferentes. Ao contrário das chaves primárias, as restrições de unicidade podem permitir valores nulos (a menos que combinadas com NOT NULL) e podem ser aplicadas a várias colunas em uma tabela. 


        CREATE TABLE students (
            student_id SERIAL PRIMARY KEY,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL,
            email VARCHAR(100) UNIQUE,
            student_number VARCHAR(10) UNIQUE NOT NULL
        );
PRIMARY KEY vs. Restrição UNIQUE

Uma chave primária é automaticamente única e não nula. As principais diferenças são: uma tabela pode ter apenas uma chave primária, mas várias restrições de unicidade; as restrições de unicidade podem permitir valores nulos (a menos que combinadas com NOT NULL), enquanto as chaves primárias não podem; e as chaves primárias são tipicamente usadas como o identificador principal de um registro, enquanto as restrições de unicidade impõem a unicidade para outros atributos.

Restrição CHECK

A restrição CHECK garante que todos os valores em uma coluna satisfaçam uma condição específica. 


        CREATE TABLE products (
            product_id SERIAL PRIMARY KEY,
            product_name VARCHAR(100) NOT NULL,
            price DECIMAL(10,2) CHECK (price > 0),
            discount_percent DECIMAL(5,2) CHECK (discount_percent >= 0 AND discount_percent <= 100)
        );

Neste exemplo, as restrições CHECK garantem que price seja sempre maior que zero e discount_percent esteja entre 0 e 100.

Restrição DEFAULT

A restrição DEFAULT fornece um valor padrão para uma coluna quando nenhum valor é especificado durante uma inserção. 


        CREATE TABLE orders (
            order_id SERIAL PRIMARY KEY,
            customer_id INTEGER NOT NULL,
            order_date DATE DEFAULT CURRENT_DATE,
            status VARCHAR(20) DEFAULT 'Pending'
        );

Neste exemplo, se nenhum valor for fornecido para order_date, o valor padrão será a data atual, e se nenhum valor for fornecido para status, o valor padrão será 'Pending'.

Relacionamentos entre tabelas

Os bancos de dados relacionais derivam seu poder da capacidade de estabelecer relacionamentos entre tabelas. Esses relacionamentos são implementados usando chaves estrangeiras e ajudam a modelar conexões do mundo real entre diferentes tipos de dados.

Um para Um (1:1)

Em um relacionamento um para um, um registro na primeira tabela está relacionado a exatamente um registro na segunda tabela. 


        CREATE TABLE students (
            student_id SERIAL PRIMARY KEY,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL
        );

        CREATE TABLE student_details (
            detail_id SERIAL PRIMARY KEY,
            student_id INTEGER UNIQUE,  -- Ensures one-to-one relationship
            address TEXT,
            phone VARCHAR(20),
            medical_notes TEXT,
            FOREIGN KEY (student_id) REFERENCES students (student_id)
        );

A restrição UNIQUE em student_id na tabela student_details garante que cada estudante possa ter apenas um registro de detalhes.

Um para Muitos (1:N)

Em um relacionamento um para muitos, um registro na primeira tabela pode estar relacionado a vários registros na segunda tabela, mas cada registro na segunda tabela está relacionado a apenas um registro na primeira tabela. 


        CREATE TABLE departments (
            department_id SERIAL PRIMARY KEY,
            department_name VARCHAR(100) NOT NULL
        );

        CREATE TABLE employees (
            employee_id SERIAL PRIMARY KEY,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL,
            department_id INTEGER,
            FOREIGN KEY (department_id) REFERENCES departments (department_id)
        );

Neste exemplo, um departamento pode ter muitos funcionários, mas cada funcionário pertence a apenas um departamento.

Muitos para Muitos (N:M)

Em um relacionamento muitos para muitos, um registro na primeira tabela pode estar relacionado a vários registros na segunda tabela e vice-versa. Isso requer uma tabela de junção (também chamada de tabela de ponte ou de ligação). 


        CREATE TABLE students (
            student_id SERIAL PRIMARY KEY,
            first_name VARCHAR(50) NOT NULL,
            last_name VARCHAR(50) NOT NULL
        );

        CREATE TABLE courses (
            course_id SERIAL PRIMARY KEY,
            course_name VARCHAR(100) NOT NULL,
            credits INTEGER
        );

        -- Junction table for the many-to-many relationship
        CREATE TABLE enrollments (
            student_id INTEGER,
            course_id INTEGER,
            enrollment_date DATE DEFAULT CURRENT_DATE,
            grade CHAR(2),
            PRIMARY KEY (student_id, course_id),  -- Composite primary key
            FOREIGN KEY (student_id) REFERENCES students (student_id),
            FOREIGN KEY (course_id) REFERENCES courses (course_id)
        );

Neste exemplo, um estudante pode se matricular em muitos cursos, um curso pode ter muitos estudantes, e a enrollments tabela de junção resolve esse relacionamento muitos para muitos criando dois relacionamentos um para muitos.

Tipos de dados básicos no PostgreSQL

O PostgreSQL oferece uma grande variedade de tipos de dados para armazenar diferentes tipos de informações de forma eficiente. Escolher o tipo de dado correto é importante tanto para o desempenho quanto para a integridade dos dados.

Tipos numéricos

  • INTEGER ou INT - Números inteiros (sem decimais)
  • SERIAL - Inteiro de incremento automático, tipicamente usado para IDs
  • DECIMAL(p,s) ou NUMERIC(p,s) - Numérico exato com precisão (p) e escala (s) especificadas
  • REAL, DOUBLE PRECISION - Números de ponto flutuante

Tipos de caractere

  • CHAR(n) - String de caracteres de tamanho fixo
  • VARCHAR(n) - String de caracteres de tamanho variável com um limite
  • TEXT - String de caracteres de tamanho variável sem um limite especificado

Tipos de data e hora

  • DATE - Data do calendário (ano, mês, dia)
  • TIME - Hora do dia
  • TIMESTAMP - Data e hora
  • INTERVAL - Período de tempo

Tipos booleanos e outros tipos

  • BOOLEAN - Armazena valores verdadeiro/falso
  • UUID - Identificadores universalmente exclusivos
  • JSON, JSONB - Dados JSON
  • ARRAY - Array de um tipo específico

Resumo dos Conceitos-Chave

Esta leitura apresentou a você conceitos fundamentais do SQL no PostgreSQL que formam o fundamento do design de banco de dados relacional. Você aprendeu que as tabelas organizam dados em linhas e colunas, com cada tabela representando uma entidade ou conceito específico em sua aplicação.

As chaves primárias servem como identificadores exclusivos para cada registro e são automaticamente exclusivas e não nulas. As chaves estrangeiras estabelecem relacionamentos entre tabelas e aplicam a integridade referencial, garantindo que as conexões de dados permaneçam válidas. Restrições como NOT NULL, UNIQUE, CHECK e DEFAULT aplicam regras de integridade de dados, impedindo que dados inválidos ou inconsistentes entrem em seu banco de dados.

Você também explorou os três tipos principais de relacionamentos: um para um (onde os registros correspondem diretamente), um para muitos (o tipo mais comum, onde um registro se relaciona com vários outros) e muitos para muitos (que exige tabelas de junção para resolver a complexidade). Por fim, você aprendeu sobre o rico conjunto de tipos de dados do PostgreSQL, desde inteiros e texto básicos até tipos mais avançados, como JSON e arrays.

Entender esses conceitos é essencial antes de se aprofundar nas categorias da linguagem SQL (DDL, DML, DQL, etc.) e nas operações CRUD. Na próxima tarefa de leitura, usaremos esse fundamento como base para explorar como interagir com bancos de dados por meio de diferentes tipos de comandos SQL.
