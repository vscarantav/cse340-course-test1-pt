Passagem por Valor vs Passagem por Referência no JavaScript

Compreender como o JavaScript lida com dados ao passá-los para funções é fundamental para escrever código previsível e livre de bugs. A distinção entre passagem por valor e passagem por referência afeta como suas funções interagem com os dados e pode levar a comportamentos inesperados se não for devidamente compreendida.

Este conceito fundamental determina se as alterações feitas dentro de uma função afetam os dados originais fora da função. O comportamento depende inteiramente do tipo de dado com o qual você está trabalhando.

Compreendendo a Passagem por Valor

Passagem por valor significa que, quando você passa uma variável para uma função, o JavaScript cria uma cópia do valor dessa variável. Qualquer alteração feita no parâmetro dentro da função afeta apenas a cópia, não a variável original.

No JavaScript, todos os tipos de dados primitivos são passados por valor. Estes incluem números, strings, booleanos, nulo, undefined e symbols. Quando você passa um valor primitivo para uma função, está essencialmente entregando à função uma fotocópia dos seus dados. 


        function modifyNumber(num) {
            num = num + 10;
            console.log("Inside function:", num); // 25
        }

        let originalNumber = 15;
        modifyNumber(originalNumber);
        console.log("Outside function:", originalNumber); // Still 15

Neste exemplo, a originalNumber permanece inalterada porque o JavaScript criou uma cópia do seu valor (15) e passou essa cópia para a função. A função modificou a cópia, não o original.

Exemplo de String

As strings se comportam da mesma maneira, embora possam parecer estruturas de dados complexas: 


        function modifyString(str) {
            str = str + " - modified";
            console.log("Inside function:", str); // "Hello - modified"
        }

        let originalString = "Hello";
        modifyString(originalString);
        console.log("Outside function:", originalString); // Still "Hello"

Compreendendo a Passagem por Referência

Passagem por referência significa que, quando você passa uma variável para uma função, o JavaScript passa uma referência (ou ponteiro) para os dados originais na memória. Isso significa que a função pode modificar diretamente a estrutura de dados original.

No JavaScript, objetos (incluindo arrays, funções e datas) são passados por referência. Quando você passa um objeto para uma função, está dando à função acesso ao objeto real na memória, não a uma cópia. 


        function modifyObject(obj) {
            obj.name = "Jane";
            obj.age = 30;
            console.log("Inside function:", obj); // { name: "Jane", age: 30 }
        }

        let person = { name: "John", age: 25 };
        modifyObject(person);
        console.log("Outside function:", person); // { name: "Jane", age: 30 }

Observe como o person objeto original foi modificado pela função. Isso acontece porque tanto a person variável quanto o obj parâmetro apontam para o mesmo objeto na memória.

Exemplo de Array

Os arrays se comportam da mesma maneira, pois são objetos no JavaScript: 


        function modifyArray(arr) {
            arr.push("new item");
            arr[0] = "modified";
            console.log("Inside function:", arr); // ["modified", "b", "c", "new item"]
        }

        let originalArray = ["a", "b", "c"];
        modifyArray(originalArray);
        console.log("Outside function:", originalArray); // ["modified", "b", "c", "new item"]

A Distinção Crítica: Atribuição vs Modificação

Existe uma nuance importante ao trabalhar com objetos e referências. Embora você possa modificar o conteúdo de um objeto por meio de uma referência, não pode reatribuir a própria referência para apontar para um objeto completamente diferente. 


        /**
         * Copy-paste this code in your browsers dev console to see the results in action.
         */

        function reassignObject(obj) {
            // This modifies the original object
            obj.name = "Modified";
            
            // This creates a new local variable, doesn't affect the original
            obj = { name: "Completely New", age: 99 };
            console.log("Inside function after reassignment:", obj);
        }

        let person = { name: "John", age: 25 };
        reassignObject(person);
        console.log("Outside function:", person); // { name: "Modified", age: 25 }

Neste exemplo, modificar obj.name altera o objeto original porque estamos modificando o objeto para o qual a referência aponta. No entanto, quando atribuímos obj a um objeto completamente novo, estamos apenas alterando para onde a obj variável local aponta, sem afetar a person variável original.

Perspectiva da Memória

Pense em referências como endereços. Quando você passa um objeto por referência, está dando à função o endereço onde o objeto reside. A função pode visitar esse endereço e modificar o objeto, mas não pode alterar para onde a sua variável original aponta. Essa abordagem permite o uso eficiente da memória e evita duplicações desnecessárias (overhead adicional), e é por isso que a passagem por referência é comum em muitas linguagens de programação.

Implicações Práticas e Armadilhas Comuns

Compreender a passagem por valor vs passagem por referência é essencial para evitar bugs e escrever código previsível. Aqui estão alguns cenários comuns em que esse conhecimento é fundamental:

Mutações Inesperadas de Objetos

Um dos problemas mais comuns ocorre quando funções modificam objetos não intencionalmente: 


        function calculateDiscount(product, discountPercent) {
            product.price = product.price * (1 - discountPercent / 100);
            return product;
        }

        let originalProduct = { name: "Laptop", price: 1000 };
        let discountedProduct = calculateDiscount(originalProduct, 10);

        console.log("Original:", originalProduct); // { name: "Laptop", price: 900 }
        console.log("Discounted:", discountedProduct); // { name: "Laptop", price: 900 }

Neste exemplo, o produto original foi modificado não intencionalmente. Para evitar isso, você deve criar uma cópia do objeto antes de modificá-lo: 


        function calculateDiscountSafely(product, discountPercent) {
            // Create a shallow copy of the object
            let productCopy = { ...product };
            productCopy.price = productCopy.price * (1 - discountPercent / 100);
            return productCopy;
        }

        let originalProduct = { name: "Laptop", price: 1000 };
        let discountedProduct = calculateDiscountSafely(originalProduct, 10);

        console.log("Original:", originalProduct); // { name: "Laptop", price: 1000 }
        console.log("Discounted:", discountedProduct); // { name: "Laptop", price: 900 }

Arrays e Compartilhamento de Referência

Problemas semelhantes podem ocorrer com arrays quando múltiplas variáveis referenciam o mesmo array: 


        let numbers = [1, 2, 3, 4, 5];
        let evenNumbers = numbers; // This creates a reference, not a copy!

        // Attempting to filter even numbers, but modifying the original
        for (let i = numbers.length - 1; i >= 0; i--) {
            if (numbers[i] % 2 !== 0) {
                numbers.splice(i, 1);
            }
        }

        console.log("Numbers:", numbers); // [2, 4]
        console.log("Even Numbers:", evenNumbers); // [2, 4] - Same as numbers!

Para criar uma cópia real de um array, use métodos como o operador spread ou Array.from(): 


        let numbers = [1, 2, 3, 4, 5];
        let evenNumbers = [...numbers]; // Creates a copy

        // Or use filter method for a cleaner approach
        evenNumbers = numbers.filter(num => num % 2 === 0);

        console.log("Numbers:", numbers); // [1, 2, 3, 4, 5] - Unchanged
        console.log("Even Numbers:", evenNumbers); // [2, 4]

Comparação com Outras Linguagens de Programação

Diferentes linguagens de programação lidam com passagem por valor e passagem por referência de várias maneiras. Entender essas diferenças ajuda ao trabalhar em ambientes de múltiplas linguagens ou ao transitar entre linguagens.

PHP

O PHP se comporta de maneira semelhante ao JavaScript para tipos primitivos (passagem por valor), mas possui uma sintaxe explícita para passagem por referência. No PHP, você deve usar o símbolo e comercial (&) para passar por referência: 


        // Pass by value (default in PHP)
        function modifyValue($num) {
            $num = $num + 10;
        }

        // Pass by reference (explicit with &)
        function modifyReference(&$num) {
            $num = $num + 10;
        }

        $original = 5;
        modifyValue($original);        // $original remains 5
        modifyReference($original);    // $original becomes 15

Objetos em PHP são passados automaticamente por referência (como no JavaScript), mas o PHP oferece controle explícito sobre quando usar referências para outros tipos de dados.

Java

O Java é sempre passagem por valor, mas isso pode ser confuso com objetos. O Java passa o valor da referência (uma cópia do endereço de memória), não a referência em si. Isso significa que você pode modificar o objeto para o qual a referência aponta, mas não pode reatribuir a referência para apontar para um objeto diferente: 


        // Java behavior is similar to JavaScript for objects
        public void modifyObject(Person person) {
            person.setName("Jane");  // This works - modifies original object
            person = new Person("Bob"); // This doesn't affect the original
        }

Python

O Python usa um modelo chamado "passagem por referência de objeto" ou "passagem por atribuição". O comportamento depende de o objeto ser mutável ou imutável: 


        # Immutable objects (int, string, tuple) behave like pass by value
        def modify_number(x):
            x = x + 10  # Creates new object, doesn't affect original

        # Mutable objects (list, dict) behave like pass by reference  
        def modify_list(lst):
            lst.append(4)  # Modifies original list

C++

O C++ oferece controle explícito tanto sobre a passagem por valor quanto sobre a passagem por referência com sintaxes diferentes: 


        void passByValue(int x);      // Copy of value
        void passByReference(int& x); // Reference to original
        void passByPointer(int* x);   // Pointer to memory address
Filosofia de Design da Linguagem

A abordagem do JavaScript equilibra simplicidade com funcionalidade. Primitivos são copiados (evitando modificações acidentais), enquanto objetos são referenciados (permitindo um uso eficiente de memória e modificações intencionais). Outras linguagens fazem concessões diferentes com base em seus objetivos de design e casos de uso.

Boas Práticas para JavaScript

Entender a diferença entre passagem por valor e passagem por referência permite que você escreva um código JavaScript mais previsível e de fácil manutenção. Aqui estão as principais práticas a serem seguidas:

  • Seja intencional sobre a modificação de objetos: Decida se sua função deve modificar o objeto original ou criar um novo
  • Use a desestruturação de objetos e a sintaxe spread para criar cópias quando necessário: let copy = { ...original }
  • Considere usar padrões de programação imutáveis onde os objetos nunca são modificados, apenas substituídos por novas versões
  • Documente o comportamento das funções: Deixe claro se as funções modificam os parâmetros de entrada ou retornam novos valores
  • Use métodos de array como map, filter e reduce que retornam novos arrays em vez de modificar os existentes

Essas práticas ajudam a prevenir bugs e tornam seu código mais fácil de raciocinar, especialmente ao trabalhar em equipes ou manter grandes aplicações.

Resumo dos Conceitos-Chave

Compreender a passagem por valor vs. passagem por referência é fundamental para escrever código JavaScript previsível. Tipos primitivos criam cópias seguras que não podem afetar os dados originais, enquanto objetos compartilham referências que permitem a modificação da estrutura de dados original.

Esse conhecimento ajuda você a evitar bugs comuns, escrever funções mais confiáveis e entender como seus dados fluem pela sua aplicação. Quer você esteja trabalhando com valores simples ou objetos complexos, saber quando os dados serão copiados versus referenciados é essencial para uma programação em JavaScript segura.

À medida que você continua desenvolvendo em JavaScript e em outras linguagens, este fundamento conceitual ajudará você a entender rapidamente como cada linguagem lida com a passagem de dados e a tomar decisões informadas sobre a arquitetura do seu código.
