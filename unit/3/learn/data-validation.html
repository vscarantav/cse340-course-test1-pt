Validação de Dados de Formulário: Do Cliente ao Servidor

Quando os usuários enviam formulários em seu site, você não pode confiar que os dados fornecidos por eles sejam válidos, completos ou seguros. A validação de formulários é o processo de verificar a entrada do usuário para garantir que ela atenda aos seus requisitos antes de processá-la. Esta leitura explora tanto a validação do lado do cliente (que melhora a experiência do usuário) quanto a validação do lado do servidor (que protege sua aplicação).

Compreender a validação é crucial porque dados inválidos podem quebrar sua aplicação, corromper seu banco de dados ou até mesmo criar vulnerabilidades de segurança. Você aprenderá como a validação evoluiu do JavaScript personalizado e complexo para funcionalidades modernas do HTML5 e, o mais importante, como validar adequadamente os dados no lado do servidor, onde isso realmente importa.

A Evolução da Validação do Lado do Cliente

Antes de o HTML5 introduzir funcionalidades nativas de validação, os desenvolvedores tinham que escrever um código JavaScript extenso para validar formulários. Essa abordagem antiga exigia a verificação manual de cada campo, a exibição de mensagens de erro e a prevenção do envio do formulário quando a validação falhava.

A Forma Antiga: Validação com JavaScript Personalizado

Veja como os desenvolvedores costumavam validar um formulário de registro simples com JavaScript personalizado. Observe a quantidade de código necessária para uma validação básica: 


        <form id="registrationForm">
            <div>
                <label for="email">Email:</label>
                <input type="text" id="email" name="email">
                <span id="emailError" class="error"></span>
            </div>
            <div>
                <label for="password">Password:</label>
                <input type="password" id="password" name="password">
                <span id="passwordError" class="error"></span>
            </div>
            <div>
                <label for="age">Age:</label>
                <input type="text" id="age" name="age">
                <span id="ageError" class="error"></span>
            </div>
            <button type="submit">Register</button>
        </form>

O código JavaScript de validação correspondente era longo e propenso a erros: 


        document.getElementById('registrationForm').addEventListener('submit', function(event) {
            let isValid = true;
            
            // Clear previous errors
            document.getElementById('emailError').textContent = '';
            document.getElementById('passwordError').textContent = '';
            document.getElementById('ageError').textContent = '';
            
            // Validate email
            const email = document.getElementById('email').value;
            const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
            if (!email) {
                document.getElementById('emailError').textContent = 'Email is required';
                isValid = false;
            } else if (!emailRegex.test(email)) {
                document.getElementById('emailError').textContent = 'Please enter a valid email';
                isValid = false;
            }
            
            // Validate password
            const password = document.getElementById('password').value;
            if (!password) {
                document.getElementById('passwordError').textContent = 'Password is required';
                isValid = false;
            } else if (password.length < 8) {
                document.getElementById('passwordError').textContent = 'Password must be at least 8 characters';
                isValid = false;
            }
            
            // Validate age
            const age = document.getElementById('age').value;
            const ageNumber = parseInt(age);
            if (!age) {
                document.getElementById('ageError').textContent = 'Age is required';
                isValid = false;
            } else if (isNaN(ageNumber) || ageNumber < 13 || ageNumber > 120) {
                document.getElementById('ageError').textContent = 'Please enter a valid age between 13 and 120';
                isValid = false;
            }
            
            // Prevent submission if validation fails
            if (!isValid) {
                event.preventDefault();
            }
        });

Esta abordagem exigia dezenas de linhas de código para uma validação básica, e cada formulário precisava de sua própria lógica de validação personalizada. Manter e fazer a depuração desse código consumia muito tempo e era propenso a erros.

A Forma Moderna: Validação Nativa do HTML5

O HTML5 introduziu funcionalidades de validação nativas poderosas que atingem os mesmos objetivos com muito menos código. Os navegadores modernos lidam automaticamente com a lógica de validação, exibição de erros e prevenção do envio do formulário. 


        <form>
            <div>
                <label for="email">Email:</label>
                <input type="email" id="email" name="email" required>
            </div>
            <div>
                <label for="password">Password:</label>
                <input type="password" id="password" name="password" required minlength="8">
            </div>
            <div>
                <label for="age">Age:</label>
                <input type="number" id="age" name="age" required min="13" max="120">
            </div>
            <button type="submit">Register</button>
        </form>

Essa abordagem moderna usa tipos de entrada e atributos do HTML5 para fornecer a mesma validação sem a necessidade de JavaScript. O navegador valida automaticamente o formato do e-mail, impõe um tamanho mínimo de senha e garante que a idade esteja dentro do intervalo especificado.

Atributos Comuns de Validação do HTML5

O HTML5 fornece muitos atributos de validação: required (o campo deve ser preenchido), minlength e maxlength (limites de comprimento de texto), min e max (intervalos numéricos), pattern (expressões regulares personalizadas) e tipos de entrada especializados como email, url, tel, e date que fornecem validação de formato nativa.

Compreendendo as Limitações da Validação do Lado do Cliente

Embora a validação do lado do cliente melhore bastante a experiência do usuário ao fornecer feedback imediato, é importante entender suas limitações. A validação do lado do cliente serve puramente para conveniência e experiência do usuário — ela nunca deve ser considerada uma medida de segurança.

Os usuários podem facilmente burlar a validação do lado do cliente desativando o JavaScript, modificando o HTML nas ferramentas de desenvolvedor do navegador ou enviando requisições diretamente para o seu servidor usando ferramentas como curl ou Postman. Usuários mal-intencionados podem enviar quaisquer dados que desejarem, independentemente das suas regras de validação do lado do cliente. 


        <!-- A user could modify this in browser dev tools -->
        <input type="email" required minlength="8">
        
        <!-- And change it to this -->
        <input type="text">

Os principais benefícios da validação do lado do cliente são melhorar a experiência do usuário ao capturar erros imediatamente, reduzir a carga do servidor ao evitar envios obviamente inválidos e fornecer um feedback útil antes que os usuários percam tempo enviando dados incorretos. No entanto, você deve sempre validar os dados no lado do servidor, onde os usuários não podem adulterar sua lógica de validação.

Lembrete de Segurança

A validação do lado do cliente serve apenas para a experiência do usuário. Nunca confie nela para segurança, integridade de dados ou aplicação de regras de negócios. Sempre implemente uma validação abrangente no lado do servidor para proteger sua aplicação.

Introdução ao Processamento no Lado do Servidor

Quando um usuário envia um formulário, os dados precisam ser processados no seu servidor. Até agora, você trabalhou com rotas GET que respondem a requisições de página. Os envios de formulário geralmente usam rotas POST, que são projetadas para lidar com operações de envio e modificação de dados.

As requisições POST funcionam de forma diferente das requisições GET. Em vez de passar dados na URL (como parâmetros de consulta), as requisições POST enviam dados no corpo da requisição. Isso permite maiores quantidades de dados e mantém informações sensíveis, como senhas, fora das URLs e do histórico do navegador.

Entendendo os corpos das requisições

O corpo da requisição é onde os dados POST são transmitidos. Quando um usuário envia um formulário, o navegador empacota os dados do formulário e os envia como o corpo da requisição HTTP. Sua aplicação Express precisa de um middleware especial para analisar esses dados do corpo e disponibilizá-los em seus manipuladores de rotas. 


        // Express middleware to parse form data from request bodies
        app.use(express.urlencoded({ extended: true }));
        app.use(express.json()); // For handling JSON data from API requests

Após adicionar este middleware, os dados do formulário ficam disponíveis em seus manipuladores de rotas através do req.body objeto. Cada campo do formulário aparece como uma propriedade neste objeto, com o nome da propriedade correspondendo ao do campo do formulário name atributo.

Criando sua primeira rota POST

As rotas POST lidam com envios de formulários e processamento de dados. Veja como criar uma rota POST básica que recebe dados de registro de usuário: 


        // Handle user registration form submission
        app.post('/register', (req, res) => {
            // Extract data from request body
            const { email, password, age } = req.body;
            
            // Log the received data for debugging
            console.log('Registration data received:', {
                email: email,
                password: password,
                age: age
            });
            
            // For now, just send a simple response
            res.send(`Registration received for ${email}`);
        });

Observe como esta rota usa app.post() em vez de app.get(), e acessa os dados do formulário através de req.body em vez de req.params ou req.query. O formulário que envia para esta rota deve especificar o método e a ação corretos: 


        <form method="POST" action="/register">
            <input type="email" name="email" required>
            <input type="password" name="password" required>
            <input type="number" name="age" required>
            <button type="submit">Register</button>
        </form>

Implementando validação no lado do servidor

A validação no lado do servidor é onde você aplica suas regras de negócio reais e requisitos de segurança. Você deve validar cada dado que os usuários enviam, independentemente de qualquer validação no lado do cliente. Essa validação é executada em seu servidor, onde os usuários não podem modificá-la nem burlá-la.

Abordagem de validação manual

Você pode implementar uma validação básica usando uma lógica simples em JavaScript. Veja como adicionar validação à rota de registro: 


        app.post('/register', (req, res) => {
            const { email, password, age } = req.body;
            const errors = [];
            
            // Validate email
            if (!email) {
                errors.push('Email is required');
            } else if (!email.includes('@') || !email.includes('.')) {
                errors.push('Please provide a valid email address');
            }
            
            // Validate password
            if (!password) {
                errors.push('Password is required');
            } else if (password.length < 8) {
                errors.push('Password must be at least 8 characters long');
            }
            
            // Validate age
            const ageNumber = parseInt(age);
            if (!age) {
                errors.push('Age is required');
            } else if (isNaN(ageNumber) || ageNumber < 13 || ageNumber > 120) {
                errors.push('Age must be between 13 and 120');
            }
            
            // Handle validation results
            if (errors.length > 0) {
                return res.status(400).json({
                    success: false,
                    errors: errors
                });
            }
            
            // If validation passes, process the registration
            console.log('Valid registration data:', { email, age: ageNumber });
            res.json({
                success: true,
                message: 'Registration successful'
            });
        });

Embora essa abordagem manual funcione, ela se torna verbosa e difícil de manter à medida que seus requisitos de validação se tornam mais complexos. Aplicações profissionais normalmente usam bibliotecas de validação para lidar com essa lógica de forma mais elegante.

Usando a biblioteca Express-Validator

A biblioteca express-validator fornece uma maneira limpa e poderosa de validar dados de requisição. Ela oferece validadores pré-construídos para requisitos comuns e permite criar regras de validação personalizadas. Esta biblioteca se integra perfeitamente com o Express e fornece um relatório de erros detalhado.

Configurando o Express-Validator

Se você quiser testar qualquer um dos exemplos de código do express-validator nesta leitura, precisará instalar a biblioteca em seu projeto e importar as funções de validação: 


        pnpm install express-validator
    

        // Import validation functions using ES modules
        import { body, validationResult } from 'express-validator';

Regras básicas de validação

O express-validator usa uma abordagem de middleware em que você define regras de validação como um array de funções middleware. Veja como reescrever a validação de registro usando o express-validator: 


        // Define validation rules for registration
        const registrationValidation = [
            body('email')
                .isEmail()
                .withMessage('Please provide a valid email address')
                .normalizeEmail(),
            
            body('password')
                .isLength({ min: 8 })
                .withMessage('Password must be at least 8 characters long'),
            
            body('age')
                .isInt({ min: 13, max: 120 })
                .withMessage('Age must be between 13 and 120')
        ];
        
        // Apply validation to the route
        app.post('/register', registrationValidation, (req, res) => {
            // Check for validation errors
            const results = validationResult(req);
            
            if (!results.isEmpty()) {
                return res.status(400).json({
                    success: false,
                    errors: results.array()
                });
            }
            
            // If validation passes, process the data
            const { email, password, age } = req.body;
            console.log('Valid registration:', { email, age });
            
            res.json({
                success: true,
                message: 'Registration successful'
            });
        });

Essa abordagem separa as regras de validação da lógica da sua rota, tornando o código mais legível e fácil de manter. A normalizeEmail() função limpa automaticamente a formatação do e-mail, e validationResult() coleta todos os erros de validação em um único objeto. À medida que sua aplicação cresce, você deve mover essas regras de validação para um arquivo separado e importá-las onde for necessário.

Exemplos avançados de validação

O express-validator oferece muitos validadores integrados para requisitos comuns. Aqui estão exemplos de regras de validação mais sofisticadas: 


        const advancedValidation = [
            // Email validation with custom domain restrictions
            body('email')
                .isEmail()
                .withMessage('Invalid email format')
                .custom((value) => {
                    if (value.endsWith('@tempmail.com')) {
                        throw new Error('Temporary email addresses are not allowed');
                    }
                    return true;
                })
                .normalizeEmail(),
            
            // URL validation
            body('website')
                .optional()
                .isURL()
                .withMessage('Please provide a valid website URL'),
            
            // Phone number validation
            body('phone')
                .isMobilePhone()
                .withMessage('Please provide a valid phone number'),
            
            // Date validation
            body('birthdate')
                .isISO8601()
                .withMessage('Please provide a valid date')
                .custom((value) => {
                    const date = new Date(value);
                    const eighteenYearsAgo = new Date();
                    eighteenYearsAgo.setFullYear(eighteenYearsAgo.getFullYear() - 18);
                    
                    if (date > eighteenYearsAgo) {
                        throw new Error('You must be at least 18 years old');
                    }
                    return true;
                })
        ];

Criando validadores personalizados

Embora o express-validator forneça muitos validadores integrados, com frequência você precisará criar uma lógica de validação personalizada para seus requisitos de negócio específicos. Validadores personalizados permitem implementar regras complexas exclusivas da sua aplicação.

Validação de complexidade de senha

Veja como criar um validador personalizado que garante que as senhas atendam a requisitos de complexidade específicos: 


        // Custom password validator
        const passwordValidation = body('password')
            .isLength({ min: 8 })
            .withMessage('Password must be at least 8 characters long')
            .custom((value) => {
                // Check for at least one number
                if (!/\d/.test(value)) {
                    throw new Error('Password must contain at least one number');
                }
                
                // Check for at least one special character
                if (!/[!@#$%^&*(),.?":{}|<>]/.test(value)) {
                    throw new Error('Password must contain at least one special character');
                }
                
                // Check for at least one uppercase letter
                if (!/[A-Z]/.test(value)) {
                    throw new Error('Password must contain at least one uppercase letter');
                }
                
                // Check for at least one lowercase letter
                if (!/[a-z]/.test(value)) {
                    throw new Error('Password must contain at least one lowercase letter');
                }
                
                return true;
            });

Validação de unicidade do nome de usuário

Validadores personalizados também podem realizar operações assíncronas, como verificações no banco de dados. Aqui está um exemplo que garante que os nomes de usuário sejam únicos: 


        // Simulate a database check (you would use your actual database here)
        const existingUsernames = ['admin', 'user', 'test', 'demo'];
        
        const usernameValidation = body('username')
            .isLength({ min: 3, max: 20 })
            .withMessage('Username must be between 3 and 20 characters')
            .matches(/^[a-zA-Z0-9_]+$/)
            .withMessage('Username can only contain letters, numbers, and underscores')
            .custom(async (value) => {
                // Simulate database lookup
                if (existingUsernames.includes(value.toLowerCase())) {
                    throw new Error('Username is already taken');
                }
                return true;
            });

Combinando múltiplos validadores personalizados

Você pode combinar múltiplos validadores personalizados para criar conjuntos abrangentes de validação para formulários complexos: 


        const completeRegistrationValidation = [
            // Email validation
            body('email')
                .isEmail()
                .withMessage('Invalid email format')
                .normalizeEmail(),
            
            // Username validation
            usernameValidation,
            
            // Password validation
            passwordValidation,
            
            // Password confirmation
            body('confirmPassword')
                .custom((value, { req }) => {
                    if (value !== req.body.password) {
                        throw new Error('Passwords do not match');
                    }
                    return true;
                }),
            
            // Terms acceptance
            body('acceptTerms')
                .equals('true')
                .withMessage('You must accept the terms and conditions')
        ];
        
        // Use in route
        app.post('/register', completeRegistrationValidation, (req, res) => {
            const results = validationResult(req);
            
            if (!errors.isEmpty()) {
                return res.status(400).json({
                    success: false,
                    errors: results.array()
                });
            }
            
            // Process successful registration
            const { email, username, password } = req.body;
            console.log('New user registered:', { email, username });
            
            res.json({
                success: true,
                message: 'Registration completed successfully'
            });
        });

Tratamento de erros e feedback ao usuário

O tratamento adequado de erros garante que as falhas de validação sejam comunicadas de forma clara aos usuários. O express-validator fornece informações detalhadas sobre erros que você pode usar para criar mensagens de feedback úteis.

Processando erros de validação

A validationResult() função retorna um objeto contendo todos os erros de validação. Você pode formatar esses erros de várias maneiras, dependendo das necessidades da sua aplicação: 


        app.post('/register', registrationValidation, (req, res) => {
            const results = validationResult(req);
            
            if (!results.isEmpty()) {
                // Get all errors as an array
                const errorArray = results.array();
                
                // Group errors by field
                const errorsByField = results.mapped();
                
                // Format for different response types
                if (req.headers.accept === 'application/json') {
                    // API response format
                    return res.status(400).json({
                        success: false,
                        errors: errorArray,
                        fields: errorsByField
                    });
                } else {
                    // Web form response - render page with errors
                    return res.render('register', {
                        title: 'Register',
                        errors: errorArray,
                        formData: req.body // Preserve user input
                    });
                }
            }
            
            // Success handling
            res.redirect('/dashboard');
        });

Exibindo erros em modelos

Ao renderizar formulários com erros de validação, você deve exibir os erros de forma clara e preservar a entrada do usuário para que ele não precise inserir novamente os dados válidos: 


        <form method="POST" action="/register">
            <% if (typeof errors !== 'undefined' && errors.length > 0) { %>
                <div class="error-summary">
                    <h3>Please correct the following errors:</h3>
                    <ul>
                        <% errors.forEach(error => { %>
                            <li><%= error.msg %></li>
                        <% }); %>
                    </ul>
                </div>
            <% } %>
            
            <div>
                <label for="email">Email:</label>
                <input type="email" id="email" name="email" 
                       value="<%= typeof formData !== 'undefined' ? formData.email || '' : '' %>">
            </div>
            
            <div>
                <label for="password">Password:</label>
                <input type="password" id="password" name="password">
            </div>
            
            <button type="submit">Register</button>
        </form>

Sanitização de entrada

O express-validator inclui funções de sanitização que limpam e normalizam a entrada do usuário. A sanitização ajuda a prevenir certos tipos de ataques e garante a consistência dos dados: 


        const sanitizedValidation = [
            body('name')
                .trim() // Remove leading/trailing whitespace
                .escape() // Escape HTML characters
                .isLength({ min: 2, max: 50 })
                .withMessage('Name must be between 2 and 50 characters'),
            
            body('email')
                .normalizeEmail() // Standardize email format
                .isEmail()
                .withMessage('Invalid email address'),
            
            body('bio')
                .trim()
                .isLength({ max: 500 })
                .withMessage('Bio cannot exceed 500 characters')
                .customSanitizer((value) => {
                    // Remove potentially dangerous HTML tags
                    return value.replace(/<script>.*<\/script>/gi, '');
                })
        ];
Nunca confie na entrada do usuário

Sempre valide e higienize a entrada do usuário no lado do servidor. Assuma que qualquer dado vindo dos usuários pode ser malicioso ou incorreto. Implemente a validação como sua primeira linha de defesa, mas também use outras medidas de segurança, como limitação de taxa, autenticação e tratamento adequado de erros.

Resumo dos conceitos-chave

A validação de formulários serve a dois propósitos distintos: melhorar a experiência do usuário por meio da validação no lado do cliente e proteger sua aplicação por meio da validação no lado do servidor. A validação no lado do cliente usando funcionalidades do HTML5 fornece feedback imediato e reduz a carga do servidor, mas não se pode confiar nela para fins de segurança, pois os usuários podem burlá-la facilmente.

A validação no lado do servidor é onde está sua proteção real. Ao processar requisições POST e validar os dados no corpo da requisição, você garante que apenas dados válidos e seguros entrem na sua aplicação. Ferramentas como o express-validator tornam mais fácil implementar regras de validação abrangentes, incluindo validadores personalizados para requisitos de negócios complexos.

Entender a diferença entre requisições GET e POST é fundamental para o desenvolvimento web. Enquanto as requisições GET passam dados por meio de URLs e parâmetros, as requisições POST transmitem dados pelo corpo da requisição, tornando-as adequadas para envios de formulários e informações sensíveis. Validação, sanitização e tratamento de erros adequados criam aplicações que são fáceis de usar e seguras.
