Construindo um Sistema de Registro de Usuários

Nesta tarefa, você criará um sistema de registro de usuários que armazena contas de usuários com senhas com hash com segurança. Isso se baseia diretamente na tarefa do formulário de contato, aplicando os mesmos padrões MVC enquanto introduz conceitos críticos de segurança, como hash de senha e regras de validação mais sofisticadas.

Você implementará o registro de usuários com confirmação de e-mail e senha, validação abrangente de formulário e uma interface administrativa para visualizar usuários registrados. Esta tarefa enfatiza as melhores práticas de segurança usando bcrypt para hash de senha e implementando uma validação robusta nos lados do cliente e do servidor.

Ferramentas de IA poderiam concluir esta tarefa para você em apenas alguns minutos. Não ceda a essa tentação. Muitas indústrias já estão preocupadas com o fato de que novos desenvolvedores, especialmente recém-formados e contratados juniores, têm dificuldade para programar de forma independente ou pensar criticamente sobre seu trabalho. Esta tarefa foi projetada para ajudá-lo a desenvolver as habilidades essenciais de que você precisará como desenvolvedor. Se você deixar a IA fazer o trabalho por você, perderá o aprendizado de habilidades críticas e colocará sua futura carreira em risco.

Entendendo a Segurança de Senhas

Armazenar senhas de usuários exige considerações especiais de segurança que o conteúdo estático nunca enfrenta. Senhas em texto puro criam vulnerabilidades graves de segurança: se o seu banco de dados for comprometido, todas as senhas dos usuários serão imediatamente expostas. Mesmo ter senhas em texto puro durante o desenvolvimento cria maus hábitos e abre espaço para erros em sistemas de produção.

O hashing de senhas resolve esse problema por meio de criptografia unidirecional. Quando um usuário se registra, sua senha é processada por um algoritmo de hashing que cria uma string única e irreversível. A senha original não pode ser recuperada a partir do hash, mas a mesma senha sempre produzirá o mesmo hash, permitindo que sua aplicação verifique as tentativas de login.

A biblioteca bcrypt fornece hashing de senhas no padrão da indústria, que inclui geração de salt integrada e níveis de dificuldade configuráveis. Esta tarefa implementa o bcrypt desde o início porque é muito mais seguro começar com a segurança adequada de senhas do que adaptá-la posteriormente em um sistema projetado para texto puro.

Como o bcrypt Funciona

Quando você chama bcrypt.hash(password, 10), a biblioteca gera automaticamente um salt aleatório, combina-o com a senha e aplica o algoritmo de hashing 2^10 (1.024) vezes. Esse processo é intencionalmente lento para tornar os ataques de força bruta impraticáveis. O hash resultante contém tanto o salt quanto o hash final, permitindo que a mesma função verifique as senhas mais tarde.

Salt é um valor aleatório adicionado à senha antes do hashing para garantir que até mesmo senhas idênticas produzam hashes diferentes. Isso impede que atacantes usem tabelas pré-computadas (rainbow tables) para reverter senhas a partir de seus hashes. Nenhum par de usuários com a mesma senha terá o mesmo hash armazenado no banco de dados.

Preparação

Antes de construir o sistema de registro, você precisa criar uma tabela no banco de dados para armazenar contas de usuários e instalar a biblioteca bcrypt para o hashing de senhas. Você adicionará essa tabela ao mesmo practice.sql arquivo que você criou na tarefa do formulário de contato.

Abra o seu arquivo src/models/sql/practice.sql existente e adicione o seguinte SQL ao final do arquivo, após a tabela do formulário de contato: 


        -- Users table for registration system
        CREATE TABLE IF NOT EXISTS users (
            id SERIAL PRIMARY KEY,
            name VARCHAR(255) NOT NULL,
            email VARCHAR(255) UNIQUE NOT NULL,
            password VARCHAR(255) NOT NULL,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        );

Observe que você está adicionando ao mesmo practice.sql arquivo que você criou na tarefa do formulário de contato. Este arquivo foi projetado para acumular alterações no banco de dados de várias tarefas ao longo do curso. Toda vez que seu banco de dados for propagado novamente (quando a tabela faculty estiver vazia), tanto a tabela do formulário de contato quanto a tabela users serão criadas. Essa abordagem mantém seu trabalho prático organizado e separado da estrutura principal do banco de dados do curso.

Tenha em mente que, para re-povoar o banco de dados e executar o SQL de prática novamente, você precisa excluir todos os dados da tabela faculty. Isso dispara o processo de povoamento, que agora inclui seu arquivo SQL de prática.

Em seguida, instale a biblioteca bcrypt para o hashing de senhas: 


        pnpm install bcrypt

Após a instalação, o pnpm exibirá um aviso sobre scripts de compilação ignorados para o bcrypt. Execute o seguinte comando para aprovar a compilação: 


        pnpm approve-builds

Quando solicitado, aprove a compilação do bcrypt. Isso permite que o módulo nativo do bcrypt seja compilado corretamente para o seu sistema.

Reinicie seu servidor e verifique se a tabela de usuários foi criada checando o console do seu servidor. Você deve ver a mensagem "Practice database tables initialized" após "Database seeded successfully". Use o pgAdmin para examinar as tabelas do seu banco de dados e confirmar que uma nova users tabela existe com colunas para ID, name, email, password, created_at e updated_at. A coluna de email deve ter uma restrição UNIQUE para evitar contas duplicadas. Não prossiga até confirmar que a tabela existe e que seu servidor é iniciado sem erros.

3. Criar o Modelo de Registro

Crie o arquivo de modelo que lida com as operações do banco de dados para o registro de usuário. Crie src/models/forms/registration.js com o seguinte conteúdo: 


        import db from '../db.js';

        /**
         * Checks if an email address is already registered in the database.
         * 
         * @param {string} email - The email address to check
         * @returns {Promise<boolean>} True if email exists, false otherwise
         */
        const emailExists = async (email) => {
            const query = `
                SELECT EXISTS(SELECT 1 FROM users WHERE email = $1) as exists
            `;
            const result = await db.query(query, [email]);
            return result.rows[0].exists;
        };

        /**
         * Saves a new user to the database with a hashed password.
         * 
         * @param {string} name - The user's full name
         * @param {string} email - The user's email address
         * @param {string} hashedPassword - The bcrypt-hashed password
         * @returns {Promise<Object>} The newly created user record (without password)
         */
        const saveUser = async (name, email, hashedPassword) => {
            const query = `
                INSERT INTO users (name, email, password)
                VALUES ($1, $2, $3)
                RETURNING id, name, email, created_at
            `;
            const result = await db.query(query, [name, email, hashedPassword]);
            return result.rows[0];
        };

        /**
         * Retrieves all registered users from the database.
         * 
         * @returns {Promise<Array>} Array of user records (without passwords)
         */
        const getAllUsers = async () => {
            const query = `
                SELECT id, name, email, created_at
                FROM users
                ORDER BY created_at DESC
            `;
            const result = await db.query(query);
            return result.rows;
        };

        export { emailExists, saveUser, getAllUsers };
Nota de Segurança: Nunca Retorne Senhas

Observe que nenhuma das funções do modelo retorna o campo da senha, mesmo que ele esteja armazenado como um hash. Esta é uma boa prática de segurança: senhas (mesmo em formato de hash) nunca devem ser incluídas em resultados de consultas, a menos que seja absolutamente necessário para a autenticação. A RETURNING cláusula e SELECT instruções listam explicitamente apenas os campos que devem ser retornados, omitindo completamente o campo de senha.

4. Entendendo o Hashing de Senhas com o bcrypt

Antes de implementar o controlador, você precisa entender como usar o bcrypt para hashing de senhas. A biblioteca bcrypt fornece duas funções principais: hash() para criar hashes de senha e compare() para verificar senhas (que você usará em uma futura tarefa de login).

Para gerar o hash de uma senha, você chama bcrypt.hash(password, saltRounds). O parâmetro de rodadas de salt (geralmente 10) determina quantas vezes o algoritmo de hashing é executado. Números mais altos são mais seguros, mas mais lentos. A função retorna uma promise que resolve para a string da senha em hash.

Aqui está um exemplo de uso básico: 


        import bcrypt from 'bcrypt';

        // Hash a password with 10 salt rounds
        const password = 'userPassword123!';
        const hashedPassword = await bcrypt.hash(password, 10);
        
        // The hash looks like: $2b$10$N9qo8uLOickgx2ZMRZoMye...
        console.log(hashedPassword);

Em seu controlador de registro, você usará esse padrão para gerar o hash das senhas antes de salvá-las no banco de dados. O hashing ocorre no controlador (não no modelo) porque faz parte da lógica de negócios para processar o registro, enquanto o modelo se concentra puramente nas operações do banco de dados.

Você pode se perguntar por que geramos o hash das senhas no controlador em vez de no modelo. Essa separação segue os princípios do MVC: o modelo deve lidar com operações de banco de dados com quaisquer dados que receber, enquanto o controlador lida com a lógica de negócios de preparação desses dados. Isso torna o modelo mais reutilizável (ele poderia salvar usuários de diferentes fontes, não apenas do registro) e mantém as transformações de segurança explícitas no controlador, onde são fáceis de auditar e manter.

                .custom((value, { req }) => value === req.body.password)

7. Teste Seu Sistema de Registro

Teste minuciosamente seu sistema de registro para garantir que todas as funcionalidades funcionem corretamente:

  1. Acesse http://127.0.0.1:3000/register para ver o formulário de registro.
  2. Teste a validação no lado do cliente tentando enviar o formulário com dados inválidos (nome curto, formato de e-mail inválido, senha fraca). O navegador deve impedir o envio e exibir as mensagens de erro apropriadas.
  3. Teste a validação no lado do servidor ignorando a validação no lado do cliente. Você pode usar as ferramentas de desenvolvedor do navegador para adicionar novalidate à tag de abertura do formulário ou executar o seguinte JavaScript para adicioná-lo automaticamente a todos os formulários da página: 
    
                document.querySelectorAll('form').forEach((form) => {
                    form.setAttribute('novalidate', '');
                });
    Envie dados inválidos e verifique se o servidor redireciona de volta sem salvar nada.
  4. Teste a validação no lado do servidor enviando o formulário com e-mails e senhas incompatíveis. O servidor deve impedir o envio e exibir mensagens de erro apropriadas.
  5. Registre um usuário válido com todos os campos devidamente preenchidos. Após o envio, você deve ser redirecionado automaticamente para a página da lista de usuários, onde poderá ver seu novo registro.
  6. Use o pgAdmin para verificar se a senha está armazenada como um hash bcrypt (ela deve começar com $2b$ e parecer caracteres aleatórios, não a senha em texto simples que você digitou).
  7. Tente se registrar novamente com o mesmo endereço de e-mail. O sistema deve impedir o registro duplicado e registrar uma mensagem apropriada no console do seu servidor.
  8. Acesse http://127.0.0.1:3000/register/list diretamente para verificar se consegue acessar a página da lista de usuários.

Verifique o console do seu servidor durante os testes para confirmar que as mensagens apropriadas estão sendo registradas em log para registros bem-sucedidos, falhas de validação e tentativas de e-mail duplicado. A saída do console ajuda você a depurar problemas e confirma que seu tratamento de erros está funcionando corretamente.

Ao implementar funcionalidades de segurança, é fundamental testar vários cenários, incluindo casos limite. Tente enviar o formulário com campos ausentes, formatos inválidos e e-mails duplicados para garantir que sua validação e seu tratamento de erros sejam robustos. Sempre verifique se dados sensíveis, como senhas, nunca são expostos em logs ou mensagens de erro. Sempre verifique se as senhas estão realmente armazenadas com hash no banco de dados, checando no pgAdmin. Se você vir senhas em texto simples, seu hash bcrypt não está funcionando corretamente.

Resumo dos Conceitos-Chave

Esta tarefa introduziu conceitos de segurança críticos para aplicações web. O hash de senha com bcrypt garante que as credenciais do usuário permaneçam seguras, mesmo que seu banco de dados seja comprometido. A natureza unidirecional do hash criptográfico significa que as senhas originais não podem ser recuperadas, apenas verificadas.

O sistema abrangente de validação que você implementou protege contra vulnerabilidades de segurança comuns e melhora a experiência do usuário. A validação no lado do servidor garante a integridade e a segurança dos dados, enquanto a validação no lado do cliente fornece feedback imediato aos usuários. Os campos de confirmação de e-mail e senha ajudam a prevenir erros do usuário durante o registro.

A verificação de unicidade de e-mail previne contas duplicadas e mantém a integridade dos dados. Ao implementar essa verificação tanto no nível do banco de dados (restrição UNIQUE) quanto no nível da aplicação (função emailExists), você garante que nenhum e-mail duplicado possa ser armazenado, independentemente de como a função de registro seja chamada.

Sua arquitetura MVC agora inclui funcionalidade de gerenciamento de usuários que segue os mesmos padrões do seu formulário de contato. Essa consistência torna sua base de código mais fácil de manter e demonstra como o padrão MVC escala para lidar com diferentes tipos de dados e interações do usuário. A abordagem de controlador de arquivo único mantém a funcionalidade relacionada organizada e fácil de manter.

Experimente e Estenda

Tente adicionar campos de usuário adicionais, como número de telefone ou endereço, lembrando-se de atualizar a tabela do seu banco de dados em practice.sql usando ALTER TABLE instruções, adicione regras de validação para os novos campos, atualize suas funções de modelo para lidar com as colunas adicionais e modifique suas exibições para mostrar as informações adicionais.

Experimente diferentes rodadas de salt do bcrypt para entender as implicações no desempenho de um hash mais forte. Tente alterar o 10 em bcrypt.hash(password, 10) para 12 ou 14 e note o quão mais lento o hash se torna. Isso demonstra o compromisso de segurança entre proteção e desempenho.

Considere adicionar páginas de perfil de usuário que exibam informações individuais do usuário, ou implemente a funcionalidade de busca e filtragem de usuários na página da lista de usuários. Você também pode adicionar paginação para lidar com eficiência com grandes números de usuários registrados, ou adicionar um botão de exclusão que permita remover usuários de teste do banco de dados.
