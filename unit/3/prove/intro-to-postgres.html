Introdução ao PostgreSQL com Express

Nesta tarefa, você conectará sua aplicação Express a um banco de dados PostgreSQL e substituirá os dados estáticos de cursos e corpo docente por conteúdo orientado a banco de dados. Isso representa um passo importante na construção de aplicações web escaláveis que podem armazenar e recuperar dados dinamicamente em vez de ficarem limitadas por objetos codificados diretamente no código.

Você instalará os pacotes necessários do PostgreSQL, estabelecerá uma conexão com o banco de dados, integrará arquivos de configuração de banco de dados pré-criados e modificará seus manipuladores de rota existentes para trabalhar com consultas reais de banco de dados. Ao final desta tarefa, o sistema de catálogo da sua universidade será alimentado por um banco de dados PostgreSQL em vez de objetos JavaScript estáticos.

O Problema dos Dados Estáticos

Sua aplicação atual usa objetos JavaScript estáticos para armazenar informações de cursos e do corpo docente. Embora essa abordagem funcione para aprendizado e pequenas demonstrações, ela possui limitações significativas que se tornam evidentes à medida que as aplicações crescem:

Problemas de Escalabilidade: Imagine sua universidade oferecendo 10.000 cursos com 500 membros do corpo docente. Carregar todos esses dados na memória cada vez que o servidor é iniciado consumiria quantidades massivas de RAM e desaceleraria significativamente a inicialização do servidor.

Problemas de Persistência de Dados: Quaisquer alterações nos horários dos cursos, informações do corpo docente ou novas ofertas de cursos exigem alterações de código e reinicializações do servidor. Não há como atualizar informações dinamicamente ou permitir que administradores modifiquem dados por meio de uma interface do usuário.

Limitações de Acesso Concorrente: Múltiplos usuários não podem acessar ou modificar com segurança os mesmos dados simultaneamente. Objetos estáticos não fornecem mecanismos integrados para lidar com acesso concorrente, validação de dados ou manutenção da integridade dos dados.

Os bancos de dados resolvem esses problemas fornecendo armazenamento persistente, recursos de consulta eficientes, controles de acesso concorrente e a capacidade de lidar com grandes conjuntos de dados sem carregar tudo na memória da aplicação.

Entendendo as Conexões de Banco de Dados

Antes de mergulhar na implementação, é importante entender como as aplicações web se conectam aos bancos de dados e por que precisamos de padrões especiais para gerenciar essas conexões de forma eficiente.

Pooling de Conexões

Criar uma nova conexão de banco de dados para cada consulta seria extremamente ineficiente. As conexões de banco de dados exigem handshakes de rede, autenticação e alocação de recursos, o que consome tempo e recursos do servidor. O pooling de conexões resolve isso mantendo um conjunto de conexões reutilizáveis que podem ser compartilhadas entre múltiplas requisições.

Quando sua aplicação precisa executar uma consulta, ela obtém uma conexão emprestada do pool, executa a consulta e devolve a conexão ao pool para reutilização. Isso melhora drasticamente o desempenho e reduz a carga no seu servidor de banco de dados.

Scripts de Configuração de Banco de Dados

Aplicações profissionais precisam de uma maneira confiável de garantir que a estrutura do banco de dados corresponda ao que a aplicação espera. Os scripts de configuração lidam com isso criando tabelas, índices e dados iniciais automaticamente. Esses scripts são projetados para serem idempotentes, o que significa que podem ser executados várias vezes com segurança sem causar erros ou perda de dados.

Nosso script de configuração usa comandos SQL como CREATE TABLE IF NOT EXISTS e ON CONFLICT DO NOTHING para evitar erros quando tabelas ou dados já existirem. Isso permite que a configuração seja executada toda vez que o servidor for iniciado, sem falhar caso o banco de dados já esteja configurado.

Preparação

Você precisará de credenciais do banco de dados para concluir esta tarefa. Consulte a Unidade 3 no Canvas para saber como obtê-las. Não fornecemos links para o processo de credenciais em nenhum lugar fora do Canvas por motivos de segurança.

Antes de iniciar esta tarefa, siga as instruções no Canvas para recuperar suas credenciais do banco de dados PostgreSQL. Se não conseguir localizar suas credenciais, peça ajuda à sua equipe antes de entrar em contato com seu instrutor. Você receberá credenciais individuais que incluem nome de usuário, senha, host, porta e nome do banco de dados.

Você usará essas credenciais para construir uma string de conexão com o banco de dados parecida com esta: 


        postgresql://[username]:[password]@[host]:[port]/[database]

Substitua as seções entre colchetes pelas suas credenciais reais. Por exemplo, se seu nome de usuário for student123, a senha for secret456, o host for postgres.university.edu, a porta for 5432e o banco de dados for catalog_db, sua string de conexão seria: 


        postgresql://student123:secret456@postgres.university.edu:5432/catalog_db

Baixar Certificado SSL

Quando você recuperou suas credenciais seguindo as instruções no Canvas, você foi direcionado a um site que forneceu um certificado SSL. Crie uma bin pasta na raiz do seu projeto e salve o certificado lá como byuicse-psql-cert.pem. Este certificado é necessário para que sua aplicação Node.js se conecte ao banco de dados com segurança e não é usado pelo pgAdmin ou por qualquer outra ferramenta gráfica.

Instruções da Tarefa

1. Instalando Pacotes do PostgreSQL

Instale o pacote do cliente PostgreSQL que fornece conectividade Node.js a bancos de dados PostgreSQL: 


        pnpm install pg

O pacote pg é o cliente PostgreSQL oficial para Node.js e fornece recursos de pooling de conexões, suporte a consultas parametrizadas para evitar ataques de injeção de SQL e tratamento abrangente de erros para operações no banco de dados.

2. Adicionando Configuração do Banco de Dados

Atualize seu arquivo .env na raiz do seu projeto para incluir sua string de conexão com o banco de dados e a flag de log de SQL: 


        DB_URL=postgresql://[username]:[password]@[host]:[port]/[database]  # new
        ENABLE_SQL_LOGGING=true                                             # new
        NODE_ENV=development
        PORT=3000

Substitua os marcadores entre colchetes pelas suas credenciais reais do banco de dados. A flag ENABLE_SQL_LOGGING mostrará todas as consultas executadas no console durante o desenvolvimento, o que é útil para entender o que sua aplicação está fazendo e para a depuração de problemas no banco de dados.

Proteja Suas Credenciais do Banco de Dados

Verifique novamente se o seu arquivo .env está listado no seu arquivo .gitignore. As credenciais do banco de dados são informações confidenciais que nunca devem ser incluídas em um commit para o controle de versão. Qualquer pessoa com acesso a essas credenciais poderia potencialmente acessar ou modificar seu banco de dados.

Baixe os arquivos de configuração do banco de dados e mescle todos os arquivos fornecidos na estrutura do seu projeto. Os arquivos incluem gerenciamento de conexão com o banco de dados, criação de esquema, povoamento inicial de dados e funções de modelo atualizadas que funcionam com PostgreSQL em vez de objetos estáticos.

Reserve um momento para revisar cada um desses arquivos para entender suas funções e como eles diferem da sua abordagem anterior de dados estáticos. Abaixo está uma breve visão geral do propósito e da funcionalidade de cada novo arquivo:

  • db.js: Gerencia o pool de conexões do PostgreSQL e fornece logs de consultas no modo de desenvolvimento.
  • setup.js: Cria tabelas no banco de dados e as popula com dados iniciais de cursos, corpo docente e catálogo.
  • sql/seed.sql: Popula o banco de dados com SQL INSERTs; mais rápido e confiável do que carregar JSON no código da aplicação.
  • catalog.js: Manipula consultas relacionadas a seções e horários de cursos.
  • courses.js: Substitui seus dados estáticos de cursos por consultas ao banco de dados.
  • faculty.js: Substitui seus dados estáticos do corpo docente por consultas ao banco de dados.
Notas Importantes Sobre os Arquivos Fornecidos

Um controlador de catálogo é fornecido para evitar falhas no servidor, mas precisa de correções (veja a próxima seção). O controlador do corpo docente NÃO É fornecido — você deve atualizar o seu existente. Todos os modelos precisarão de atualizações para a nova estrutura de dados.

Entendendo Slugs

A estrutura do banco de dados usa "slugs" em vez de IDs simples para o roteamento de URLs. Um slug é uma versão amigável para URL de um nome que contém apenas letras minúsculas, números e hífens. Por exemplo, "CSE 110" torna-se "cse-110" e "Brother Keers" torna-se "brother-keers". Isso cria URLs mais limpas e legíveis, mantendo a eficiência do banco de dados.

4. Atualizar o Processo de Inicialização do Servidor

Modifique o seu server.js arquivo para inicializar a conexão e a configuração do banco de dados quando o servidor for iniciado. Adicione esta importação perto do topo do seu arquivo com suas outras importações: 


        import { setupDatabase, testConnection } from './src/models/setup.js';

Em seguida, atualize seu código de inicialização do servidor existente na parte inferior do arquivo para incluir a inicialização do banco de dados: 


        app.listen(PORT, async () => {
            await setupDatabase();
            await testConnection();
            console.log(`Server is running on http://127.0.0.1:${PORT}`);
        });

O manipulador global de erros da sua aplicação capturará quaisquer erros de conexão ou configuração do banco de dados, impedindo que o servidor inicie e exibindo mensagens de erro claras no console.

O processo de configuração e povoamento (seeding) do banco de dados é executado automaticamente toda vez que o servidor é iniciado. Ele é projetado para ser seguro e não destrutivo: tabelas e dados iniciais só são criados se ainda não existirem, portanto reiniciar seu servidor não sobrescreverá nem excluirá dados existentes. Essa abordagem permite que você desenvolva com confiança sem se preocupar com perdas acidentais de dados.

Redefinindo a Configuração do Banco de Dados

O script de configuração só cria tabelas e insere dados se eles ainda não existirem. Para forçar um repovoamento (re-seed) completo durante o desenvolvimento, exclua todas as linhas da tabela faculty executando DELETE FROM faculty; ou TRUNCATE TABLE faculty; no pgAdmin e, em seguida, reinicie o seu servidor. O script de configuração detectará os dados de corpo docente ausentes e recriará as tabelas e povoará todos os dados iniciais.

Refatoração Necessária

Neste ponto, seu site estará parcialmente funcional. A conexão e a configuração do banco de dados estão funcionando, mas seus controladores e modelos ainda dependem da antiga estrutura estática de dados. Você precisa atualizar seus controladores para usar as novas funções assíncronas do modelo de banco de dados e modificar seus modelos para corresponder à nova estrutura de dados (consulte as etapas 6 a 8).

6. Atualizar o Controlador de Catálogo

O controlador de catálogo foi fornecido para evitar falhas, mas precisa de correções. Atualmente ele usa getCourseById() e getSectionsByCourseId(), mas suas URLs contêm slugs, não IDs. Atualize as importações e chamadas de função para funcionar com o roteamento baseado em slugs.

Abra src/controllers/catalog/catalog.js e atualize as importações no topo do arquivo: 


        // Update these imports:
        import { getAllCourses, getCourseBySlug } from '../../models/catalog/courses.js';
        import { getSectionsByCourseSlug } from '../../models/catalog/catalog.js';

Em seguida, encontre a função courseDetailPage e atualize-a para usar funções baseadas em slug em vez de funções baseadas em ID: 


        // In courseDetailPage function, replace:
        const courseId = req.params.courseId;
        const course = await getCourseById(courseId);
        const sections = await getSectionsByCourseId(courseId, sortBy);
        
        // With:
        const courseSlug = req.params.slugId;
        const course = await getCourseBySlug(courseSlug);
        const sections = await getSectionsByCourseSlug(courseSlug, sortBy);

Garantimos que as novas funções de modelo ainda retornem um objeto vazio ({}) quando nenhum dado for encontrado. Isso significa que a lógica existente de manipulação de erros no controlador funcionará corretamente com alterações mínimas. Sinta-se à vontade para adicionar mais às mensagens de erro, se desejar: 


        // Replace the existing error:
            if (Object.keys(course).length === 0) {
            const err = new Error(`Course ${courseId} not found`);
            err.status = 404;
            return next(err);
        }

        // With:
        if (Object.keys(course).length === 0) {
            const err = new Error(`Course ${courseSlug} not found`);
            err.status = 404;
            return next(err);
        }

Como renomeamos o parâmetro da rota para :slugId, as páginas de detalhes do catálogo não funcionarão até que você atualize as definições de rota dos catálogos em src/controllers/routes.js: 


        // In your route definitions, update:
        router.get('/catalog/:courseId', courseDetailPage);
        
        // To:
        router.get('/catalog/:slugId', courseDetailPage);

7. Atualizar o Controlador do Corpo Docente

Um novo controlador de corpo docente não foi incluído nos arquivos baixados. Você precisará atualizar seu arquivo src/controllers/faculty/faculty.js existente para funcionar com as novas funções do modelo baseadas em banco de dados, seguindo a mesma abordagem usada na etapa anterior para o controlador de catálogo.

Primeiro, atualize as importações no topo do seu arquivo do controlador de corpo docente para usar as funções assíncronas do modelo: 


        import { getFacultyBySlug, getSortedFaculty } from '../../models/faculty/faculty.js';

Em seguida, atualize ambas as funções do controlador com as seguintes alterações:

  • Converta ambas as funções para usar async
  • Adicione await antes de todas as chamadas ao banco de dados
  • Atualize sua lógica de verificação de erros: as funções do banco de dados retornam um objeto vazio ({}) quando os dados não forem encontrados, portanto, verifique com Object.keys(facultyMember).length === 0 em vez de verificar se há null ou undefined
Verifique Seu Trabalho

Veja como deve ficar o seu controlador de corpo docente atualizado: 


            const facultyListPage = async (req, res) => {
                const validSortOptions = ['name', 'department', 'title'];
                const sortBy = validSortOptions.includes(req.query.sort) ? req.query.sort : 'department';
                const facultyList = await getSortedFaculty(sortBy);
                
                res.render('faculty/list', {
                    title: 'Faculty Directory',
                    faculty: facultyList,
                    currentSort: sortBy
                });
            };

            const facultyDetailPage = async (req, res, next) => {
                const facultySlug = req.params.facultySlug;
                const facultyMember = await getFacultyBySlug(facultySlug);

                if (Object.keys(facultyMember).length === 0) {
                    const err = new Error(`Faculty member ${facultySlug} not found`);
                    err.status = 404;
                    return next(err);
                }
                
                res.render('faculty/detail', {
                    title: `${facultyMember.name} - Faculty Profile`,
                    faculty: facultyMember
                });
            };

Veja como devem ser as definições de rota de corpo docente: 


            router.get('/faculty/:facultySlug', facultyDetailPage);

8. Atualizar Seus Modelos

Agora que seus controllers estão funcionando com o banco de dados, você precisa atualizar todos os seus modelos (views) para usar a nova estrutura de dados e nomes de propriedades. O banco de dados retorna dados com nomes de propriedades diferentes dos que seus objetos estáticos usavam.

Use console.log() em seus controllers para inspecionar a estrutura de dados real sendo passada para seus modelos. Isso ajudará você a entender exatamente quais propriedades estão disponíveis.

Entendendo a Nova Estrutura de Dados

O banco de dados usa nomes de propriedades e estruturas diferentes dos seus objetos estáticos. Aqui estão as principais diferenças que você precisa saber:

  • Cursos: Use courseCode, name, creditHours, department, slug em vez de propriedades antigas como id, title, credits
  • Seções: As seções agora são um array separado com propriedades courseCode, courseName, professor, professorSlug, time, room (não incorporado no objeto do curso)
  • Corpo docente: Use firstName, lastName, name, slug, department, title, office, phone, email

Atualize catalog.ejs, course-detail.ejs, faculty/list.ejs, e faculty/detail.ejs para corresponder a esses novos nomes de propriedades. Sempre use console.log() em seus controllers para verificar a estrutura de dados real antes de fazer alterações em seus modelos, mas não se esqueça de remover esses logs posteriormente para manter seu console limpo.

Não se esqueça de que alguns cursos não têm seções! Seus modelos de detalhes do curso devem lidar com listas de seções vazias de forma adequada, mas você pode adicionar lógica condicional para exibir uma mensagem como "Nenhuma seção disponível" se o array de seções estiver vazio. Tente um curso diferente que tenha seções para testar totalmente seu modelo.

Entendendo o Que Você Construiu

Esta Tarefa introduziu vários conceitos importantes que formam o fundamento de aplicações web orientadas a banco de dados. Vamos examinar o que você realizou e por que esses padrões são essenciais para o desenvolvimento escalável.

Gerenciamento do Pool de Conexões

Sua aplicação agora usa um pool de conexões para gerenciar as conexões com o banco de dados de forma eficiente. Em vez de criar uma nova conexão para cada consulta (o que seria lento e exigiria muitos recursos), o pool mantém um conjunto de conexões reutilizáveis. Esse padrão é essencial para aplicações que lidam com múltiplos usuários concorrentes e operações frequentes no banco de dados.

Acesso Assíncrono a Dados

Ao converter seus manipuladores de rotas para usar async/await, seu aplicativo agora pode lidar com consultas ao banco de dados sem bloquear outras requisições. Quando uma consulta está em execução, o Node.js pode processar outras requisições de entrada, melhorando dramaticamente a capacidade do seu aplicativo de atender a múltiplos usuários simultaneamente.

Roteamento Baseado em Slugs

A transição de IDs simples como "CS121" para slugs como "cse-110" oferece vários benefícios: as URLs são mais amigáveis ao usuário e otimizadas para SEO, o formato é consistente independentemente das convenções de nomenclatura dos cursos, e a estrutura interna do banco de dados não é exposta nas URLs.

Consistência de Dados e Relacionamentos

A estrutura do banco de dados inclui relacionamentos adequados entre cursos, corpo docente, departamentos e entradas do catálogo. Isso garante a consistência dos dados (as informações do departamento de um membro do corpo docente são armazenadas uma vez e referenciadas em todos os lugares) e permite consultas complexas que seriam difíceis com objetos estáticos.

Processo de Configuração Não Destrutivo

O script de configuração demonstra práticas profissionais de gerenciamento de banco de dados. Ele pode ser executado várias vezes com segurança, atualiza os dados existentes quando necessário e evita a perda de informações durante o desenvolvimento. Esse padrão é crucial para aplicativos que precisam evoluir seu esquema de banco de dados ao longo do tempo.

Resumo dos Conceitos-Chave

Esta Tarefa fez a transição bem-sucedida do seu aplicativo de dados estáticos para um sistema totalmente orientado a banco de dados. Você aprendeu a estabelecer conexões de banco de dados usando pooling de conexões, integrar scripts de configuração de banco de dados que são executados com segurança várias vezes, converter manipuladores de rotas síncronos em padrões assíncronos e implementar um tratamento de erros adequado para operações de banco de dados.

Mais importante ainda, você vivenciou os benefícios práticos do desenvolvimento orientado a banco de dados: seu aplicativo agora pode lidar com conjuntos de dados muito maiores sem problemas de desempenho, os dados podem ser modificados sem alterações no código ou reinicializações do servidor, múltiplos usuários podem acessar as mesmas informações simultaneamente, e o fundamento está pronto para funcionalidades avançadas, como conteúdo gerado pelo usuário e interfaces administrativas.

Os padrões que você implementou — pooling de conexões, operações assíncronas e tratamento de erros adequado — são padrões da indústria que você usará ao longo de sua carreira em desenvolvimento web. Entender como essas peças funcionam juntas prepara você para construir aplicativos de nível profissional que podem escalar para atender às demandas do mundo real.

Solução de Problemas Comuns

Se você encontrar problemas durante esta Tarefa, aqui estão alguns problemas comuns e suas soluções:

Erros de Conexão de Certificado SSL

Verifique se o certificado SSL foi baixado e colocado no bin/ diretório como byuicse-psql-cert.pem.

Erros de Conexão com o Banco de Dados

Se você vir erros como "Database connection failed", verifique se suas credenciais do banco de dados no .env arquivo estão corretas e correspondem exatamente ao formato. Verifique se a sua string de conexão não possui espaços extras ou caracteres especiais e confirme se o seu servidor de banco de dados está acessível a partir do seu ambiente de desenvolvimento.

Erro Comum

Usamos símbolos para as senhas do seu banco de dados que quebram as strings de conexão se não forem codificadas em URL. Se a sua senha contiver qualquer tipo de símbolo, ela precisará ser codificada em URL. Por exemplo, se a sua senha for p@ssw0rd!, ela deve ser codificada como p%40ssw0rd%21 na string de conexão. Fornecemos as versões codificadas no mesmo local de onde você obtém suas credenciais do banco de dados.

Problemas na Inicialização do Servidor

Se o seu servidor falhar ao iniciar após adicionar o código do banco de dados, certifique-se de que todos os seus caminhos de importação usem a extensão .js e que os caminhos dos arquivos estejam corretos em relação ao arquivo que faz a importação. Verifique se você instalou o pacote pg com pnpm install pg.

Página de Detalhes do Catálogo Mostra 404 para Cursos Válidos

O controlador de catálogo fornecido usa getCourseById mas as URLs contêm slugs. Atualize-o para usar getCourseBySlug conforme mostrado na etapa 6.

Páginas do Corpo Docente Não Estão Funcionando

O controlador do corpo docente não foi fornecido. Você deve atualizar seu controlador existente para usar async/await e as novas funções do modelo (veja a etapa 7).

Modelos Mostram Dados Indefinidos ou Ausentes

Os nomes das propriedades mudaram. Use console.log() em seus controladores para inspecionar a estrutura de dados real e, em seguida, atualize seus modelos para usar os novos nomes de propriedades (veja a etapa 8).

Erros 404 em URLs que Funcionavam Anteriormente

Lembre-se de que o banco de dados usa slugs em vez do seu formato de ID anterior. URLs como /catalog/CS121 agora devem ser /catalog/cse-110. Verifique a saída do console durante a configuração do banco de dados para ver os slugs reais sendo criados para seus dados.

Obtendo Ajuda

Ao buscar ajuda para problemas no banco de dados, inclua a mensagem de erro específica, a seção de código relevante e o que você estava tentando realizar. Erros de banco de dados geralmente fornecem informações detalhadas que podem ajudar a identificar a causa raiz rapidamente.

Conclusão

Você transformou com sucesso seu sistema estático de catálogo universitário em uma aplicação dinâmica movida a banco de dados. Isso representa um marco significativo em sua jornada de desenvolvimento, pois agora você entende como as aplicações web do mundo real armazenam e recuperam dados de forma eficiente.

As habilidades que você desenvolveu nesta Tarefa — trabalhar com bancos de dados, lidar com operações assíncronas e gerenciar o estado da aplicação — são fundamentais para o desenvolvimento web moderno.
