Desafio de Codificação: Transferência de Emergência

Nesta tarefa de desafio, você entrará em um cenário do mundo real que desenvolvedores encontram com frequência: assumir o projeto de outra pessoa no meio do desenvolvimento. Seu colega de trabalho teve uma emergência familiar e ficará fora por pelo menos uma semana. O site do cliente está quase pronto para o lançamento, mas várias tarefas críticas permanecem inacabadas. Solicitaram que você concluísse o trabalho para que o site possa ser lançado no prazo.

Ao contrário das tarefas anteriores, nas quais você construiu funcionalidades do zero, este desafio exige que você leia, entenda e modifique o código existente. Isso testa um conjunto de habilidades diferente, mas igualmente importante: compreensão de código, depuração e trabalho em uma base de código estabelecida com seus próprios padrões e convenções.

O projeto é para a Kizuna Rail, uma empresa ferroviária japonesa que está lançando um site em inglês para atrair turistas internacionais. Seu colega de trabalho deixou uma lista detalhada de tarefas sobre o que ainda precisa ser feito. Seu trabalho é concluir cada tarefa e entregar o produto final.

Preparação

Esta tarefa usa um repositório de projeto pré-construído. Você usará a funcionalidade de modelo do GitHub para criar sua própria cópia e, em seguida, irá cloná-lo para sua máquina local para trabalhar nele.

1. Crie sua cópia e clone o repositório

Comece criando sua própria cópia do projeto:

  1. Acesse o repositório em https://github.com/byui-cse/kizuna-rail
  2. Clique no botão Usar este modelo no canto superior direito e selecione Criar um novo repositório
  3. Dê um nome ao seu repositório (kizuna-rail) e crie-o na sua conta do GitHub
  4. Clone seu novo repositório para sua máquina local: 
    
                git clone https://github.com/YOUR-USERNAME/kizuna-rail.git
                cd kizuna-rail

Este repositório é um modelo, não um repositório padrão para fazer fork. Use o botão Usar este modelo para criar sua própria cópia independente para concluir o desafio. Só faça fork do repositório se planejar contribuir com melhorias ou atualizações para o próprio desafio, o que normalmente é feito por instrutores ou profissionais da indústria.

2. Instale as dependências e inicie o servidor

Este projeto usa o pnpm como seu gerenciador de pacotes. Instale as dependências necessárias e inicie o servidor de desenvolvimento: 


        # Install all project dependencies
        pnpm install
        
        # Start the development server
        pnpm run dev

O servidor deve iniciar em http://127.0.0.1:3000. Abra esta URL no seu navegador para visualizar o site.

Sobre o pnpm

Este projeto usa o pnpm como seu gerenciador de pacotes. Se você não tiver o pnpm instalado globalmente em seu sistema, siga as instruções de instalação em pnpm.io/installation.

3. Revise o cenário

Antes de começar o trabalho, familiarize-se com o projeto visitando estas páginas no seu navegador:

  • http://127.0.0.1:3000/scenarios — Explica o propósito deste site de prática
  • http://127.0.0.1:3000/scenarios/emergency-handoff — Contém a lista detalhada de tarefas para este desafio

A página de transferência de emergência fornece o contexto sobre o projeto e lista seis tarefas específicas que precisam ser concluídas. Leia todo o cenário antes de começar a trabalhar nas tarefas.

Instruções do Desafio

Seu colega de trabalho deixou uma lista detalhada de tarefas que precisa ser concluída antes do lançamento do site. A lista completa de tarefas, juntamente com os requisitos específicos e dicas úteis, está disponível na página do cenário de transferência de emergência dentro da aplicação em execução.

Cada tarefa exige que você leia o código existente, entenda como ele funciona e faça melhorias ou correções direcionadas. Trabalhe nas tarefas de forma sistemática, realizando testes minuciosos em cada uma antes de passar para a próxima.

Trabalhando com Código Existente

Este desafio é diferente de construir funcionalidades do zero. Você precisa explorar a base de código para entender como ela está organizada, encontrar os arquivos que precisam de modificação e fazer alterações que se ajustem aos padrões existentes. Use as ferramentas de desenvolvedor do seu navegador para inspecionar elementos, verificar a aba de rede para requisições e revisar as mensagens do console em busca de pistas.

Algumas tarefas dependem da compreensão de conceitos de Tarefas anteriores, como parâmetros de consulta, funções auxiliares e media queries do CSS. Revise seu trabalho anterior se precisar refrescar sua memória sobre esses conceitos.

Testes do Seu Trabalho

À medida que você conclui cada tarefa da lista de a fazer, teste sua implementação minuciosamente para garantir que ela funcione corretamente. A página do cenário de transferência de emergência fornece orientações específicas de testes para cada tarefa.

As estratégias gerais de testes incluem:

  • Navegar pelo site e verificar se todas as páginas carregam sem erros
  • Testar funcionalidades interativas clicando em botões, selecionando opções e enviando formulários
  • Verificar o console do navegador quanto a erros ou avisos do JavaScript
  • Verificar se quaisquer funcionalidades de filtragem ou ordenação funcionam com diferentes combinações de parâmetros
  • Testar casos limite, como parâmetros ausentes ou valores inválidos
  • Garantir que suas alterações funcionem em diferentes navegadores, se possível

A página do cenário inclui URLs específicas e etapas de verificação para cada tarefa. Use-as para confirmar que sua implementação atende aos requisitos antes de passar para a próxima tarefa.

Sugestões de Fluxo de Trabalho do Git

Embora não seja obrigatório, você pode achar útil usar branches do Git para organizar seu trabalho em cada tarefa. Isso reflete práticas de desenvolvimento profissional em que funcionalidades e correções são desenvolvidas de forma isolada antes de serem mescladas.

Um fluxo de trabalho sugerido para este projeto:

  1. Criar uma issue ou nota para cada tarefa para acompanhar seu progresso
  2. Criar uma nova branch para cada tarefa assim que começar a trabalhar nela
  3. Fazer o commit das suas alterações quando uma tarefa estiver concluída
  4. Mesclar a branch de volta para a main após os testes
  5. Passar para a próxima tarefa e repetir o processo

Essa abordagem ajuda você a isolar alterações, facilita desfazer erros e fornece um histórico claro do seu trabalho. No entanto, o foco principal desta Tarefa é concluir as tarefas, não dominar os fluxos de trabalho do Git.

Requisitos de Envio

Quando você tiver concluído todas as tarefas da lista de a fazer:

  1. Grave uma demonstração em vídeo (de preferência de 2 a 3 minutos, no máximo 5 minutos) apresentando cada tarefa concluída. Mostre como você resolveu cada requisito e demonstre que sua implementação funciona corretamente.
  2. Faça o upload do seu vídeo para o YouTube (como não listado), OneDrive, Google Drive ou outro serviço de compartilhamento de arquivos
  3. Se você estiver usando uma solução de armazenamento na nuvem, garanta que o link esteja configurado para ser visualizado por qualquer pessoa com o link. Quaisquer envios que exijam permissão ou solicitações de acesso receberão nota zero.
  4. Envie seu código concluído para o seu repositório no GitHub
  5. Envie tanto o link do vídeo quanto a URL do seu repositório do GitHub

Seu vídeo deve demonstrar cada tarefa concluída de forma sistemática. Explique o que você alterou e o porquê enquanto mostra cada funcionalidade funcionando corretamente. Consulte a lista de a fazer na página do cenário para garantir que cobriu todos os requisitos.

Dicas e Sugestões

A página do cenário de transferência de emergência inclui dicas específicas para cada tarefa, mas aqui estão algumas estratégias gerais para trabalhar com códigos desconhecidos:

Compreendendo a Base de Código

  • Comece explorando a estrutura do projeto. Identifique onde estão localizadas as views, controllers, models e arquivos estáticos.
  • Use a função de busca do seu editor de código para encontrar arquivos relevantes. Por exemplo, buscar por "rotas" ou "filtro" pode ajudá-lo a localizar arquivos relacionados a essas funcionalidades.
  • Siga o fluxo de dados das rotas para os controllers e para as views. Compreender esse caminho ajudará você a identificar onde as alterações precisam ser feitas.
  • Leia o código existente com atenção para entender os padrões e convenções usados no projeto. Adapte suas alterações a esses padrões.

Estratégias de Depuração

  • Use console.log() instruções para inspecionar valores em diferentes pontos do seu código. Isso ajuda você a entender com quais dados está trabalhando.
  • Verifique o console do desenvolvedor do seu navegador para erros de JavaScript que possam indicar problemas com suas alterações.
  • Use a aba de rede do seu navegador para ver quais requisições estão sendo feitas e quais parâmetros de consulta estão sendo enviados.
  • Teste as alterações incrementalmente. Faça pequenas modificações, teste-as e passe para a próxima alteração. Isso torna mais fácil identificar o que quebrou se algo parar de funcionar.

Armadilhas comuns

  • Lembre-se de atualizar os caminhos de importação após reorganizar os arquivos. Caminhos ausentes ou incorretos farão o servidor falhar.
  • Ao trabalhar com funções auxiliares, garanta que elas estejam devidamente exportadas de seu módulo e importadas onde forem necessárias.
  • Os parâmetros de consulta são sempre strings. Converta-os para o tipo de dado correto, se necessário para comparações ou cálculos.
  • Teste casos de borda, como parâmetros de consulta ausentes, valores inválidos ou resultados vazios, para garantir que seu código lide com todos os cenários adequadamente.

Resumo dos conceitos-chave

Esta Tarefa de desafio reforçou habilidades críticas de desenvolvimento do mundo real que vão além de escrever código novo. Você praticou a leitura e a compreensão do código existente, navegando em uma base de código desconhecida, depurando problemas no trabalho de outra pessoa e fazendo melhorias direcionadas sem quebrar a funcionalidade existente.

As tarefas cobriram vários conceitos técnicos de Tarefas anteriores: melhorias de acessibilidade, organização e arquitetura de arquivos, filtragem por parâmetros de consulta, criação e uso de funções auxiliares, transformação de dados em modelos e consultas de mídia CSS para estilos de impressão. Aplicar esses conceitos em um projeto pré-construído demonstra sua capacidade de transferir conhecimento para novos contextos.

Assumir o projeto de outra pessoa no meio do desenvolvimento é um cenário comum no desenvolvimento profissional de software. Se um membro da equipe sai, as prioridades mudam ou ocorrem emergências, os desenvolvedores frequentemente precisam trabalhar com código que não escreveram. Essa experiência constrói a adaptabilidade e as habilidades de resolução de problemas que diferenciam desenvolvedores eficazes daqueles que só conseguem trabalhar em projetos do zero (greenfield).
