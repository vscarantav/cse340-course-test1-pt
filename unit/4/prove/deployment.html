Implantando sua aplicação Express no Render

Até agora, você esteve executando sua aplicação Express localmente. Embora isso funcione para o desenvolvimento, ninguém mais pode acessá-la. Nesta Tarefa, você vai implantar seu projeto de prática no Render, tornando-o acessível na internet com sua própria URL. Você também configurará implantações automáticas, para que quaisquer alterações que você enviar para o GitHub atualizem automaticamente seu site no ar.

Revisão de código em breve

Colegas de equipe começarão a realizar revisões de código no final desta semana e/ou no início da próxima semana. Faça commit e envie suas alterações com frequência para que seu site no ar permaneça atualizado e os revisores possam ver seu trabalho mais recente.

Entendendo a implantação

Quando você executa pnpm dev localmente, seu computador é o servidor. A implantação significa colocar sua aplicação em um servidor remoto que está sempre em execução e conectado à internet. O Render é uma Plataforma como Serviço (PaaS) que cuida do gerenciamento do servidor para você. Você fornece seu código, e o Render cuida do resto: instalar dependências, executar sua aplicação e mantê-la online.

Variáveis de ambiente: O que copiar para o Render

Seu arquivo .env não está no Git (por segurança), então o Render não pode acessá-lo. Você adicionará variáveis de ambiente através do painel do Render. Aqui está o que você precisa:

  • DB_URL: Copie isto exatamente do seu arquivo .env. Seu banco de dados na nuvem funciona da mesma forma localmente e em produção.
  • SESSION_SECRET: Copie isto exatamente do seu arquivo .env. Isso mantém as sessões de usuário funcionando e deve ser idêntico por segurança.

Não adicione estas variáveis (o Render lida com elas automaticamente ou elas não são necessárias):

  • ENABLE_SQL_LOGGING: Deixe isso de fora. Registrar logs de consultas SQL em produção gera ruído e pode expor dados sensíveis. O Render trata isso como false por padrão.
  • NODE_ENV: O Render define isso automaticamente como production.
  • PORT: O Render atribui a porta dinamicamente. Não defina isso você mesmo.

Processo de compilação: npm vs pnpm

Localmente você usa pnpm, o que economiza espaço em disco ao compartilhar pacotes entre projetos. No Render, sua aplicação é executada em sua própria máquina virtual isolada, portanto esse benefício não se aplica. Você pode usar pnpm ou npm no Render. A escolha não afeta sua aplicação, apenas especifique os comandos corretos durante a configuração.

Implantações automáticas

Quando você habilita a implantação automática e envia para a sua branch principal, o Render puxa automaticamente seu código mais recente, recompila sua aplicação e a implanta. Isso significa que você pode desenvolver localmente, fazer commit das alterações, enviar para o GitHub e seu site no ar será atualizado em poucos minutos. Isso é essencial para as revisões de código em equipe e para o desenvolvimento rápido.

Instruções da Tarefa

1. Crie uma conta no Render

Navegue até render.com e cadastre-se para criar uma conta. Você deve usar a opção "Sign up with GitHub", pois isso simplifica o processo de conexão dos seus repositórios. O uso da autenticação do GitHub permite que o Render acesse seus repositórios sem etapas adicionais de configuração.

O Render oferece um plano gratuito que é suficiente para este curso. Você não precisará fornecer informações de pagamento, a menos que opte por atualizar para funcionalidades pagas posteriormente.

2. Conecte seu repositório

A partir do seu painel do Render, crie um novo Web Service e conecte o repositório do seu projeto de prática. O Render guiará você durante a configuração. Configure estas definições:

  • Nome: Escolha um nome significativo (torna-se parte da sua URL)
  • Branch: Selecione main
  • Comando de Compilação:
    • Se estiver usando pnpm: pnpm install --dangerously-allow-all-builds
    • Se estiver usando npm: npm install
    O Render não detecta automaticamente qual gerenciador de pacotes você usa, por isso você deve especificar isso explicitamente. A --dangerously-allow-all-builds flag é necessária para o pnpm porque algumas das suas dependências (como bcrypt) compilam código nativo específico para o sistema operacional em que executam. Enquanto o npm executa esses scripts de compilação automaticamente, o pnpm inclui verificações adicionais de segurança que exigem aprovação explícita. Esta flag ignora essas verificações, permitindo que todos os scripts pós-instalação sejam executados durante a implantação.
  • Comando de Início: Se estiver usando pnpm, insira pnpm run start. Se estiver usando npm, insira npm run start. Isso executa o start script a partir do seu package.json, o que executa node server.js.
Habilitar Auto-Deploy

Certifique-se de que o "Auto-Deploy" esteja habilitado. Isso recompila e reimplanta automaticamente sua aplicação sempre que você enviar para a main. Sem isso, você precisaria disparar implantações manualmente todas as vezes.

Após a configuração inicial, você pode acessar essas configurações e suas variáveis de ambiente na barra lateral esquerda (Settings e Environment).

3. Configurar Variáveis de Ambiente

No painel do serviço web do Render, vá para a seção "Environment". Adicione estas duas variáveis do seu arquivo local .env:

  • DB_URL: Copie sua string de conexão com o banco de dados exatamente
  • SESSION_SECRET: Copie seu segredo de sessão exatamente

Não adicione ENABLE_SQL_LOGGING, NODE_ENV, ou PORT. O Render lida com estes automaticamente.

Verifique novamente seus valores. Um erro de digitação na URL do seu banco de dados interromperá a conexão com o banco de dados, e um segredo de sessão incorreto causará problemas de autenticação. Após adicionar estes valores, o Render disparará automaticamente uma implantação.

4. Monitorar a Implantação

Acompanhe o progresso da implantação na seção "Logs". O processo de compilação leva alguns minutos. Se falhar, os logs mostrarão mensagens de erro. Problemas comuns incluem variáveis de ambiente ausentes ou comandos incorretos. Consulte a documentação de solução de problemas do Render em render.com/docs/troubleshooting-deploys se necessário.

5. Testar Sua Aplicação Implantada

Assim que a implantação for bem-sucedida, o Render fornece sua URL (como https://your-service-name.onrender.com). Abra-a em seu navegador e teste sua aplicação. Seu banco de dados na nuvem deve funcionar da mesma forma que funciona localmente.

6. Enviar Seu Trabalho

Tire uma captura de tela da página inicial do seu site de prática mostrando a barra de endereços do navegador com a sua URL do Render visível. Envie esta captura de tela de acordo com as orientações do seu instrutor.

Olhando para o Futuro: Encerramento do Projeto de Prática e Seu Próximo Projeto

Você concluirá e encerrará seu projeto de prática na Unidade 4. Depois disso, você iniciará um projeto separado para a segunda metade do curso. Quando esse novo projeto estiver pronto, siga esse mesmo processo de implantação usando um serviço web do Render separado.

Faça commit e envie frequentemente. Com a implantação automática habilitada, cada envio para a main atualiza automaticamente seu site no ar. Assim que seu próximo projeto estiver implantado e estável, você poderá remover seu projeto de prática do Render se desejar; isso é opcional.

Resumo dos Conceitos-Chave

Você aprendeu como implantar uma aplicação Express em produção e como configurar a implantação contínua para que envios para a main atualizem automaticamente seu site no ar. Entender a diferença entre ambientes de desenvolvimento e produção, e configurar as variáveis de ambiente corretas em seu servidor de hospedagem, é o que mantém sua aplicação no ar funcionando corretamente. Esta Tarefa é a primeira da unidade para que você possa verificar sua implantação antes do início das revisões de código. Faça commit e envie com frequência para que os colegas de equipe vejam seu trabalho mais recente.
