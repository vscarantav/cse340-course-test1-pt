Validação avançada de formulários

Nesta Tarefa, você aprimorará as regras de validação dos seus três formulários (contato, cadastro e login) para garantir a qualidade dos dados, evitar erros comuns e melhorar a segurança. Embora seus formulários tenham atualmente uma validação básica, as aplicações em produção exigem uma validação mais abrangente para lidar com casos de borda, evitar entradas maliciosas e fornecer feedback claro quando os dados não atendem aos requisitos.

Você adicionará restrições de comprimento máximo para evitar erros no banco de dados e possíveis ataques, implementará correspondência de padrões para garantir a formatação adequada dos dados, criará uma lógica de validação personalizada para regras de negócio específicas e aprimorará os requisitos de senha para melhorar a segurança. Essas melhorias de validação tornarão sua aplicação mais robusta e amigável ao usuário.

Compreendendo a validação abrangente

A validação básica garante que os campos obrigatórios estejam presentes e atendam aos padrões mínimos, mas a validação abrangente vai mais além. As aplicações do mundo real devem lidar com usuários que inserem texto em excesso acidentalmente, tentam quebrar o sistema intencionalmente ou simplesmente cometem erros honestos de formatação. As colunas do seu banco de dados têm comprimentos máximos, e exceder esses limites causa erros. A correspondência de padrões garante que os dados estejam em conformidade com os formatos esperados, facilitando o processamento e a exibição correta.

A segurança é outra consideração crucial. Requisitos de senha que impõem complexidade tornam as contas mais difíceis de serem comprometidas. A validação de entrada que rejeita padrões suspeitos pode ajudar a prevenir spam e abusos. A validação que verifica a formatação adequada evita problemas quando os dados são usados em diferentes contextos ao longo da sua aplicação.

O express-validator fornece ferramentas poderosas para implementar essas verificações. Você já usou validadores básicos como isLength() e isEmail(). Esta Tarefa introduz validadores adicionais como matches() para correspondência de padrões, custom() para lógica de negócios e notEmpty() para garantir que os campos contenham dados. Você também aprenderá a encadear várias regras de validação para criar verificações abrangentes que capturam vários tipos de entrada inválida.

Preparação

Antes de aprimorar a validação do seu formulário, você precisa entender três conceitos-chave: encadeamento de regras de validação, expressões regulares para correspondência de padrões e funções de validação personalizadas. Esses conceitos formam o fundamento para a validação abrangente que você implementará nos seus formulários.

Encadeamento de regras de validação

O express-validator permite encadear vários métodos de validação. Cada validador na cadeia é executado em ordem, e cada um pode ter sua própria mensagem de erro personalizada. Esse padrão permite verificar várias condições em um único campo enquanto fornece feedback específico para cada tipo de falha.

Aqui está uma estrutura de exemplo mostrando como as regras de validação se encadeiam: 


        body('fieldName')
            .trim()                                    // Sanitizer: removes whitespace
            .isLength({ min: 2, max: 100 })           // Validator: checks length
            .withMessage('Custom error for length')    // Error message for previous validator
            .matches(/^[a-zA-Z\s]+$/)                 // Validator: checks pattern
            .withMessage('Custom error for pattern')   // Error message for previous validator

O trim() sanitizador é executado primeiro, removendo espaços em branco no início e no fim. Depois, isLength() valida se o valor sem espaços atende aos requisitos de comprimento. Se essa verificação falhar, o withMessage() associado fornece o texto do erro. Se o comprimento for aprovado, matches() verifica o padrão. Cada validador tem sua própria mensagem de erro, para que os usuários vejam um feedback específico sobre o que deu errado.

Sanitizadores vs Validadores

Sanitizadores como trim() e normalizeEmail() modificam a entrada antes que a validação seja executada. Eles limpam os dados do usuário para tornar a validação mais confiável. Validadores como isLength() e matches() verificam condições, mas não modificam os dados. Sempre execute os sanitizadores antes dos validadores.

Expressões regulares para correspondência de padrões

O matches() O validador usa expressões regulares para verificar se o texto segue um padrão específico. As expressões regulares podem parecer intimidadoras, mas você pode entendê-las dividindo-as em partes.

Por exemplo, /^[a-zA-Z\s'-]+$/ valida nomes:

  • ^ significa que o padrão deve coincidir desde o início da string
  • [a-zA-Z\s'-] é uma classe de caracteres que permite letras minúsculas (a-z), letras maiúsculas (A-Z), espaços em branco (\s), hífens (-) e apóstrofos (')
  • + significa um ou mais da classe de caracteres anterior
  • $ significa que o padrão deve coincidir até o final da string

Outro exemplo, /^[a-zA-Z0-9\s\-.,!?]+$/ valida linhas de assunto:

  • Permite letras e números (a-zA-Z0-9)
  • Permite espaços (\s)
  • Permite pontuação básica (\-.,!?)
  • A barra invertida antes do hífen (\-) faz o escape dele para que seja tratado como um caractere literal

Você não precisa se tornar um especialista em expressões regulares para esta Tarefa. Os padrões fornecidos foram testados e funcionam corretamente. Entender a estrutura básica deles ajuda você a modificá-los, se necessário.

Funções de Validação Personalizadas

Às vezes, você precisa de uma lógica de validação que vai além do que os validadores integrados oferecem. O custom() validador permite que você escreva sua própria função de validação. Esta função recebe o valor do campo e deve retornar true para entrada válida ou lançar um erro para entrada inválida.

Aqui está um validador personalizado que verifica padrões de spam: 


        body('message')
            .custom((value) => {
                // Split message into words
                const words = value.split(/\s+/);
                // Create a Set of unique words
                const uniqueWords = new Set(words);
                
                // If message has many words but few unique ones, likely spam
                if (words.length > 20 && uniqueWords.size / words.length < 0.3) {
                    throw new Error('Message appears to be spam');
                }
                
                // Valid input must return true
                return true;
            })

Este validador calcula a proporção de palavras únicas em relação ao total de palavras. Se uma mensagem tiver mais de 20 palavras, mas menos de 30% delas forem únicas (o que significa muita repetição), ele lança um erro. Isso captura mensagens como "buy now buy now buy now" que bots de spam costumam enviar. Mensagens legítimas naturalmente possuem mais variedade na escolha das palavras.

Instruções da Tarefa

1. Aprimorar a Validação do Formulário de Contato

Abra src/controllers/forms/contact.js e localize seu array de validação. Atualmente, ele só verifica tamanhos mínimos para os campos de assunto e mensagem. Você precisa adicionar restrições de tamanho máximo, correspondência de padrão para o assunto e detecção personalizada de spam para a mensagem.

Substitua seu array de validação atual por esta versão aprimorada: 


        router.post('/',
            [
                body('subject')
                    .trim()
                    .isLength({ min: 2, max: 255 })
                    .withMessage('Subject must be between 2 and 255 characters')
                    .matches(/^[a-zA-Z0-9\s\-.,!?]+$/)
                    .withMessage('Subject contains invalid characters'),
                body('message')
                    .trim()
                    .isLength({ min: 10, max: 2000 })
                    .withMessage('Message must be between 10 and 2000 characters')
                    .custom((value) => {
                        // Check for spam patterns (excessive repetition)
                        const words = value.split(/\s+/);
                        const uniqueWords = new Set(words);
                        if (words.length > 20 && uniqueWords.size / words.length < 0.3) {
                            throw new Error('Message appears to be spam');
                        }
                        return true;
                    })
            ],
            handleContactSubmission
        );

Salve o arquivo e teste sua validação aprimorada. Adicione novalidate à visualização do seu formulário de contato e tente enviar um assunto com 300 caracteres. Você deve ver a mensagem de erro. Tente enviar um assunto com caracteres especiais como @ ou #. Você deve ver o erro de caracteres inválidos. Tente enviar uma mensagem que repete a mesma palavra 30 vezes. Você deve ver o erro de detecção de spam.

Por que Esses Limites Específicos?

O limite de 255 caracteres para o assunto corresponde à definição da coluna do seu banco de dados (VARCHAR(255)). O limite de 2000 caracteres para a mensagem é um máximo razoável que previne abusos enquanto permite mensagens detalhadas. Esses limites protegem seu banco de dados de erros que ocorrem quando os dados excedem o tamanho das colunas.

O validador personalizado de detecção de spam usa uma abordagem matemática para identificar mensagens repetitivas. Antes de prosseguir, reserve um momento para estudar o código e pensar sobre por que comparar o número de palavras únicas com o total de palavras identificaria spam. Qual proporção uma mensagem normal teria? Como seria uma mensagem de spam? Formule seu raciocínio e, em seguida, compartilhe o trecho de código e sua explicação com seu assistente de IA para verificar seu entendimento.

2. Aprimorar a Validação do Formulário de Registro

Abra src/controllers/forms/registration.js e localize o registrationValidation array. Você precisa aprimorar a validação para todos os campos: name, email, emailConfirm, password e passwordConfirm.

Atualize seu registrationValidation array com estes requisitos:

Campo de nome:

  • Adicione o comprimento máximo de 100 caracteres ao isLength(): isLength({ min: 2, max: 100 })
  • Atualize a mensagem de erro para: 'Name must be between 2 and 100 characters'
  • Adicione a correspondência de padrão: matches(/^[a-zA-Z\s'-]+$/)
  • Adicione a mensagem de erro para o padrão: 'Name can only contain letters, spaces, hyphens, and apostrophes'

Campo de e-mail:

  • Mantenha trim(), isEmail(), e normalizeEmail() como estão
  • Adicione a verificação de comprimento máximo após normalizeEmail: isLength({ max: 255 })
  • Adicione a mensagem de erro: 'Email address is too long'

Campo de senha:

  • Atualize isLength() para incluir o máximo: isLength({ min: 8, max: 128 })
  • Atualize a mensagem de erro para: 'Password must be between 8 and 128 characters'
  • Mantenha a regra matches(/[0-9]/) existente e sua mensagem de erro
  • Adicione uma nova regra para letras minúsculas: matches(/[a-z]/) com a mensagem 'Password must contain at least one lowercase letter'
  • Adicione uma nova regra para maiúsculas: matches(/[A-Z]/) com a mensagem 'Password must contain at least one uppercase letter'
  • Atualize a regra de caractere especial para usar este padrão: matches(/[!@#$%^&*()_+\-=\[\]{};':"\\|,.<>\/?]/)
  • Mantenha a mensagem de erro de caractere especial existente

Campos EmailConfirm e PasswordConfirm:

  • Mantenha-os como estão (eles já usam validação personalizada)

Seu registrationValidation array agora deve validar o formato e o tamanho do nome, o tamanho do e-mail e a complexidade da senha com requisitos de maiúsculas, minúsculas, números e caracteres especiais. Teste minuciosamente com novalidate no seu formulário.

Lembre-se da Codificação de Caracteres

Ao escrever expressões regulares em seu código, você precisa escapar caracteres especiais. O & símbolo no padrão de caracteres especiais é escrito como &amp; neste documento HTML, mas deve ser apenas & no seu código JavaScript. As barras invertidas e colchetes já estão devidamente escapados no padrão fornecido acima.

3. Aprimorar a Validação do Formulário de Login

Abra src/controllers/forms/login.js e localize o loginValidation array. Formulários de login precisam de menos validação do que formulários de cadastro porque os usuários estão inserindo dados existentes, não criando novos registros. No entanto, você ainda deve validar restrições de tamanho e garantir que os campos não estejam vazios.

Atualize seu loginValidation array com estes requisitos:

Campo de e-mail:

  • Mantenha toda a validação existente (trim, isEmail, normalizeEmail)
  • Adicione verificação de tamanho máximo: isLength({ max: 255 })
  • Adicione a mensagem de erro: 'Email address is too long'

Campo de senha:

  • Adicione notEmpty() antes do isLength()
  • Mantenha a mensagem de erro para notEmpty como 'Password is required'
  • Atualize isLength() para: isLength({ min: 8, max: 128 })
  • Adicione a mensagem de erro: 'Password must be between 8 and 128 characters'

Observe que a validação de login não verifica a complexidade da senha (maiúsculas, minúsculas, caracteres especiais). Isso é intencional. Os usuários criaram suas senhas durante o cadastro, onde essas regras foram aplicadas. Durante o login, você verifica apenas as restrições de tamanho para capturar erros óbvios, ao mesmo tempo em que permite qualquer senha válida existente.

4. Testar Toda a Validação Aprimorada

Teste minuciosamente cada formulário com várias entradas inválidas para garantir que suas regras de validação funcionem corretamente. Lembre-se de adicionar novalidate a cada formulário temporariamente para ignorar a validação do navegador e testar suas regras no lado do servidor.

Testes do Formulário de Contato:

  • Envie com um assunto com mais de 255 caracteres (copie e cole um parágrafo longo)
  • Envie com um assunto contendo os símbolos @ ou #
  • Envie com uma mensagem com mais de 2000 caracteres
  • Envie com uma mensagem que repita a mesma palavra muitas vezes

Testes do Formulário de Cadastro:

  • Envie com um nome contendo números ou caracteres especiais
  • Envie com um nome com mais de 100 caracteres
  • Envie com um endereço de e-mail extremamente longo (mais de 255 caracteres)
  • Envie com uma senha que não tenha letras maiúsculas
  • Envie com uma senha que não tenha letras minúsculas
  • Envie com uma senha que não tenha números
  • Envie com uma senha que não tenha caracteres especiais
  • Envie com uma senha com mais de 128 caracteres

Testes do Formulário de Login:

  • Envie com um campo de senha vazio
  • Envie com um endereço de e-mail extremamente longo
  • Envie com uma senha com mais de 128 caracteres

Para cada teste, verifique se você vê as mensagens de erro flash adequadas e se a validação impede o envio. Após confirmar que toda a validação funciona, remova os novalidate atributos dos seus formulários para restaurar a validação no lado do cliente.

Múltiplas Mensagens de Erro

Quando um campo falha em várias regras de validação, você verá múltiplas mensagens de erro flash. Por exemplo, uma senha sem letras maiúsculas e sem números gerará duas mensagens de erro. Esse feedback abrangente ajuda os usuários a entenderem todos os requisitos que precisam cumprir.

Resumo dos Conceitos-Chave

Esta Tarefa aprimorou a validação do seu formulário com regras abrangentes que melhoram a qualidade e a segurança dos dados. Você adicionou restrições de comprimento máximo que evitam erros de banco de dados e protegem contra determinados ataques. A correspondência de padrões com expressões regulares garante que os dados estejam em conformidade com os formatos esperados. Funções de validação personalizadas implementam a lógica de negócios que validadores nativos não conseguem lidar.

As melhorias de validação funcionam em conjunto com o sistema de mensagens flash que você implementou anteriormente. Quando a validação falha, os usuários veem mensagens de erro específicas e acionáveis que explicam exatamente o que precisa ser corrigido. Essa combinação de validação no lado do servidor e feedback do usuário cria um sistema robusto de manipulação de formulários.

Você praticou o encadeamento de vários validadores, compreendendo que cada validador na cadeia pode ter sua própria mensagem de erro. Sanitizadores como trim() executam primeiro para limpar os dados, e depois os validadores verificam as condições. A validação de senha demonstra como múltiplas matches() chamadas podem impor requisitos complexos verificando padrões separados.

A distinção entre a validação de registro e de login é importante. O registro valida se os novos dados atendem a todos os requisitos, enquanto o login valida se os dados existentes estão formatados corretamente sem checar novamente as regras de criação. Essa abordagem equilibra a segurança com a usabilidade.

Experimente e Estenda

Considere estas melhorias para aprimorar ainda mais a sua validação:

  • Adicione validação para verificar se os domínios de e-mail são realistas (rejeite domínios claramente falsos)
  • Crie um validador personalizado que verifique a força da senha e forneça feedback além dos requisitos básicos
  • Adicione validação ao seu formulário de contato para detectar e bloquear mensagens com muitas URLs (outro indicador de spam)
  • Implemente a exibição de erros específica por campo em suas exibições para que os erros apareçam ao lado de seus campos em vez de no topo da página

Conclusão

A validação abrangente é essencial para aplicações web em produção. A validação básica captura erros óbvios, mas aplicações do mundo real lidam com usuários que cometem erros, excedem limites ou tentam entradas maliciosas. As melhorias de validação que você implementou protegem seu banco de dados, melhoram a segurança e fornecem um feedback melhor ao usuário.

O express-validator fornece ferramentas poderosas para implementar regras de validação que são abrangentes e fáceis de manter. Encadear validadores, usar expressões regulares para correspondência de padrões e escrever funções de validação personalizadas oferecem controle total sobre quais dados sua aplicação aceita. Essas habilidades se aplicam a qualquer formulário que você criar em Projetos futuros.
