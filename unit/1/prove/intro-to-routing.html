Introdução ao Roteamento

Nesta tarefa, você construirá um site simples de 3 páginas usando o Express. O objetivo é apresentar conceitos de roteamento e praticar o fornecimento de arquivos estáticos como HTML e CSS. Você criará e servirá arquivos HTML estáticos para as rotas Home, About e Products, configurará e servirá um arquivo CSS estático para estilizar seu site, e aprenderá os conceitos básicos de roteamento no Express usando res.sendFile().

Em tarefas futuras, exploraremos técnicas de roteamento mais avançadas e faremos a transição para o uso de um mecanismo de modelos como o EJS. Mecanismos de modelos simplificam o gerenciamento de exibições dinâmicas, permitindo reutilizar componentes e passar dados para nossos arquivos HTML. Por enquanto, nos concentraremos em entender os fundamentos do roteamento e da organização de arquivos.

Visão Geral da Estrutura do Projeto

Antes de começarmos, vamos entender como organizaremos nosso projeto e por que essa organização é importante. Trabalharemos com dois diretórios principais que atendem a propósitos fundamentalmente diferentes:

  • public/: Contém arquivos estáticos que os navegadores podem acessar diretamente (CSS, imagens, JavaScript do lado do cliente)
  • src/views/: Contém arquivos HTML que o Express serve por meio de rotas

Esta separação reflete como as aplicações web modernas funcionam. Arquivos em public/ são servidos exatamente como existem no seu servidor – sem processamento, sem verificações de segurança, sem lógica. Eles são perfeitos para recursos que nunca mudam: folhas de estilo, imagens, fontes e arquivos JavaScript do lado do cliente. Qualquer pessoa pode solicitá-los diretamente digitando a URL.

Arquivos em src/views/, por outro lado, são servidos por meio da lógica da sua aplicação. O Express decide se deve servi-los, pode modificá-los antes de servir, pode aplicar verificações de segurança e pode até gerá-los dinamicamente. Isso lhe dá controle total sobre o que os usuários veem e quando veem.

Ao final desta tarefa, a estrutura do seu projeto terá a seguinte aparência: 


        [project-root]
        ├── public/
        │   └── css/
        │       └── main.css
        ├── src/
        │   └── views/
        │       ├── about.html
        │       ├── home.html
        │       └── products.html
        ├── .env
        └── server.js

Preparação

Usaremos o aplicativo Express que você configurou anteriormente em seu repositório de prática. Siga estas etapas para preparar seu projeto:

1. Atualizar a Configuração de Ambiente

Modifique seu .env arquivo excluindo seu conteúdo e adicionando apenas a seguinte linha: 

PORT=3000

Isso define a porta na qual seu servidor será executado. Variáveis de ambiente como essa permitem que você gerencie a configuração separadamente do seu código, facilitando a implantação da sua aplicação em diferentes ambientes. Atualize seu server.js arquivo para usar condicionalmente este número de porta: 


        const PORT = process.env.PORT || 3000;

Se o seu .env arquivo estiver ausente ou você esqueceu de definir um número de porta, isso permitirá que o servidor inicie definindo o valor padrão da porta como 3000. Dependendo do serviço que você usará para hospedar seu site no futuro, você precisará alterar esse valor pré-definido para o número suportado por esse serviço.

Ao usar valores condicionais (padrão) em seu código, tenha cuidado! Embora definir padrões ajude sua aplicação a lidar com configurações ausentes e a falhar de maneira elegante, evite usá-los de maneiras que possam introduzir riscos de segurança ou comportamentos não intencionais. Os valores padrão só devem ser usados quando for seguro para sua aplicação se recuperar de erros. Para saber mais sobre este tópico, consulte tratamento elegante de erros.

2. Atualize Sua Estrutura

Até agora, não pensamos muito sobre como estruturamos nosso código. Agora que estamos começando a adicionar mais arquivos e declarações, é importante organizar nosso projeto de uma forma que o torne fácil de navegar e manter. Reorganize cuidadosamente a estrutura do seu projeto para corresponder ao seguinte modelo: 


        // Imports
        ...

        /**
         * Declare Important Variables
         */

        const PORT = process.env.PORT || 3000;

        /**
         * Setup Express Server
         */
        const app = express();

        /**
         * Declare Routes
         */

        ...

        // Start the server and listen on the specified port
        ...

Ao longo deste curso, você deve revisar periodicamente a estrutura e a organização do seu código. À medida que você adiciona mais arquivos, funções e funcionalidades, manter seu código organizado ajudará você e outras pessoas a entendo-lo melhor. Isso é especialmente importante em projetos maiores, onde vários desenvolvedores podem estar trabalhando juntos.

Dicas de Estrutura de Diretórios

Quando pedirmos para você criar arquivos ou diretórios neste curso, certifique-se de criá-los no local correto. O public diretório deve estar na raiz do seu projeto, no mesmo nível do seu server.js arquivo. O src diretório também deve estar no nível da raiz, separado de public.

Instruções da Tarefa

1. Servir Arquivos Estáticos

Arquivos estáticos são recursos que não mudam quando servidos aos usuários, como arquivos CSS, imagens e JavaScript do lado do cliente. O Express oferece uma maneira simples de servir esses arquivos usando o express.static middleware. Esta função integrada permite servir seus arquivos estáticos diretamente ao navegador sem qualquer processamento.

Antes de podermos servir arquivos, precisamos entender como o JavaScript lida com caminhos de arquivos. Em módulos CommonJS tradicionais (usando require()), o Node.js fornecia automaticamente duas variáveis especiais: __dirname e __filename. Essas variáveis resolviam um problema crítico em aplicações de servidor: como encontrar arquivos de forma confiável quando você não sabe onde sua aplicação estará sendo executada?

__dirname contém o caminho absoluto para o diretório que contém o arquivo JavaScript atual. __filename contém o caminho absoluto para o próprio arquivo JavaScript atual. Elas são essenciais porque fornecem referências consistentes, independentemente de onde alguém execute sua aplicação. Sem elas, se alguém executasse seu servidor a partir de um diretório diferente, todos os seus caminhos de arquivos quebrariam.

No entanto, módulos ES (que estamos usando com import instruções) não fornecem automaticamente essas variáveis. Em vez disso, devemos criá-las nós mesmos usando o sistema de módulos ES mais recente. Adicione essas importações ao topo do seu server.js arquivo: 


        import { fileURLToPath } from 'url';
        import path from 'path';

Em seguida, na sua seção de variáveis importantes, recrie as __dirname e __filename variáveis: 


        const __filename = fileURLToPath(import.meta.url);
        const __dirname = path.dirname(__filename);

Aqui está o que está acontecendo: import.meta.url nos dá a URL do módulo atual, fileURLToPath() converte essa URL para um caminho do sistema de arquivos e path.dirname() extrai apenas a parte do diretório. Isso recria a mesma funcionalidade que o CommonJS fornecia automaticamente.

Agora, adicione o seguinte middleware ao seu server.js arquivo após const app = express(); mas antes de qualquer rota: 


        /**
         * Configure Express middleware
         */

        // Serve static files from the public directory
        app.use(express.static(path.join(__dirname, 'public')));

Este código diz ao Express que qualquer arquivo no seu public diretório deve ser acessível diretamente através do seu site. Por exemplo, seu arquivo CSS em public/css/main.css estará disponível em http://127.0.0.1:3000/css/main.css. Observe que a parte public não está incluída na URL.

Entendendo como Servir Arquivos Estáticos

O express.static middleware mapeia automaticamente o conteúdo do seu public diretório para a raiz do seu site. Isso mantém suas URLs limpas e facilita a organização de recursos estáticos. Quando alguém requisita /css/main.css, o Express procura por public/css/main.css e o serve se for encontrado.

2. Criar Arquivos HTML Estáticos

Agora crie três arquivos HTML no seu src/views diretório. Esses arquivos servirão como o conteúdo para suas diferentes páginas:

  • home.html – Sua página inicial principal
  • about.html – Uma página para se apresentar
  • products.html – Uma página para demonstrar seus produtos

Use este modelo para cada arquivo, substituindo os espaços reservados com o conteúdo apropriado para cada página: 


        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <meta name="viewport" content="width=device-width, initial-scale=1.0">
            <title>[PAGE TITLE]</title>
            <link rel="stylesheet" href="/css/main.css">
        </head>
        <body>
            <h1>[PAGE HEADING]</h1>
            <nav>
                <ul>
                    <li><a href="/">Home</a></li>
                    <li><a href="/about">About</a></li>
                    <li><a href="/products">Products</a></li>
                </ul>
            </nav>
            <p>[Add some content specific to this page]</p>
        </body>
        </html>

Observe como o arquivo CSS é vinculado usando um caminho relativo à raiz (/css/main.css). Isso funciona porque o Express serve tudo no seu public diretório a partir da URL raiz do seu site.

3. Configurar Rotas

Agora vamos criar rotas para que as pessoas possam realmente visitar suas páginas. Uma rota é simplesmente uma regra que diz "quando alguém visitar esta URL, envie este conteúdo a ela". É como uma recepcionista que sabe para qual sala direcionar os visitantes.

Substitua toda a seção "Declarar Rotas" em server.js, incluindo quaisquer rotas que você possa ter adicionado, com o seguinte código: 


        /**
         * Routes
         */
        app.get('/', (req, res) => {
            res.sendFile(path.join(__dirname, 'src/views/home.html'));
        });

        app.get('/about', (req, res) => {
            res.sendFile(path.join(__dirname, 'src/views/about.html'));
        });

        app.get('/products', (req, res) => {
            res.sendFile(path.join(__dirname, 'src/views/products.html'));
        });

Aqui está uma explicação detalhada do que cada parte faz:

  • app.get('/', ...) diz ao Express "quando alguém visitar a página inicial (apenas o domínio sem caminho), faça algo"
  • (req, res) => { ... } é a função que é executada quando alguém visita essa URL. req contém informações sobre o que eles requisitaram, res permite que você envie algo de volta
  • res.sendFile(...) envia um arquivo HTML para o navegador deles
  • path.join(__dirname, 'src/views/home.html') cria o caminho completo para o seu arquivo HTML

Então, quando alguém digita http://127.0.0.1:3000/ em seu navegador, o Express encontra a primeira rota, executa a função e envia a eles o seu home.html arquivo.

O mesmo acontece para as outras rotas:

  • http://127.0.0.1:3000/about → envia about.html
  • http://127.0.0.1:3000/products → envia products.html
Por que não simplesmente colocar arquivos HTML em Public?

Você pode se perguntar por que não simplesmente colocamos nossos arquivos HTML no public diretório como o nosso CSS. O motivo é o controle. As rotas permitem que você faça coisas antes de enviar o arquivo: verificar se o usuário está logado, personalizar o conteúdo ou redirecioná-lo para outro lugar. Arquivos estáticos em public são enviados diretamente sem oportunidade para o seu código intervir.

Um Detalhe Importante: Nós usamos path.join(__dirname, ...) em vez de apenas escrever 'src/views/home.html' porque precisamos do caminho absoluto completo para o arquivo. __dirname nos dá o diretório onde server.js reside, e path.join() o combina adequadamente com o restante do caminho. Isso garante que o arquivo seja encontrado, não importa de onde alguém execute sua aplicação.

4. Construa um "Sobre Mim" Real

Agora que você configurou suas rotas, é hora de deixar sua página about.html mais pessoal. Substitua qualquer conteúdo temporário por informações sobre você. No mínimo, sua página deve incluir:

  • Seu nome
  • Uma breve introdução sobre você
  • Uma lista dos seus hobbies ou interesses
  • Uma foto sua salva no public/images diretório

Não se esqueça de atualizar seu main.css com estilos que tornem sua página sobre mim visualmente atraente. Você pode adicionar cores, fontes e estilos de layout para aprimorar a experiência do usuário. Todo o CSS deve seguir as convenções de aninhamento de CSS moderno, que permitem escrever estilos mais limpos e organizados.

5. Teste o Seu Site

Inicie o seu servidor usando pnpm run dev e teste cada página em seu navegador:

  • http://127.0.0.1:3000/ deve exibir sua página inicial
  • http://127.0.0.1:3000/about deve exibir sua página sobre mim
  • http://127.0.0.1:3000/products deve exibir sua página de produtos

Verifique se cada página mostra seu conteúdo correto, se a navegação funciona e se os estilos CSS estão aplicados. Se encontrar problemas, verifique os caminhos dos arquivos e as rotas em busca de erros de digitação. As ferramentas de desenvolvedor do navegador também podem ajudar a identificar problemas com arquivos ausentes ou links quebrados.

Resumo dos Conceitos-Chave

Esta Tarefa apresentou vários conceitos fundamentais:

  • Arquivos Estáticos: Recursos como CSS e imagens que são servidos diretamente aos usuários sem processamento
  • Middleware: Funções que processam requisições antes que elas alcancem suas rotas
  • Roteamento: Mapeamento de URLs para respostas ou conteúdos específicos
  • Organização de Arquivos: Separando recursos estáticos (public/) de conteúdo renderizado pelo servidor (src/views/)
  • Manipulação de Caminhos: Usando path.join() para criar caminhos de arquivo confiáveis em diferentes sistemas operacionais

Compreender esses conceitos é crucial, pois eles formam o fundamento para funcionalidades mais avançadas do Express. Na próxima Tarefa, você aprenderá sobre motores de modelos, que permitem criar conteúdo dinâmico e componentes reutilizáveis.

Experimente e Expanda

Agora que você tem um site de várias páginas funcional, tente estas melhorias opcionais:

  • Adicione mais páginas e rotas correspondentes
  • Aprimore seu CSS com mais estilos, cores ou melhorias de layout
  • Experimente conteúdos e estruturas HTML diferentes

Quanto mais você praticar com esses fundamentos, mais confortável ficará com o Express e com os conceitos de desenvolvimento web.
