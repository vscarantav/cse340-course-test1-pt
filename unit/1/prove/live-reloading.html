Adicionando Live Reloading ao Seu Fluxo de Trabalho de Desenvolvimento

No desenvolvimento web, a eficiência é a chave. Embora o nodemon simplifique o desenvolvimento back-end reiniciando automaticamente seu servidor com alterações de arquivo, ele não lida com atualizações de front-end, como alterações de HTML, CSS ou JavaScript do lado do cliente. Esta Tarefa introduz o live reloading, que atualiza automaticamente seu navegador sempre que alterações forem feitas. Aproveitando WebSockets, seu navegador e servidor permanecem em sincronia, criando uma experiência de desenvolvimento mais fluida.

Instruções da Tarefa

1. Adicionar Variáveis Globais do Modelo com Middleware

Em vez de passar manualmente a variável NODE_ENV para cada rota individual, podemos usar o middleware do Express para torná-la disponível globalmente para todos os modelos. As funções de middleware são executadas entre a requisição recebida e seus manipuladores de rota, permitindo que você configure os dados de que cada modelo precisa.

Adicione o seguinte middleware ao seu arquivo server.js após a configuração de middleware existente, mas antes das suas rotas: 


        /**
         * Global template variables middleware
         * 
         * Makes common variables available to all EJS templates without having to pass
         * them individually from each route handler
         */
        app.use((req, res, next) => {
            // Make NODE_ENV available to all templates
            res.locals.NODE_ENV = NODE_ENV.toLowerCase() || 'production';
            
            // Continue to the next middleware or route handler
            next();
        });

O objeto res.locals é uma funcionalidade especial do Express que armazena dados para a requisição atual e os torna automaticamente disponíveis para todos os modelos. Qualquer propriedade que você adicionar ao res.locals torna-se uma variável que seus modelos EJS podem acessar diretamente, assim como as variáveis que você passa para res.render(). Isso é perfeito para dados de que cada modelo precisa, como informações de ambiente, detalhes do usuário ou configurações globais.

Entendendo o Fluxo do Middleware

Este middleware é executado para cada requisição antes de atingir suas rotas. Ele configura a variável NODE_ENV uma vez e, em seguida, todos os seus modelos poderão usá-la sem nenhum trabalho adicional em seus manipuladores de rota. Exploraremos o conceito de res.locals mais profundamente nas próximas tarefas, pois ele se torna muito útil para armazenar informações do usuário, dados de navegação e outras necessidades globais de modelos.

Não use res.locals para armazenar informações confidenciais, como senhas ou chaves de API, pois esses dados ficam acessíveis no navegador e devem ser mantidos seguros.

2. Atualizar o head para Integração com WebSocket

Abra o seu arquivo parcial header.ejs e modifique a seção head para incluir a seguinte lógica de WebSocket quando a aplicação estiver no modo de desenvolvimento: 


        <% if (NODE_ENV.includes('dev')) { %>
            <script>
                // Get the current hostname and port from the browser
                const host = window.location.hostname;
                const currentPort = window.location.port;

                // Calculate WebSocket port (current port + 1)
                const wsPort = currentPort ? (parseInt(currentPort) + 1) : 3001;

                // Create WebSocket connection using dynamic hostname and port
                const ws = new WebSocket(`ws://${host}:${wsPort}`);
                ws.onclose = () => {
                    setTimeout(() => location.reload(), 2000);
                };
            </script>
        <% } %>

Observe como agora podemos usar NODE_ENV diretamente no modelo sem ter que passá-la de cada rota. Este script abre uma conexão WebSocket para uma porta uma unidade acima da porta principal da aplicação. Se a conexão for fechada, a página é recarregada após um atraso de 2 segundos, simulando o live reloading quando nossa aplicação está no modo de desenvolvimento.

3. Adicionar um Servidor WebSocket ao server.js

Agora precisamos configurar um servidor WebSocket para live reloading no modo de desenvolvimento. Embora os WebSockets sejam normalmente usados para comunicação em tempo real em aplicações como aplicativos de chat ou notificações ao vivo, estamos aproveitando essa tecnologia para atualizar automaticamente o navegador quando alterações forem detectadas. Isso permite atualizações em tempo real sem a necessidade de atualizar a página manualmente. Para começar, instale o pacote ws como uma dependência de desenvolvimento. Abra seu terminal e execute o seguinte comando: 


        pnpm add -D ws

Em seguida, atualize seu arquivo server.js para iniciar o servidor WebSocket no modo de desenvolvimento. Adicione o seguinte código antes do código que inicia o seu servidor Express perto do final do arquivo: 


        // When in development mode, start a WebSocket server for live reloading
        if (NODE_ENV.includes('dev')) {
            const ws = await import('ws');

            try {
                const wsPort = parseInt(PORT) + 1;
                const wsServer = new ws.WebSocketServer({ port: wsPort });

                wsServer.on('listening', () => {
                    console.log(`WebSocket server is running on port ${wsPort}`);
                });

                wsServer.on('error', (error) => {
                    console.error('WebSocket server error:', error);
                });
            } catch (error) {
                console.error('Failed to start WebSocket server:', error);
            }
        }

4. Testar Suas Alterações

Inicie sua aplicação com pnpm run dev, em seguida, modifique seus arquivos EJS, CSS ou JavaScript. Verifique se o navegador recarrega automaticamente quando as alterações são salvas. Se a página não recarregar ou se você encontrar erros, certifique-se de que:

  • O middleware global foi adicionado corretamente ao server.js antes das suas rotas.
  • O script WebSocket em header.ejs está correto.
  • A server.js lógica do WebSocket está funcionando corretamente.
Benefícios do Middleware Global

Ao usar middleware para definir variáveis globais de modelo, você eliminou a necessidade de passar NODE_ENV para cada rota. Essa abordagem escala perfeitamente à medida que sua aplicação cresce, e você pode adicionar facilmente outras variáveis globais, como informações do usuário, configurações do site ou dados de navegação, sem alterar as rotas existentes.

Resumo dos Conceitos-Chave

Nesta Tarefa, você implementou o recarregamento em tempo real para sua aplicação Express e aprendeu sobre variáveis globais de modelo usando middleware. Você configurou a lógica do WebSocket em header.ejs, configurou um servidor WebSocket no modo de desenvolvimento e usou res.locals para disponibilizar dados em todos os modelos. Juntamente com nodemon, este fluxo de trabalho melhora drasticamente a produtividade, eliminando atualizações manuais do navegador e reduzindo código repetitivo em suas rotas.

O padrão de middleware que você acabou de implementar é fundamental para o desenvolvimento com Express. À medida que suas aplicações se tornam mais complexas, você achará res.locals inestimável para armazenar o status de autenticação do usuário, permissões, configuração em todo o site e outros dados aos quais múltiplos modelos precisam ter acesso.
