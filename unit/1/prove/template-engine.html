Motores de Modelos, Parciais e Layouts

Nesta tarefa, você transformará seu site HTML estático em uma aplicação dinâmica e de fácil manutenção usando o motor de modelos EJS. Você aprenderá por que os motores de modelos são essenciais para o desenvolvimento web moderno, como criar componentes reutilizáveis chamados parciais e como organizar suas visualizações para melhor manutenção.

Ao final desta tarefa, você entenderá como os motores de modelos resolvem problemas reais que o HTML estático não consegue resolver e terá o fundamento para construir aplicações web escaláveis.

O Problema com o HTML Estático

Sua aplicação Express atual funciona, mas tem várias limitações significativas que se tornam evidentes à medida que os sites crescem. Considere o que acontece quando você deseja fazer uma alteração simples, como atualizar seu menu de navegação ou alterar o ano dos direitos autorais no seu rodapé.

Com arquivos HTML estáticos, você precisaria abrir cada arquivo HTML e fazer a mesma alteração em cada um deles. Se esquecer um arquivo, seu site se tornará inconsistente. Adicione mais dez páginas e você terá mais dez lugares onde as alterações devem ser feitas perfeitamente. Essa abordagem não escala e leva a pesadelos de manutenção.

O HTML estático também não pode se adaptar a diferentes situações. Você não pode alterar o conteúdo com base em quem está visitando, que horas são ou em dados de um banco de dados. Cada visitante vê exatamente a mesma coisa, o que limita severamente o que sua aplicação pode fazer.

Os motores de modelos resolvem esses problemas separando seu conteúdo do seu layout, permitindo criar componentes reutilizáveis e viabilizando a geração de conteúdo dinâmico. Esta tarefa mostrará como.

Entendendo os Motores de Modelos

Um motor de modelos é uma ferramenta que combina modelos (HTML com sintaxe especial) e dados para produzir o HTML final que é enviado ao navegador. Pense nisso como uma mala direta em um processador de texto: você tem um modelo com espaços reservados (placeholders) e o motor preenche esses espaços com dados reais.

O EJS (Embedded JavaScript) é um dos muitos motores de modelos disponíveis para o Express. Ele permite incorporar JavaScript diretamente em seu HTML usando tags especiais, tornando fácil criar conteúdo dinâmico enquanto mantém seus modelos legíveis.

Veja como o processo funciona: quando alguém visita seu site, o Express encontra o modelo EJS apropriado, combina-o com quaisquer dados fornecidos, processa a sintaxe EJS especial e envia o HTML resultante para o navegador do usuário. O usuário nunca vê o código EJS – apenas o HTML final.

Preparação

Construiremos sobre sua aplicação Express da tarefa anterior. Antes de começarmos, vamos fazer uma pequena adição para melhorar sua experiência de desenvolvimento.

Adicionar Configuração do Ambiente de Desenvolvimento

Adicione NODE_ENV=development ao seu .env arquivo (em uma nova linha após a sua configuração de PORT). Isso informa à sua aplicação que ela está sendo executada no modo de desenvolvimento, o que será útil para funcionalidades como depuração e recarregamento em tempo real em tarefas futuras: 


        NODE_ENV=development
        PORT=3000

Em seguida, em seu server.js arquivo, adicione esta variável ao lado da sua variável PORT existente: 


        const NODE_ENV = process.env.NODE_ENV || 'production';
        const PORT = process.env.PORT || 3000;

O valor padrão de production garante que sua aplicação seja executada de forma segura se a variável de ambiente não estiver definida, o que é exatamente o que você deseja ao implantar em um servidor em produção.

Instruções da Tarefa

1. Instalar e Configurar o EJS

Primeiro, instale o motor de modelos EJS usando o pnpm: 


        pnpm add ejs

A seguir, configure o Express para usar o EJS adicionando estas linhas ao seu server.js arquivo. Coloque-as na sua seção de configuração de middleware logo após a configuração do diretório estático público: 


        // Set EJS as the templating engine
        app.set('view engine', 'ejs');

        // Tell Express where to find your templates
        app.set('views', path.join(__dirname, 'src/views'));

A primeira linha diz ao Express para usar o EJS para processar modelos. A segunda linha especifica onde seus arquivos de modelo estão localizados. O Express procurará automaticamente por .ejs arquivos neste diretório quando você renderizar visualizações.

A Ordem da Configuração Importa

Estas chamadas de configuração devem vir antes das suas rotas porque o Express precisa saber sobre o mecanismo de modelos antes de tentar renderizar qualquer modelo. Pense nisso como arrumar a cozinha antes de começar a cozinhar.

2. Entendendo Partials

Antes de começarmos a criar modelos, vamos entender o conceito de partials. Um partial é um fragmento de modelo reutilizável que contém código que você deseja usar em vários lugares. Pense nos partials como o equivalente de funções em programação para modelos – eles permitem que você escreva algo uma vez e use em qualquer lugar.

Por exemplo, em vez de copiar seu menu de navegação em cada modelo de página, você cria um partial de navegação e o inclui onde quer que precise dele. Altere a navegação uma vez e ela será atualizada em todos os lugares automaticamente.

Crie um partials diretório dentro do seu src/views diretório. É aqui que armazenaremos nossos componentes de modelo reutilizáveis.

3. Criar Partials de Cabeçalho e Rodapé

Agora vamos criar nossos primeiros partials. Eles conterão os elementos comuns que aparecem em todas as páginas.

Criar o Partial de Cabeçalho

Crie src/views/partials/header.ejs com o seguinte conteúdo: 


        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <meta name="viewport" content="width=device-width, initial-scale=1.0">
            <title><%= title %></title>
            <link rel="stylesheet" href="/css/main.css">
        </head>
        <body>
            <header>
                <nav>
                    <ul>
                        <li><a href="/">Home</a></li>
                        <li><a href="/about">About</a></li>
                        <li><a href="/products">Products</a></li>
                    </ul>
                </nav>
            </header>

Observe a <%= title %> sintaxe. Este é o EJS dizendo ao mecanismo de modelos para inserir o valor de uma variável chamada title. As <%= %> tags significam "gerar a saída deste valor no HTML."

Criar o Partial de Rodapé

Crie src/views/partials/footer.ejs com este conteúdo: 


            <footer>
                <p>&copy; 2025 My Express App.</p>
            </footer>
        </body>
        </html>

Juntos, esses partials fornecem a estrutura HTML completa de que cada página precisa, mas deixam espaço no meio para conteúdo específico da página.

4. Converter HTML Estático em Modelos EJS

Agora vem a transformação. Converteremos seus arquivos HTML estáticos em modelos EJS dinâmicos que usam os partials que acabamos de criar.

Renomeie Seus Arquivos HTML

Primeiro, renomeie seus arquivos HTML existentes para usar a .ejs extensão:

  • home.html → home.ejs
  • about.html → about.ejs
  • products.html → products.ejs

Substitua o Conteúdo pela Estrutura do Modelo

Agora edite cada .ejs arquivo para usar esta estrutura simples: 


        <%- include('partials/header') %>
        <main>
            <h1><%= title %></h1>
            <!-- Put your page-specific content here -->
        </main>
        <%- include('partials/footer') %>

A <%- include() %> sintaxe diz ao EJS para inserir o conteúdo de outro arquivo de modelo. O %- significa "incluir este conteúdo sem escapá-lo" (já que queremos incluir HTML bruto).

Por exemplo, seu home.ejs pode ficar assim: 


        <%- include('partials/header') %>
        <main>
            <h1><%= title %></h1>
            <p>Welcome to my Express application! This site demonstrates the power of templating engines.</p>
            <img src="https://picsum.photos/600/400" alt="Random image">
        </main>
        <%- include('partials/footer') %>
Não Duplique a Estrutura HTML

Ao converter seus arquivos, remova todos os elementos de estrutura HTML como <!DOCTYPE html>, <html>, <head>, <body>, etc. Estes agora são manipulados por seus partials. Inclua apenas o conteúdo exclusivo de cada página dentro das <main> tags.

5. Atualizar Suas Rotas para Usar Modelos

Agora precisamos atualizar suas rotas para renderizar modelos EJS em vez de enviar arquivos HTML estáticos. A principal mudança é alternar de res.sendFile() para res.render().

Atualize suas rotas em server.js para ficarem assim: 


        /**
         * Routes
         */
        app.get('/', (req, res) => {
            const title = 'Welcome Home';
            res.render('home', { title });
        });

        app.get('/about', (req, res) => {
            const title = 'About Me';
            res.render('about', { title });
        });

        app.get('/products', (req, res) => {
            const title = 'Our Products';
            res.render('products', { title });
        });

Aqui está o que mudou:

  • res.render() em vez de res.sendFile(): Isso diz ao Express para processar um modelo EJS em vez de enviar um arquivo estático
  • Nome do modelo sem extensão: 'home' procura automaticamente por home.ejs no seu diretório de visualizações
  • Objeto de dados: O segundo parâmetro { title } fornece dados que o modelo pode usar
Entendendo a Passagem de Dados

Quando você escreve res.render('home', { title }), você está passando um objeto com uma propriedade title para o modelo. Dentro do modelo EJS, <%= title %> gera a saída do valor dessa propriedade. Os nomes das propriedades no seu objeto de dados devem corresponder aos nomes das variáveis usadas nos seus modelos.

6. Testar Sua Aplicação com Modelos

A estrutura do seu projeto deve ficar assim agora: 


        [project-root]
        ├── public/
        │   └── css/
        │       └── main.css
        ├── src/
        │   └── views/
        │       ├── partials/
        │       │   ├── header.ejs
        │       │   └── footer.ejs
        │       ├── about.ejs
        │       ├── home.ejs
        │       └── products.ejs
        ├── .env
        └── server.js

Inicie seu servidor com pnpm run dev e teste cada página:

  • Verifique se os títulos das páginas aparecem corretamente na guia do navegador
  • Verifique se a navegação funciona em todas as páginas
  • Confirme se os seus estilos CSS ainda estão sendo aplicados
  • Certifique-se de que o rodapé apareça em todas as páginas

Se tudo funcionar corretamente, você converteu com sucesso o HTML estático para modelos dinâmicos! Agora tente alterar algo no seu partial de cabeçalho e recarregue a página – você verá a alteração refletida em todas as páginas imediatamente.

Compreendendo a Sintaxe do EJS

Agora que você tem uma aplicação com modelos funcionando, vamos revisar parte da sintaxe do EJS que você esteve usando:

  • <%= variable %>: Exibe o valor de uma variável no HTML (escapa caracteres HTML para segurança)
  • <%- variable %>: Exibe o valor sem escapar (use para incluir conteúdo HTML)
  • <% code %>: Executa código JavaScript sem exibir nenhuma saída (útil para laços e condicionais)
  • <%- include('file') %>: Inclui outro arquivo de modelo

Essas tags simples oferecem recursos poderosos para criar conteúdo dinâmico enquanto mantêm seus modelos legíveis e fáceis de manter.

Resumo dos Conceitos-Chave

Ao concluir esta Tarefa, você resolveu os problemas que identificamos com o HTML estático:

  • Manutenibilidade: Altere sua navegação ou rodapé uma vez e ele será atualizado em todos os lugares
  • Consistência: Todas as páginas compartilham a mesma estrutura e estilo automaticamente
  • Conteúdo Dinâmico: Os títulos das páginas mudam com base na rota, e você pode facilmente adicionar mais elementos dinâmicos
  • Escalabilidade: Adicionar novas páginas requer apenas a criação do conteúdo exclusivo, e não a duplicação de toda a estrutura
  • Organização: O código relacionado é agrupado, tornando seu projeto mais fácil de entender e modificar

Estes benefícios se tornarão ainda mais evidentes conforme você adicionar mais funcionalidades e páginas à sua aplicação.

Aprofunde-se

Para aprofundar sua compreensão dos conceitos de modelos, tente estas melhorias opcionais:

  • Ano de Direitos Autorais Dinâmico: Modifique o seu partial de rodapé para exibir o ano atual usando <%= new Date().getFullYear() %>
  • Partial do Head: Extraia a seção <head> em seu próprio partial para uma organização ainda melhor
  • Partial de Navegação: Crie uma parcial de navegação separada que possa ser reutilizada em diferentes layouts e remova os links fixos da sua parcial de cabeçalho

Estes exercícios ajudarão você a entender como os motores de modelos permitem uma geração de conteúdo dinâmico mais sofisticada.
