Criando e Gerenciando Seu Repositório Git

Gerenciar seu código com o Git é uma habilidade essencial para desenvolvedores. Nesta Tarefa, você aprenderá a criar um repositório Git no GitHub, cloná-lo para o seu computador local e adicionar os arquivos necessários para o seu Projeto prático. Essa abordagem é mais simples e intuitiva do que criar um repositório localmente primeiro, espelhando como a maioria dos desenvolvedores trabalha com o Git em ambientes profissionais e facilitando o início com o controle de versão.

Se você é iniciante no Git, a IA pode guiá-lo no processo de configuração. Certifique-se de fornecer informações sobre seu sistema operacional e seu nível de experiência com Git e GitHub para obter assistência personalizada. Além do suporte por IA, existem inúmeros recursos online, incluindo tutoriais no YouTube, que podem ajudá-lo ao longo do caminho. Se preferir manuais e documentação, recomendamos revisar o livro Pro Git, que oferece um guia abrangente tanto sobre os fundamentos do Git quanto sobre tópicos avançados.

Instruções da Tarefa

Se você é iniciante no Git, recomendamos começar com a abordagem focada no GitHub. Esse método permite criar seu repositório diretamente no GitHub, o que é mais simples e garante que seu repositório remoto seja configurado corretamente desde o início. Se você se sente confortável com o terminal e prefere aprender todo o processo de criação de um repositório local primeiro, pode seguir as instruções alternativas no final deste documento.

1. Instalar e Configurar o Git

Antes de trabalhar com repositórios, certifique-se de que o Git esteja instalado, atualizado e devidamente configurado em seu sistema.

Verificar se o Git está instalado

Execute o seguinte comando para verificar se o Git está instalado: 


        git --version

Se o Git estiver instalado, isso exibirá o número da versão. Caso contrário, prossiga para a próxima seção para instalar o Git.

Instalar o Git (se necessário)

Siga as instruções do seu sistema operacional para instalar o Git:

  • Windows: Baixe o instalador em https://git-scm.com/ e siga as instruções de configuração.
  • macOS: Instale o Git usando o Homebrew ou as ferramentas de linha de comando do Xcode: 
    
                brew install git
                # or
                xcode-select --install
  • Linux: Use seu gerenciador de pacotes para instalar o Git: 
    
                sudo apt update && sudo apt install git

Configurar o Git

Configure suas configurações globais do Git com seu nome e endereço de e-mail. Essas informações serão anexadas a todos os seus commits e ficarão visíveis publicamente no histórico do seu repositório. Se você se preocupa com a privacidade, pode usar um pseudônimo ou seu nome de usuário do GitHub em vez de seu nome real, e considerar o uso de um endereço de e-mail sem resposta (no-reply): 


        git config --global user.name "Your Name"
        git config --global user.email "your-email@example.com"

Por privacidade, você pode usar o endereço de e-mail no-reply do GitHub. Substitua [your-username] pelo seu nome de usuário real do GitHub: 


        git config --global user.email "[your-username]@users.noreply.github.com"

2. Criar Repositório no GitHub

Comece criando seu repositório diretamente no GitHub. Essa abordagem é mais simples e garante que seu repositório remoto seja configurado corretamente desde o início.

  1. Faça login no GitHub: Acesse github.com e entre na sua conta.
  2. Crie um novo repositório:
    • Clique no botão verde Novo ou no ícone + no canto superior direito
    • Selecione Novo repositório
  3. Configure seu repositório:
    • Nome do repositório: cse340-practice-[lastname] (substitua [lastname] com seu sobrenome real)
    • Descrição: "Projeto de prática para o CSE 340" (opcional, mas recomendado)
    • Visibilidade: Público (está tudo bem para trabalhos de curso)
    • Inicializar repositório: Marque "Add a README file"
    • Adicionar .gitignore: Selecione "Node" no menu suspenso de modelo
  4. Criar repositório: Clique no botão verde Criar repositório.

Parabéns! Seu repositório agora existe no GitHub com um arquivo README e um arquivo .gitignore para Node.js criado automaticamente. Isso oferece um fundamento sólido para começar.

3. Clonar o repositório para o seu computador

Agora você fará o download (clonar) do seu repositório do GitHub para o seu computador local para poder trabalhar nele.

  1. Copie a URL do repositório: Na página do seu repositório do GitHub, clique no botão verde Code e copie a URL HTTPS; você pode usar a URL SSH se tiver configurado chaves SSH.
  2. Escolha um local: Navegue até um diretório no seu computador onde deseja armazenar seu projeto. Isso não deve estar em uma pasta sincronizada com a nuvem, como o OneDrive ou o Google Drive.
  3. Abra o terminal: Abra o seu terminal ou prompt de comando nesse local; ou navegue até ele usando o cd comando.
  4. Clone o repositório: Execute o seguinte comando, substituindo a URL pela URL do repositório que você copiou: 
    
                git clone https://github.com/[your-username]/cse340-practice-[lastname].git
  5. Navegue até o seu projeto: Mova para o diretório recém-criado: 
    
                cd cse340-practice-[lastname]

Agora você tem uma cópia local do seu repositório que está conectada automaticamente ao GitHub!

4. Personalizar o arquivo .gitignore

O GitHub criou um arquivo .gitignore do Node.js para você, mas você precisa adicionar mais uma entrada para garantir que os arquivos de ambiente não sejam rastreados.

Abra o arquivo .gitignore no seu editor de texto e adicione .env ao início do arquivo em uma linha própria. O arquivo deve incluir essa linha juntamente com muitas outras entradas relacionadas ao Node.js que o GitHub adicionou automaticamente. Salve o arquivo quando terminar.

Se o seu arquivo .gitignore estiver ausente, você poderá criar um novo na raiz do seu repositório com o seguinte conteúdo: 

            .env
            node_modules/

5. Adicionar o arquivo restore.js

Durante o desenvolvimento, seu servidor pode ocasionalmente falhar ou parar de responder, o que pode deixar processos de servidor órfãos (tarefas em segundo plano) que continuam sendo executados mesmo após o término do processo principal. Esses processos órfãos podem consumir recursos do sistema, impedir que seu servidor reinicie adequadamente e podem fazer com que seu servidor se reconecte a um processo desatualizado em vez de iniciar um novo.

Baixe o arquivo restore.js e salve-o no diretório raiz do repositório do seu projeto. Para usá-lo, execute: 


        node restore.js 3000 3001

O script utilitário restore.js ajuda você a identificar e encerrar processos de servidor órfãos que possam permanecer após falhas. Manter esse script em seu repositório garante que você possa resolver problemas rapidamente se o seu servidor parar de responder ou falhar ao reiniciar devido a processos pendentes. No futuro, se você perceber que seu servidor não está atualizando e continua mostrando conteúdo antigo, executar esse script pode ajudar a limpar quaisquer processos travados e fazer com que seu servidor volte a um estado limpo.

Se você tiver interesse em aprender mais sobre processos órfãos e como gerenciá-los, considere ler o artigo O que é um processo órfão? do GeeksforGeeks.

6. Configurar as configurações do VS Code

Crie um diretório .vscode na raiz do seu repositório para armazenar as configurações do Visual Studio Code. Isso melhorará sua experiência de desenvolvimento personalizando como o VS Code exibe os arquivos do seu projeto.

Dentro do diretório .vscode, crie um arquivo settings.json com o seguinte conteúdo: 


        {
            "explorer.compactFolders": false
        }

Essa configuração desativa a exibição compacta de pastas no explorador de arquivos do VS Code, facilitando a navegação pela estrutura do seu projeto.

7. Fazer commit e enviar suas alterações

Agora você salvará suas alterações no repositório e as enviará para o GitHub:

  1. Verifique o status: Veja quais arquivos foram adicionados ou alterados: 
    
                git status
  2. Adicione todas as alterações: Prepare todos os novos arquivos: 
    
                git add .
  3. Faça commit das suas alterações: Crie um commit com uma mensagem descritiva: 
    
                git commit -m "Added project files and VS Code settings"
  4. Envie para o GitHub: Envie suas alterações para o GitHub: 
    
                git push

Visite a página do seu repositório no GitHub para verificar se seus arquivos foram enviados com sucesso.

Faça Commit Com Frequência

A partir deste ponto, crie o hábito de fazer commit do seu código com frequência. Commits regulares permitem que seu instrutor e colegas de equipe analisem seu progresso e forneçam feedback em tempo útil. Uma boa regra é fazer commit após concluir cada Tarefa principal ou marco significativo em seu trabalho. Sempre escreva mensagens de commit claras e significativas que expliquem a finalidade da alteração. Para ajudá-lo a manter a consistência, considere seguir o Conventional Commits padrão. Para uma referência rápida, consulte a Cheatsheet do Conventional Commits.

Benefícios do GitHub para Estudantes

Como estudante, você se qualifica para o GitHub Pro gratuitamente, que oferece funcionalidades e benefícios adicionais que podem aprimorar sua experiência de aprendizado. Esses benefícios não são obrigatórios para este curso, mas podem ser úteis para seus projetos de desenvolvimento e carreira futura.

Como Obter o GitHub Pro

  1. Visite a página do GitHub Student Developer Pack.
  2. Clique em "Get your pack" e entre com sua conta do GitHub.
  3. Verifique seu status de estudante usando seu endereço de e-mail escolar. Se necessário, você pode obter uma carta de verificação em https://web.byui.edu/verify.
  4. Aguarde a conclusão da verificação. Assim que for aprovado, você terá acesso ao GitHub Pro e a outras ferramentas de desenvolvedor.

Instruções de Tarefa Alternativas

Linha de Comando Primeiro (Opcional)

Se você preferir criar seu repositório localmente primeiro e depois conectá-lo ao GitHub, poderá usar esta abordagem alternativa. Esse método requer mais etapas, mas oferece experiência com o fluxo de trabalho completo do Git.

Esta seção é opcional. A abordagem "GitHub em primeiro lugar" descrita acima é recomendada para iniciantes e é o método usado pela maioria dos desenvolvedores profissionais. Se preferir aprender o processo completo, você pode seguir estas etapas para criar um repositório local primeiro e depois enviá-lo para o GitHub.

Criar Repositório Local Primeiro

  1. Crie um diretório para o seu projeto e navegue até ele: 
    
                mkdir cse340-practice-[lastname]
                cd cse340-practice-[lastname]
  2. Inicialize um repositório Git: 
    
                git init
  3. Crie um arquivo .gitignore básico: 
    
                echo ".env" > .gitignore
                echo "node_modules/" >> .gitignore
  4. Crie um commit inicial: 
    
                git add .gitignore
                git commit -m "Initial commit with .gitignore"
  5. Crie um repositório no GitHub (sem inicializar arquivos).
  6. Conecte seu repositório local ao GitHub: 
    
                git remote add origin https://github.com/[your-username]/cse340-practice-[lastname].git
                git branch -M main
                git push -u origin main

Conclusão

Seu repositório Git agora está configurado e conectado ao GitHub. Você tem um fundamento sólido para controle de versão que inclui a ignoragem adequada de arquivos, utilitários de desenvolvimento e configuração do VS Code. À medida que avança no curso, continue usando o Git para gerenciar suas alterações de código, fazer backup do seu trabalho e enviar suas tarefas.

Lembre-se de fazer commit de suas alterações frequentemente com mensagens descritivas e enviar para o GitHub regularmente para manter seu repositório remoto atualizado.
