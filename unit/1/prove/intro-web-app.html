Configurando Seu Primeiro Projeto Node.js

Introdução

Esta Tarefa guiará você na configuração do seu primeiro projeto Node.js usando pnpm. Você aprenderá sobre a estrutura e o propósito do package.json arquivo. Além disso, você adicionará pacotes essenciais como express para construir aplicações web e nodemon para um desenvolvimento eficiente. Finalmente, você criará um servidor web simples. Cada etapa foi projetada para ajudar você a entender os fundamentos do Node.js, incentivando o aprendizado prático e a experimentação.

Instruções da Tarefa

1. Inicializar um Novo Projeto

Na última Tarefa, você criou um diretório para o seu projeto ao configurar o seu repositório do GitHub. Navegue até esta pasta no seu terminal e execute o seguinte comando: 


        pnpm init

Isso criará automaticamente um novo package.json arquivo no diretório do seu projeto com valores padrão. Este arquivo é essencial para gerenciar as dependências e metadados do seu projeto. Para um projeto que não se destina a ser implantado como um pacote público, que é o caso desta aula, você pode simplificar o package.json arquivo incluindo apenas os campos essenciais necessários para seus processos de desenvolvimento e compilação. Esses campos essenciais geralmente incluem:

  • name: O nome do seu projeto.
  • dependencies: A lista de pacotes npm dos quais seu projeto depende.
  • devDependencies: A lista de pacotes npm necessários para o desenvolvimento (por exemplo, frameworks de testes, ferramentas de compilação).
  • scripts: Um conjunto de comandos que podem ser executados usando pnpm run ou npm run.

Como usaremos Módulos do ECMAScript (ESM) em vez do CommonJS, você precisa adicionar o "type": "module" campo ao seu package.json arquivo. Isso ativará o suporte para ESM no seu projeto. Se você não estiver familiarizado com as diferenças entre CommonJS e ESM, deve reservar um momento para revisar Entendendo Import e Módulos em JavaScript. Neste ponto, seu package.json arquivo deve conter pelo menos os seguintes campos: 


        {
            "name": "cse340-practice-[lastname]",
            "dependencies": {},
            "devDependencies": {},
            "type": "module",
            "scripts": {
                "start": "node server.js"
            }
        }
Como este projeto não precisa ser publicado no registro do npm, você pode substituir com segurança o conteúdo do package.json arquivo pela estrutura JSON mostrada acima.

Se você tem experiência anterior com Node.js, pode estar se perguntando por que omitimos o main campo. O main campo especifica o ponto de entrada para um módulo, que é o arquivo que será carregado quando alguém importar ou requisitar seu pacote em seu próprio projeto. Por exemplo, se você publicar um módulo no npm ou usá-lo localmente, quando alguém instalar o pacote e usar require('your-package') ou import 'your-package', o Node.js procurará pelo arquivo especificado no main campo. Como não estamos publicando um pacote, não precisamos especificar um ponto de entrada.

2. Adicionar o Express

Express é um framework web popular para Node.js que simplifica a construção de aplicações web e APIs. Para adicioná-lo ao seu projeto, execute: 


        pnpm add express

Isso baixará e adicionará a versão 5.1.0 (ou a versão compatível mais recente dentro do intervalo 5.x) do Express ao seu projeto. Você verá o Express listado como uma dependência em seu package.json arquivo.

3. Adicionar o Nodemon

O Nodemon é uma ferramenta de desenvolvimento que reinicia automaticamente sua aplicação Node.js sempre que você faz alterações no código. Isso evita que você tenha que parar e reiniciar o servidor manualmente. Para adicionar o Nodemon como uma dependência de desenvolvimento, execute: 


        pnpm add -D nodemon

A -D flag especifica que o Nodemon é uma dependência de desenvolvimento, o que significa que ele não será incluído em compilações de produção.

4. Configure o Nodemon

Crie um arquivo chamado nodemon.json no diretório raiz do seu repositório de projeto com a seguinte configuração: 


        {
            "watch": [".", ".env"],
            "ext": "js,css,ejs",
            "ignore": [
                ".git",
                "node_modules"
            ]
        }

Esta configuração diz ao Nodemon:

  • watch – Monitorar o diretório do projeto e o arquivo .env em busca de alterações
  • ext – Reiniciar quando arquivos de modelo JavaScript, CSS ou EJS forem alterados
  • ignore – Não reiniciar o servidor quando arquivos forem alterados nestes diretórios
Listar .env sob watch é necessário. A opção ext do Nodemon corresponde a extensões de arquivo (por exemplo *.js ou *.env), mas o nome de arquivo .env é um arquivo iniciado por ponto sem uma extensão separada, portanto ext: "env" sozinho não detectará edições nele.

Mantenha o comando de execução fora do nodemon.json. Em vez disso, defina como o aplicativo é iniciado em scripts do package.json (próximas etapas). Colocar o mesmo comando em ambos os locais faz com que o Nodemon os concatene em uma linha de inicialização duplicada.

5. Crie um servidor simples

Crie um novo arquivo chamado server.js no diretório raiz dos seus projetos e copie o seguinte código para ele: 


        // Import express using ESM syntax
        import express from 'express';

        // Create an instance of an Express application
        const app = express();

        // Define a route handler for the root URL ('/')
        app.get('/', (req, res) => {
            res.send('Hello, World!');
        });

        // Define the port number the server will listen on
        const PORT = 3000;

        // Start the server and listen on the specified port
        app.listen(PORT, () => {
            console.log(`Server is running on http://127.0.0.1:${PORT}`);
        });

Inicie seu servidor executando: 


        node server.js

Abra seu navegador e navegue até http://127.0.0.1:3000 para visualizar a mensagem "Hello, World!" do seu servidor. Quando terminar os testes, você poderá parar o servidor pressionando Ctrl + C (Windows/Linux) ou Command + C (Mac) no seu terminal.

6. Adicione variáveis de ambiente

As variáveis de ambiente permitem armazenar configurações de forma segura. Crie um arquivo chamado .env no diretório raiz do seu projeto e adicione a seguinte linha, substituindo Your Name pelo seu nome real: 


        NAME="Your Name"

Atualize seu arquivo server.js para usar a variável de ambiente. Você pode acessar variáveis de ambiente no Node.js usando o objeto process.env. Modifique o arquivo server.js para incluir as seguintes alterações: 


        import express from 'express';

        const app = express();

        const name = process.env.NAME; // <-- NEW

        app.get('/', (req, res) => {
            res.send(`Hello, ${name}!`); // <-- UPDATED
        });

        const PORT = 3000;
        app.listen(PORT, () => {
            console.log(`Server is running on http://127.0.0.1:${PORT}`);
        });

Inicie seu servidor executando o seguinte comando modificado anterior, que carrega variáveis de ambiente do arquivo .env: 


        node --env-file=.env server.js

Acessee http://127.0.0.1:3000 no seu navegador e você deverá ver uma nova mensagem sendo exibida com o seu nome.

No passado, usávamos o pacote dotenv para manipular variáveis de ambiente. No entanto, com a flag de linha de comando mais recente --env-file disponível no Node.js, podemos carregar variáveis de ambiente automaticamente sem a necessidade de um pacote adicional. Isso simplifica nossa configuração e reduz as dependências. O objeto process no Node.js é um objeto global que fornece informações sobre o processo atual do Node.js. Ele nos permite acessar variáveis de ambiente usando a propriedade process.env.

Não faça isso em Produção

As variáveis de ambiente são usadas normalmente para armazenar informações confidenciais, como chaves de API, credenciais de banco de dados e outras configurações. É importante mantê-las seguras e não expô-las em seu código ou respostas. Para esta Tarefa, estamos usando variáveis de ambiente para demonstrar o conceito, mas em um cenário do mundo real, você nunca deve expor informações confidenciais dessa forma.

Entendendo as melhores práticas de desenvolvimento

A versão 20.6.0 do Node.js introduziu uma flag integrada --env-file para carregar variáveis de ambiente. Neste curso, você usará essa funcionalidade nativa em vez do pacote dotenv. Envios usando dotenv serão sinalizados por assistência inadequada de IA.

Isso ensina um princípio de desenvolvimento importante: seja intencional sobre as dependências. Cada pacote adicionado aumenta a superfície de ataque e a complexidade de manutenção do seu aplicativo, portanto você deve ter um bom motivo para incluí-lo. Quando a funcionalidade está disponível nativamente ou é simples o suficiente para ser escrita por você mesmo, adicionar um pacote é desnecessário.

Assistentes de código baseados em IA são ferramentas úteis, mas frequentemente sugerem pacotes ou padrões mais antigos porque esses aparecem com frequência em seus dados de treinamento. Se você confiar cegamente nas sugestões de IA, acabará com padrões de código fáceis de reconhecer como gerados por IA. Parte de se tornar um desenvolvedor experiente é avaliar sugestões e escolher a melhor solução para a sua situação, quer isso signifique usar funcionalidades nativas, escrever algumas linhas de código você mesmo ou adicionar um pacote bem escolhido que resolva um problema real.

Certifique-se de entender cada linha de código que escrever. Ao longo do semestre, você precisará explicar seu código, defender suas decisões e justificar sua nota. Até o final do período, você deve ser capaz de defender com confiança cada escolha feita em seus projetos.

7. Use o Nodemon

Normalmente, você teria que parar e reiniciar o servidor toda vez que fizesse alterações no código para que elas surtissem efeito. O Nodemon automatiza esse processo para nós. Modifique a scripts seção do seu package.json arquivo para incluir um dev campo. Mantenha start como uma inicialização simples do Node para execuções no estilo de produção: 


        {
            # Other fields...
            "scripts": {
                "dev": "nodemon --env-file=.env server.js",
                "start": "node server.js"
            }
        }

O dev script é onde você passa --env-file=.env. Como nodemon.json define apenas configurações de monitoramento (sem exec), o Nodemon executa esse comando uma vez sem duplicá-lo. Agora, se você executar seu servidor usando o seguinte comando, o Nodemon reiniciará automaticamente o servidor sempre que os arquivos monitorados forem alterados: 


        pnpm run dev

Adicionamos dois scripts à scripts seção do seu package.json arquivo:

  • dev: Este script usa o Nodemon para iniciar o servidor com a --env-file flag, que carrega variáveis de ambiente do arquivo .env. O Nodemon reinicia o servidor quando os arquivos monitorados são alterados, incluindo .env (por meio da watch entrada em nodemon.json).
  • start: Este script inicia o servidor usando Node.js. Ele é destinado a ambientes de produção onde as variáveis de ambiente são gerenciadas de forma segura pelo serviço de hospedagem. Ao contrário do script de desenvolvimento, ele não reinicia automaticamente o servidor se forem feitas alterações ou se o servidor falhar. Este comando não funcionará localmente para carregar seu .env arquivo local, porque ele não passa --env-file.

Você não precisa mais iniciar o servidor com node --env-file=.env server.js diretamente durante o trabalho do dia a dia. Use o comando dev para desenvolvimento local e reserve start para execuções no estilo de produção. 


        // Start the server in production; this will not load .env locally
        pnpm run start

        // Start the server in development
        pnpm run dev

Acesse http://127.0.0.1:3000 no seu navegador. Com o pnpm run dev ainda em execução, altere o valor da variável NAME no seu arquivo .env e aguarde o Nodemon reiniciar. Em seguida, faça uma alteração no arquivo server.js. Você pode alterar "Hello, ${name}!" para "Welcome ${name}!". Agora volte ao navegador e atualize a página. Você deve ver a mensagem atualizada no seu navegador sem ter que reiniciar o servidor manualmente.

Experimente e Divirta-se

Cobrimos os conceitos básicos de configuração de um projeto Node.js, adição de pacotes, criação de um servidor web simples e uso de variáveis de ambiente. Agora é hora de experimentar e se divertir com seu projeto. Tente adicionar novas rotas ou outras funcionalidades ao seu servidor. Por exemplo, você pode adicionar uma nova rota ao seu servidor modificando seu arquivo server.js: 


app.get('/new-route', (req, res) => {
    res.send('This is a new route!');
});

Salve o arquivo e acesse http://127.0.0.1:3000/new-route para ver sua nova rota em ação. Daqui para frente, cada novo conceito que você aprender poderá ser adicionado a este projeto de prática para construir uma aplicação web mais complexa e rica em funcionalidades.

Conclusão

O que você aprendeu nesta Tarefa é o fundamento para construir aplicações web com Node.js e Express. Na próxima Tarefa, nos aprofundaremos em roteamento e middleware no Express, os conceitos fundamentais que você praticou hoje sem perceber completamente.
