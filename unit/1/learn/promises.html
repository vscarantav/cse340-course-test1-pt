Explorando Promises, Código Assíncrono e Await no JavaScript

A capacidade do JavaScript de lidar com código assíncrono é uma funcionalidade poderosa, mas pode ser desafiadora de entender no início. Nesta Tarefa, você explorará Promises, then(), catch(), finally(), e async/await. Ao final, você terá uma compreensão sólida desses conceitos e poderá usá-los com confiança em seus projetos.

Entendendo Promises

Uma Promise é um objeto que representa a eventual conclusão (ou falha) de uma operação assíncrona. As Promises têm três estados:

  • Pendente: O estado inicial, nem cumprida nem rejeitada.
  • Cumprida: A operação foi concluída com sucesso.
  • Rejeitada: A operação falhou.

Aqui está um exemplo simples de uma Promise: 


        const promise = new Promise((resolve, reject) => {
            const success = true; // Change to false to test rejection.

            if (success) {
                resolve("The operation was successful!");
            } else {
                reject("The operation failed.");
            }
        });

        promise
            .then((message) => {
                console.log("Fulfilled:", message);
            })
            .catch((error) => {
                console.error("Rejected:", error);
            })
            .finally(() => {
                console.log("Promise has settled.");
            });
Tente Você Mesmo

Salve o código acima em um arquivo JavaScript, practice.js por exemplo, e execute o arquivo com este comando node practice.js ou copie e cole o código acima no console do seu navegador e observe a saída. Experimente alterar a success variável.

Relacionando Promises a Try/Catch/Finally

As Promises funcionam de maneira semelhante ao try/catch/finally bloco que você pode ter usado para código síncrono. O exemplo a seguir demonstra a similaridade com um código funcional; apenas os blocos try e finally serão executados. Altere o código dentro do try bloco para JavaScript incorreto para ver como isso afeta a saída: 


        try {
            // Synchronous code that might throw an error
            const result = "Success!";
            console.log("Result:", result);
        } catch (error) {
            // "Catch" (handle) any errors that occur
            console.error("Error:", error);
        } finally {
            // Code that runs "finally", regardless of success or failure
            console.log("Operation complete.");
        }

Encadeando Promises com then()

As Promises podem ser encadeadas usando then() para lidar com sequências de tarefas assíncronas: 


        const step1 = () => {
            return new Promise((resolve) => {
                console.log("Step 1 completed.");
                resolve("Step 1 result");
            });
        };

        const step2 = (prevResult) => {
            return new Promise((resolve) => {
                console.log("Step 2 completed with:", prevResult);
                resolve("Step 2 result");
            });
        };

        step1()
            .then(step2)
            .then((finalResult) => {
                console.log("All steps completed. Final result:", finalResult);
            });

Salve o código acima em um arquivo JavaScript, practice.js por exemplo, e execute o arquivo com este comando node practice.js ou copie e cole o código acima no console do seu navegador e observe a saída. Observe como cada etapa depende da anterior.

Tratando Erros com catch()

As Promises permitem tratar erros usando catch(). No exemplo abaixo, observe o parâmetro adicional em nossa função de promise, reject. Uma função de promise completa deve incluir tanto resolve() quanto reject(), chamando o apropriado para indicar sucesso ou falha. É uma prática comum declarar promises com nomes de parâmetros abreviados como este: new Promise((res, rej) => { ... }). Se você executar o seguinte código, ele deve registrar no log a mensagem de erro da nossa reject(...) e depois a mensagem de log do finally() bloco: 


        const failingStep = () => {
            return new Promise((resolve, reject) => {
                reject("Something went wrong!");
            });
        };

        failingStep()
            .then((result) => {
                console.log("This will not run:", result);
            })
            .catch((error) => {
                console.error("Caught an error:", error);
            })
            .finally(() => {
                console.log("Execution finished.");
            });

Entendendo Async/Await

Considere a programação assíncrona semelhante a assistir à Netflix por streaming enquanto baixa um videogame grande. Você quer garantir que a transmissão da Netflix continue sem problemas e sem interrupções do download do jogo. É aqui que o código assíncrono se torna essencial.

A async palavra-chave cria uma função que lida com essas tarefas paralelas, envolvendo tudo automaticamente em Promises. A await palavra-chave permite pausar e esperar que essas Promises sejam resolvidas, assim como você aprendeu anteriormente. Aqui está como as Promises eram antes: 


        // Old way with Promises
        fetchUserData()
            .then(user => fetchUserPosts(user))
            .then(posts => {
                console.log(posts);
            })
            .catch(error => {
                console.log("Error:", error);
            });

Agora aqui está o mesmo código com async/await em vez disso: 


        // New way with async/await
        async function getUserPosts() {
            try {
                const user = await fetchUserData();
                const posts = await fetchUserPosts(user);
                console.log(posts);
            } catch (error) {
                console.log("Error:", error);
            }
        }

Exemplo do Mundo Real: Chamada de API do Spotify

Vamos ver algo prático, como buscar uma lista de reprodução do Spotify: 


        const getPlaylist = async () => {
            try {
                console.log("Loading playlist...");
                const playlist = await spotifyAPI.getPlaylist('top_hits');
                const tracks = await spotifyAPI.getPlaylistTracks(playlist.id);
                return tracks;
            } catch (error) {
                console.log("Couldn't load playlist:", error);
            }
        };

        // Using it is simple:
        getPlaylist().then((tracks) => {
            console.log(`Here are the playlist tracks!\\n${tracks}`);
        });

Pontos-chave

  • async funções sempre retornam uma Promise
  • await funciona apenas dentro de async funções
  • Você terá que usar try/catch para tratamento de erros dentro de async funções

Exercício Prático

Vamos criar um sistema simulado de pedidos de comida para praticar o trabalho com Promises e async/await. Crie um novo arquivo JavaScript chamado food-court.js e adicione o seguinte código a ele: 


        // Simulates getting menu data
        function getMenu() {
            return new Promise((resolve) => {
                setTimeout(() => {
                    resolve([
                        'Burger',
                        'Pizza',
                        'Tacos',
                        'Sushi'
                    ]);
                }, 1500);
            });
        }

        // Simulates placing an order
        function placeOrder(food) {
            return new Promise((resolve, reject) => {
                setTimeout(() => {
                    if (food) {
                        resolve(`Your ${food} order has been placed!`);
                    } else {
                        reject('Please select a food item!');
                    }
                }, 2000);
            });
        }

        // Simulates order preparation
        function prepareOrder(order) {
            return new Promise((resolve, reject) => {
                setTimeout(() => {
                    if (order.includes('placed')) {
                        resolve('Your food is ready for pickup! 🍔');
                    } else {
                        reject('Something went wrong with your order!');
                    }
                }, 3000);
            });
        }

        // Using Promises (the traditional way)
        function orderFoodWithPromises() {
            console.log('Starting your order (Promise version)...');
            
            getMenu()
                .then(menu => {
                    console.log('Menu items:', menu);
                    return placeOrder(menu[0]);
                })
                .then(orderMessage => {
                    console.log(orderMessage);
                    return prepareOrder(orderMessage);
                })
                .then(ready => {
                    console.log(ready);
                })
                .catch(error => {
                    console.log('Error:', error);
                })
                .finally(() => {
                    console.log('Order process complete. (Simulation Competed)');
                });
        }

        // Using async/await (the modern way)
        async function orderFoodWithAsync() {
            try {
                console.log('Starting your order (async/await version)...');
                
                const menu = await getMenu();
                console.log('Menu items:', menu);
                
                const orderMessage = await placeOrder(menu[0]);
                console.log(orderMessage);
                
                const ready = await prepareOrder(orderMessage);
                console.log(ready);
                
            } catch (error) {
                console.log('Error:', error);
            } finally {
                console.log('Order process complete. (Simulation Competed)');
            }
        }

        // Try both versions!
        orderFoodWithPromises();
        // orderFoodWithAsync();

Agora execute este código usando o comando do Node.js node food-court.js ou, se quiser, copie e cole o código no console do seu navegador. Você pode comentar uma das chamadas de função para comparar a versão baseada em Promise com a versão async/await.

Este exemplo demonstra operações assíncronas do mundo real usando timeouts para simular requisições de rede. Cada função retorna uma Promise, e você pode ver o quão mais limpa a versão async/await fica em comparação com as cadeias de Promises.

Ideias para Experimentação

  • Tente alterar o item de comida sendo pedido (use diferentes índices do array)
  • Passe null para placeOrder() para ver o tratamento de erros em ação
  • Modifique os timeouts para ver como o tempo afeta o processo
  • Adicione uma nova etapa ao processo (como entrega ou pagamento)
  • Se você for realmente aventureiro, faça desta uma aplicação interativa!

Olhando para o Futuro: Construindo com Express

Os padrões assíncronos que abordamos hoje formam o fundamento do desenvolvimento web moderno. Em nossas próximas Tarefas, aplicaremos esses conceitos à medida que nos aprofundarmos no Express, um poderoso framework Node.js para construir aplicações web.

A conexão é direta: Ao construir servidores web com o Express, você lidará com múltiplas requisições concorrentes usando os mesmos padrões assíncronos que acabamos de aprender. Seu servidor precisará processar múltiplas interações de usuários simultaneamente enquanto mantém um desempenho fluido. Por exemplo, assim como esperamos que nossos pedidos de comida simulados fossem processados, suas rotas do Express lidarão com interações de usuários e operações de banco de dados. A async/await sintaxe que você aprendeu hoje ajudará você a gerenciar essas operações de forma limpa e eficaz, garantindo que suas aplicações web permaneçam responsivas mesmo sob alta carga de usuários.
