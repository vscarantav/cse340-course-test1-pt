Referência de Terminologia do CSE 340

Este guia de referência fornece definições para termos-chave usados em todo o CSE 340: Desenvolvimento Web Back-End. Use isto como uma referência rápida quando encontrar terminologias não familiares em tarefas, materiais de leitura ou trabalhos de projetos. Os termos estão organizados por categoria para ajudar você a encontrar conceitos relacionados juntos.

Termos Técnicos Principais

Framework
Uma estrutura pré-construída que fornece um fundamento para a construção de aplicações. Frameworks impõem padrões específicos e fornecem ferramentas que lidam com tarefas comuns, permitindo que os desenvolvedores se concentrem na lógica específica da aplicação em vez de reinventar a funcionalidade básica. O Express.js é um framework de aplicação web para Node.js.
Biblioteca / Pacote
Uma coleção de código pré-escrito que fornece funcionalidades específicas que você pode importar e usar em sua aplicação. Ao contrário dos frameworks, as bibliotecas dão a você mais controle sobre como e quando usar suas funcionalidades. No Node.js, os pacotes são distribuídos por meio do npm (Node Package Manager).
Roteamento
O processo de determinar como uma aplicação responde a caminhos de URL específicos e métodos HTTP. As rotas mapeiam URLs para funções manipuladoras que geram respostas. Por exemplo, app.get('/about', handler) cria uma rota que responde a requisições GET no caminho /about.
Middleware
Funções que executam durante o ciclo requisição-resposta, entre o recebimento de uma requisição e o envio de uma resposta. O middleware pode modificar objetos de requisição e resposta, encerrar o ciclo requisição-resposta ou passar o controle para a próxima função middleware. Usos comuns incluem registro de logs, autenticação, análise de corpos de requisição e fornecimento de arquivos estáticos.
Package.json
Um arquivo JSON que contém metadados sobre um projeto Node.js, incluindo nome do projeto, versão, dependências, scripts e outras configurações. Este arquivo permite que o npm identifique o projeto e gerencie suas dependências. Executar npm install lê este arquivo para instalar todos os pacotes necessários.
Objeto de Requisição (req)
Um objeto que representa a requisição HTTP que o Express passa para manipuladores de rotas e middleware. Contém informações sobre a requisição, incluindo parâmetros de URL (req.params), strings de consulta (req.query), corpo da requisição (req.body), cabeçalhos e método HTTP.
Objeto de Resposta (res)
Um objeto que representa a resposta HTTP que o Express envia de volta ao cliente. Fornece métodos para enviar respostas como res.send(), res.json(), res.render()e res.redirect(). Também usado para definir códigos de status e cabeçalhos.
Ciclo de Vida de Requisição–Resposta
O processo completo desde o momento em que um servidor recebe uma requisição HTTP até quando envia de volta uma resposta HTTP. No Express, esse ciclo de vida inclui roteamento, execução de middleware, lógica de controlador e geração de respostas. Compreender esse fluxo é essencial para a depuração e a construção de aplicações web eficazes.
Arquivo de Ambiente (.env)
Um arquivo que armazena variáveis de configuração e informações confidenciais, como credenciais de banco de dados, chaves de API e configurações do servidor. Essas variáveis são carregadas na aplicação no tempo de execução usando pacotes como dotenv. Arquivos de ambiente nunca devem ser submetidos a commit no controle de versão e geralmente são listados no .gitignore.
Tipos de Caminho
Caminho Absoluto
Um caminho completo a partir da raiz do sistema de arquivos até um arquivo ou diretório específico. Em sistemas baseados em Unix, os caminhos absolutos começam com / (por exemplo, /home/user/project/file.js). No Windows, eles começam com uma letra de unidade (por exemplo, C:\Users\project\file.js).
Caminho Relativo
Um caminho que é relativo ao diretório de trabalho atual ou à localização do arquivo atual. Usa ./ para referenciar o diretório atual e ../ para referenciar o diretório pai (por exemplo, ../models/data.js).
Caminho Relativo à Raiz
Um caminho relativo à raiz do projeto ou do servidor, normalmente começando com / em contextos web. Em aplicações web, /css/style.css refere-se ao arquivo CSS a partir da raiz do servidor web, independentemente da localização atual da página.

Estrutura e Arquitetura da Aplicação

Model–View–Controller (MVC)
Um padrão arquitetural que separa uma aplicação em três componentes interconectados: Models (dados e lógica de negócios), Views (interface do usuário e apresentação) e Controllers (manipulam requisições e coordenam entre Models e Views). Essa separação melhora a organização do código, a manutenibilidade e a testabilidade.
Model
O componente responsável por gerenciar os dados, a lógica de negócios e as regras da aplicação. Os models interagem com bancos de dados, validam dados e contêm a funcionalidade principal da aplicação. Na arquitetura MVC, os models são independentes da interface do usuário.
View
O componente responsável por apresentar dados aos usuários. As views geram a interface do usuário renderizando modelos com dados fornecidos pelos controllers. Em aplicações web, as views normalmente produzem HTML que é enviado ao navegador.
Controller
O componente que manipula requisições do usuário, processa entradas, interage com os models para recuperar ou modificar dados e seleciona as views apropriadas para renderizar respostas. Os controllers atuam como intermediários entre models e views, coordenando o fluxo da aplicação.
Projeto Brownfield
Um Projeto que envolve atualizar, modificar ou integrar com um sistema ou base de código existente. O desenvolvimento brownfield requer a compreensão do código existente, o trabalho dentro de restrições estabelecidas e, frequentemente, refatorar o código legado enquanto mantém a funcionalidade.
Projeto Greenfield
Um Projeto que envolve a construção de um sistema totalmente novo do zero, sem as restrições de sistemas ou códigos existentes. Projetos greenfield oferecem mais liberdade nas escolhas de tecnologia e decisões de arquitetura, mas exigem construir tudo do zero.
Refatoração
O processo de melhorar a estrutura, legibilidade e manutenibilidade do código sem alterar seu comportamento ou funcionalidade externa. A refatoração pode envolver renomear variáveis, extrair funções, reorganizar arquivos ou simplificar lógicas complexas enquanto garante que a aplicação continue funcionando da mesma forma.

Fundamentos da Web

Códigos de Status HTTP
Códigos de três dígitos que indicam o resultado de uma requisição HTTP. Os códigos de status são agrupados em cinco categorias:
1xx Informativo
A requisição foi recebida e está sendo processada. Estes são raramente usados em aplicações web típicas. Exemplo: 100 Continue.
2xx Sucesso
A requisição foi recebida, compreendida e processada com sucesso. Exemplos: 200 OK (requisição GET bem-sucedida), 201 Created (POST bem-sucedido que criou um recurso).
3xx Redirecionamento
Ações adicionais são necessárias para concluir a requisição, normalmente redirecionando para outra URL. Exemplos: 301 Moved Permanently, 302 Found (redirecionamento temporário), 304 Not Modified.
4xx Erro do Cliente
A requisição contém dados inválidos ou não pode ser atendida devido a um erro do cliente. Exemplos: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found.
5xx Erro do Servidor
O servidor falhou ao atender a uma requisição válida. Exemplos: 500 Internal Server Error, 503 Service Unavailable.
Métodos GET vs POST
GET e POST são métodos HTTP com propósitos diferentes. Requisições GET recuperam dados do servidor e não devem modificar o estado do servidor. Parâmetros GET são visíveis na URL e possuem limitações de comprimento. Requisições POST enviam dados ao servidor, normalmente para criar ou atualizar recursos. Os dados POST são enviados no corpo da requisição, não são visíveis na URL e não têm um limite prático de tamanho.
Parâmetros de Consulta
Pares chave-valor opcionais adicionados ao final de uma URL após um ponto de interrogação, usados para passar dados ao servidor. Múltiplos parâmetros são separados por "e comercial" (&). Exemplo: /search?term=express&sort=relevance. No Express, os parâmetros de consulta são acessados via req.query.
Parâmetros de Rota
Segmentos nomeados no caminho de uma URL que capturam valores e os disponibilizam para a aplicação. Definidos com um prefixo de dois pontos em padrões de rota. Exemplo: /users/:id corresponde a /users/123 e disponibiliza 123 disponível em req.params.id. Parâmetros de rota fazem parte da estrutura do caminho e normalmente são obrigatórios.
Mensagem Flash
Uma mensagem temporária armazenada na sessão que é exibida uma vez ao usuário após um redirecionamento e depois excluída automaticamente. Mensagens flash são comumente usadas para mostrar confirmações de sucesso, mensagens de erro ou notificações após envios de formulários ou outras ações que resultam em um redirecionamento.

Conceitos de Segurança

Autenticação
O processo de verificação da identidade de um usuário ou sistema. A autenticação responde à pergunta "Quem é você?". Métodos comuns de autenticação incluem nome de usuário e senha, autenticação multifator e sistemas baseados em token. Uma autenticação bem-sucedida normalmente resulta na criação de uma sessão ou na emissão de um token.
Autorização
O processo de determinar o que um usuário autenticado tem permissão para fazer. A autorização responde à pergunta "O que você pode fazer?". Ela controla o acesso a recursos e funcionalidades com base nas permissões ou funções do usuário. A autorização sempre segue a autenticação.
Controle de Acesso
A prática de gerenciar e aplicar permissões que determinam quem pode visualizar ou modificar recursos específicos. O controle de acesso garante que os usuários só possam acessar dados e funcionalidades adequados ao seu papel ou nível de permissão.
Controle de Acesso Baseado em Funções (RBAC)
Uma abordagem de controle de acesso que atribui permissões a funções em vez de usuários individuais. Em seguida, são atribuídas aos usuários uma ou mais funções, herdando as permissões dessas funções. Isso simplifica o gerenciamento de permissões em aplicações com muitos usuários. Exemplo: funções "admin", "editor" e "viewer" com diferentes conjuntos de permissões.
Lista de Controle de Acesso (ACL)
Uma lista ou tabela que especifica quais usuários ou sistemas podem acessar recursos específicos e quais operações podem executar. As ACLs fornecem um controle detalhado listando explicitamente as permissões de cada usuário ou grupo em cada recurso.
Princípio do Menor Privilégio
Um princípio de segurança que estabelece que usuários e sistemas devem ter apenas as permissões mínimas necessárias para concluir suas tarefas. Isso limita os danos potenciais causados por acidentes, erros ou ações maliciosas, restringindo o acesso apenas ao que é essencial.
Defesa em Profundidade
Uma estratégia de segurança que usa múltiplas camadas de proteção para defender contra ameaças. Se uma medida de segurança falhar, outras permanecem ativas para evitar violações. Exemplos incluem a combinação de firewalls, autenticação, validação de entrada, conexões criptografadas e controles de acesso.
Cross-Site Scripting (XSS)
Uma vulnerabilidade de segurança que ocorre quando a entrada do usuário não escapada é injetada em uma página web, permitindo que scripts maliciosos sejam executados nos navegadores de outros usuários. Ataques XSS podem roubar cookies de sessão, redirecionar usuários ou modificar o conteúdo da página. A prevenção inclui escapar a saída adequadamente, validar a entrada e usar cabeçalhos de Política de Segurança de Conteúdo (Content Security Policy).

Conceitos de Banco de Dados & Dados

Tabela
Uma coleção estruturada de dados organizada em linhas e colunas dentro de um banco de dados. Cada tabela representa uma entidade ou conceito específico (como usuários, produtos ou pedidos). As colunas definem os atributos da entidade, enquanto as linhas contêm registros ou instâncias individuais.
Persistência de Dados
A característica dos dados de continuarem existindo após o encerramento da aplicação ou do processo que os criou. Os dados persistentes são normalmente armazenados em bancos de dados ou arquivos, em oposição aos dados temporários armazenados na memória, que desaparecem quando a aplicação é interrompida.
Chave Primária
Uma coluna ou combinação de colunas que identifica de forma exclusiva cada linha em uma tabela de banco de dados. As chaves primárias devem conter valores exclusivos e não podem ser nulas. Toda tabela deve ter uma chave primária para garantir que cada registro possa ser identificado e referenciado de forma distinta.
Chave Estrangeira
Uma coluna ou combinação de colunas em uma tabela que referencia a chave primária de outra tabela. Chaves estrangeiras estabelecem relacionamentos entre tabelas e garantem a integridade referencial, assegurando que os relacionamentos entre tabelas permaneçam consistentes.
Restrição NOT NULL
Uma restrição de banco de dados que impede que uma coluna contenha valores nulos. Quando aplicada, o banco de dados rejeitará qualquer operação de inserção ou atualização que tente deixar essa coluna vazia. Usada para colunas que devem sempre ter um valor.
Restrição DEFAULT
Uma restrição de banco de dados que especifica um valor padrão para uma coluna quando nenhum valor é fornecido durante a inserção. Se uma linha for inserida sem especificar essa coluna, o banco de dados usa automaticamente o valor padrão. Exemplo: uma created_at coluna com um valor padrão do carimbo de data/hora atual.

Conceitos de JavaScript

Template Literals / Template Strings
Literais de string que permitem expressões incorporadas e strings de várias linhas, definidas usando crases em vez de aspas. Os modelos literais usam ${expression} sintaxe para inserir variáveis ou expressões em strings. Exemplo: `Hello, ${name}! You have ${count} messages.`
Arrow Functions
Uma sintaxe concisa para escrever funções usando o => operador. As arrow functions têm uma sintaxe mais curta que expressões de função tradicionais e herdam o this valor do escopo delimitador. Exemplo: const add = (a, b) => a + b
Promises
Objetos que representam a conclusão ou falha eventual de uma operação assíncrona. Promises fornecem métodos como .then() e .catch() para manipular resultados. O JavaScript moderno também suporta a async/await sintaxe para trabalhar com promises em um estilo de aparência mais síncrona.
Módulos
Pedaços reutilizáveis de código que podem ser exportados de um arquivo e importados em outro, promovendo a organização e reutilização de código. O JavaScript possui dois sistemas de módulos:
CommonJS
O sistema de módulos original do Node.js usando require() para importar e module.exports para exportar. Exemplo: const express = require('express')
ES Modules (ESM)
O padrão moderno de módulos do JavaScript usando as import e export instruções. Exemplo: import express from 'express'. Os ES Modules agora são totalmente suportados no Node.js e são a abordagem preferida para novos projetos.

Conceitos de UX e UI

Interface do Usuário (UI)
Os componentes visuais e interativos de uma aplicação com os quais os usuários interagem diretamente, incluindo botões, formulários, menus, layouts e estilização. A interface do usuário foca no visual e na apresentação da aplicação.
Experiência do Usuário (UX)
A experiência geral e a satisfação que um usuário tem ao interagir com uma aplicação. A UX abrange usabilidade, acessibilidade, desempenho, estética e como a aplicação faz os usuários se sentirem. Uma boa UX considera toda a jornada do usuário, não apenas elementos individuais da interface.
