Refatorando seu Catálogo de Cursos para a Arquitetura MVC

Conforme sua aplicação Express cresce, manter todo o seu código em server.js torna-se difícil de manter. Aplicações web profissionais usam a Model-View-Controller (MVC) arquitetura para organizar o código em partes lógicas e gerenciáveis.

Nesta Tarefa, você vai refatorar seu sistema de catálogo de cursos existente para seguir os princípios do MVC. Isso tornará seu código mais organizado, mais fácil de entender e mais simples de expandir com novas funcionalidades.

Entendendo a Arquitetura MVC

O MVC separa sua aplicação em três componentes principais:

  • Model: Lida com dados e lógica de negócios. Suas informações de cursos e funções para acessá-los.
  • View: Lida com a apresentação. Seus modelos EJS que exibem dados para os usuários.
  • Controller: Lida com as requisições do usuário e coordena entre modelos e visualizações. Seus manipuladores de rota.

A partir deste ponto, a estrutura da sua aplicação usará um src/ diretório para organizar todo o código principal da sua aplicação, enquanto os ativos estáticos permanecem em public/.

Por que refatorar?

A refatoração é o processo de reestruturar o código existente sem alterar sua funcionalidade. Esta é uma habilidade valiosa no desenvolvimento profissional, pois ajuda a manter a qualidade do código e torna as aplicações mais fáceis de trabalhar à medida que crescem.

Instruções da Tarefa

1. Limpe e prepare seu código

Antes de reestruturar sua aplicação, você precisa limpar as funcionalidades que não são mais necessárias. No desenvolvimento profissional, os requisitos frequentemente mudam e as funcionalidades são removidas ou reformuladas.

Remova a funcionalidade de produtos: Durante as Tarefas anteriores, você provavelmente criou uma página de produtos e a funcionalidade relacionada. Esta funcionalidade não faz mais parte do design da nossa aplicação e deve ser completamente removida.

Examine seu código atual e remova todos os vestígios de:

  • Quaisquer manipuladores de rota de produtos em server.js
  • Links de produtos na sua navegação (verifique o arquivo parcial do cabeçalho)
  • Quaisquer modelos EJS relacionados a produtos
  • Quaisquer dados ou variáveis de produtos que você possa ter criado

Simplifique e limpe: Enquanto trabalha, procure também por oportunidades para:

  • Remover código comentado que não seja mais necessário
  • Combinar funções de middleware semelhantes, caso você tenha várias
  • Atualizar comentários para refletir a funcionalidade atual
  • Remover quaisquer variáveis ou importações não utilizadas

Se algo não estiver funcionando, não prossiga para a etapa final. Depure o problema primeiro. Problemas comuns incluem caminhos de arquivo incorretos em instruções de importação ou arquivos ausentes na nova estrutura de diretórios.

2. Crie a estrutura de diretórios MVC

Crie a estrutura de diretórios para a sua arquitetura MVC. Você precisa organizar seu código em pastas lógicas dentro de cada camada MVC:

  • Crie src/models/catalog/ para dados de cursos e lógica de negócios
  • Crie src/controllers/catalog/ para manipuladores de rota relacionados a cursos
  • Crie src/controllers/ para o seu arquivo principal de rotas e controladores básicos de página
  • Crie src/middleware/ para suas funções de middleware personalizadas
  • Crie src/middleware/demo/ para o middleware específico de rota necessário para a página de demonstração

A estrutura do seu Projeto deve ser semelhante à seguinte quando você tiver concluído esta Tarefa. Alguns arquivos foram omitidos por brevidade:

4. Mova e Organize Seu Middleware

Mova suas funções de middleware para src/middleware/global.js. Este middleware adicionará dados a res.locals, tornando-os disponíveis para todos os seus modelos.

Quando você adiciona dados a res.locals, cada modelo na sua aplicação pode acessar esses valores. Os modelos simplesmente usam os valores de que precisam e ignoram o restante. Isso é útil para dados como o ano atual, configurações de ambiente ou parâmetros de consulta que muitos modelos podem usar.

Crie seu arquivo de middleware global com esta função consolidada: 


        /**
         * Helper function to get the current greeting based on the time of day.
         */
        const getCurrentGreeting = () => {
            const currentHour = new Date().getHours();

            if (currentHour < 12) {
                return 'Good Morning!';
            }
            
            if (currentHour < 18) {
                return 'Good Afternoon!';
            }

            return 'Good Evening!';
        };

        /**
         * Middleware to add local variables to res.locals for use in all templates.
         * Templates can access these values but are not required to use them.
         */
        const addLocalVariables = (req, res, next) => {
            // Set current year for use in templates
            res.locals.currentYear = new Date().getFullYear();

            // Make NODE_ENV available to all templates
            res.locals.NODE_ENV = process.env.NODE_ENV?.toLowerCase() || 'production';

            // Make req.query available to all templates
            res.locals.queryParams = { ...req.query };

            // Set greeting based on time of day
            res.locals.greeting = `<p>${getCurrentGreeting()}</p>`;

            // Randomly assign a theme class to the body
            const themes = ['blue-theme', 'green-theme', 'red-theme'];
            const randomTheme = themes[Math.floor(Math.random() * themes.length)];
            res.locals.bodyClass = randomTheme;

            // Continue to the next middleware or route handler
            next();
        };

        export { addLocalVariables };

Em seguida, crie src/middleware/demo/headers.js para middleware específico de rota:

Entendendo o res.locals

O res.locals objeto é a maneira do Express de passar dados para modelos. Qualquer propriedade que você adicionar ao res.locals fica disponível para todos os modelos que são renderizados durante essa requisição. Pense nisso como um contêiner de dados compartilhado que viaja com a resposta pela sua aplicação.

Os modelos não precisam usar todos os valores em res.locals, enquanto sua página de demonstração pode usar currentYeare greeting e bodyClass. Outros modelos podem nem usar esses valores, e está tudo bem.

5. Crie Seus Manipuladores de Rota (Controladores)

Os manipuladores de rota (também chamados de controladores) são funções de middleware que lidam com requisições HTTP e enviam respostas. Na arquitetura MVC, eles coordenam entre modelos e visualizações.

Crie src/controllers/catalog/catalog.js para a funcionalidade do catálogo de cursos: 


        import { getAllCourses, getCourseById, getSortedSections } from '../../models/catalog/catalog.js';

        // Route handler for the course catalog list page
        const catalogPage = (req, res) => {
            const courses = getAllCourses();
            
            res.render('catalog', {
                title: 'Course Catalog',
                courses: courses
            });
        };

        // Route handler for individual course detail pages
        const courseDetailPage = (req, res, next) => {
            const courseId = req.params.courseId;
            const course = getCourseById(courseId);
            
            // If course doesn't exist, create 404 error
            if (!course) {
                const err = new Error(`Course ${courseId} not found`);
                err.status = 404;
                return next(err);
            }
            
            // Handle sorting if requested
            const sortBy = req.query.sort || 'time';
            const sortedSections = getSortedSections(course.sections, sortBy);
            
            res.render('course-detail', {
                title: `${course.id} - ${course.title}`,
                course: { ...course, sections: sortedSections },
                currentSort: sortBy
            });
        };

        export { catalogPage, courseDetailPage };

6. Construa Seu Arquivo de Rotas

As rotas conectam URLs a funções manipuladoras de rota. O Express Router ajuda a organizar rotas em módulos gerenciáveis. Construiremos este arquivo passo a passo para que você entenda como ele funciona.

Crie src/controllers/routes.js e comece com a configuração básica: 


        import { Router } from 'express';

        // Create a new router instance
        const router = Router();

        // TODO: Add import statements for controllers and middleware
        // TODO: Add route definitions

        export default router;

Agora adicione as instruções de importação para seus controladores e middleware. Você precisará importar:

  • O middleware de cabeçalhos de demonstração de ../middleware/demo/headers.js
  • Os controladores do catálogo de ./catalog/catalog.js
  • Os controladores de páginas básicas de ./index.js

Adicione essas importações após a importação do Router: 


        import { addDemoHeaders } from '../middleware/demo/headers.js';
        import { catalogPage, courseDetailPage } from './catalog/catalog.js';
        import { homePage, aboutPage, demoPage, testErrorPage } from './index.js';

Por fim, adicione suas definições de rota. As rotas seguem o padrão router.get(path, handler) ou router.get(path, middleware, handler): 


        // Home and basic pages
        router.get('/', homePage);
        router.get('/about', aboutPage);

        // Course catalog routes
        router.get('/catalog', catalogPage);
        router.get('/catalog/:courseId', courseDetailPage);

        // Demo page with special middleware
        router.get('/demo', addDemoHeaders, demoPage);

        // Route to trigger a test error
        router.get('/test-error', testErrorPage);

Depois de concluir o seu routes.js arquivo, reserve um momento para entender como cada parte funciona:

  • O Router cria um manipulador de rota modular e montável
  • Instruções de importação trazem as funções de que você precisa
  • As definições de rota conectam padrões de URL a funções manipuladoras
  • Algumas rotas podem incluir middleware que é executado antes do manipulador final
Entendendo o Express Router

O Router é como uma miniaplicação Express. Ele pode lidar com middlewares e rotas, mas precisa ser montado na aplicação principal para funcionar. Isso permite organizar rotas relacionadas e depois anexá-las todas de uma vez.

7. Atualize seu server.js

Agora atualize o seu server.js para usar a estrutura MVC. Seu arquivo de servidor deve se concentrar apenas na configuração e preparação, enquanto a lógica da aplicação reside nos componentes MVC.

Substitua o conteúdo do seu server.js existente por: 


        import express from 'express';
        import path from 'path';
        import { fileURLToPath } from 'url';

        // Import MVC components
        import routes from './src/controllers/routes.js';
        import { addLocalVariables } from './src/middleware/global.js';

        /**
         * Server configuration
         */
        const __filename = fileURLToPath(import.meta.url);
        const __dirname = path.dirname(__filename);
        const NODE_ENV = process.env.NODE_ENV?.toLowerCase() || 'production';
        const PORT = process.env.PORT || 3000;

        /**
         * Setup Express Server
         */
        const app = express();

        /**
         * Configure Express
         */
        app.use(express.static(path.join(__dirname, 'public')));
        app.set('view engine', 'ejs');
        app.set('views', path.join(__dirname, 'src/views'));

        /**
         * Global Middleware
         */
        app.use(addLocalVariables);

        /**
         * Routes
         */
        app.use('/', routes);

        /**
         * Error Handling
         */
        
        // 404 handler
        app.use((req, res, next) => {
            const err = new Error('Page Not Found');
            err.status = 404;
            next(err);
        });

        // Global error handler
        app.use((err, req, res, next) => {
            // Prevent infinite loops, if a response has already been sent, do nothing
            if (res.headersSent || res.finished) {
                return next(err);
            }
            
            // Determine status and template
            const status = err.status || 500;
            const template = status === 404 ? '404' : '500';

            // Prepare data for the template
            const context = {
                title: status === 404 ? 'Page Not Found' : 'Server Error',
                error: NODE_ENV === 'production' ? 'An error occurred' : err.message,
                stack: NODE_ENV === 'production' ? null : err.stack,
                NODE_ENV // Our WebSocket check needs this and its convenient to pass along
            };

            // Render the appropriate error template with fallback
            try {
                res.status(status).render(`errors/${template}`, context);
            } catch (renderErr) {
                // If rendering fails, send a simple error page instead
                if (!res.headersSent) {
                    res.status(status).send(`<h1>Error ${status}</h1><p>An error occurred.</p>`);
                }
            }
        });

        /**
         * Start WebSocket Server in Development Mode; used for live reloading
         */
        if (NODE_ENV.includes('dev')) {
            const ws = await import('ws');

            try {
                const wsPort = parseInt(PORT) + 1;
                const wsServer = new ws.WebSocketServer({ port: wsPort });

                wsServer.on('listening', () => {
                    console.log(`WebSocket server is running on port ${wsPort}`);
                });

                wsServer.on('error', (error) => {
                    console.error('WebSocket server error:', error);
                });
            } catch (error) {
                console.error('Failed to start WebSocket server:', error);
            }
        }

        /**
         * Start Server
         */
        app.listen(PORT, () => {
            console.log(`Server is running on http://127.0.0.1:${PORT}`);
        });

Observe como está muito mais limpo o server.js agora. Ele se concentra apenas na configuração e preparação, enquanto a lógica real da aplicação foi movida para os componentes MVC.

Entendendo o manipulador de erros

O manipulador de erros global possui uma assinatura especial de quatro parâmetros (err, req, res, next) que diz ao Express para usá-lo para erros. O res.headersSent e res.finished as verificações evitam tentar enviar uma resposta duas vezes, o que derrubaria o servidor. O bloco try-catch em torno de res.render() fornece uma alternativa de contingência caso o próprio modelo de erro apresente problemas, garantindo que os usuários sempre vejam algo em vez de uma página em branco.

Em produção, ocultamos os detalhes do erro dos usuários por motivos de segurança, enquanto em desenvolvimento mostramos a mensagem de erro completa e o rastreamento da pilha para ajudar na depuração.

  • Acesse http://127.0.0.1:3000/test-error (Testar tratamento de erros)
  • Acesse http://127.0.0.1:3000/invalid (Testar erro 404)

Tudo deve funcionar exatamente como antes, mas agora seu código está organizado usando princípios de MVC!

Se algo não estiver funcionando, não prossiga para a etapa final. Depure o problema primeiro. Problemas comuns incluem caminhos de arquivos incorretos em instruções de importação ou arquivos ausentes na nova estrutura de diretórios.

Agora que sua refatoração MVC está funcionando, é hora da limpeza final. Esta etapa ajudará você a desenvolver bons hábitos profissionais em relação à manutenção e qualidade do código.

Desenvolvedores profissionais dedicam um tempo significativo à limpeza e documentação do código. Um código limpo e bem organizado é mais fácil de manter, depurar e estender com novas funcionalidades. Entendendo o que você conquistou

Você refatorou sua aplicação com sucesso para usar a arquitetura MVC. Aqui está o que cada componente faz agora:

MVC em ação
  • Modelos (src/models/catalog/catalog.js): Armazenam dados dos cursos e fornecem funções para acessá-los. Eles não sabem nada sobre HTTP ou requisições web.
  • Views (src/views/): Seus modelos EJS que exibem dados. Eles recebem dados dos controladores e os apresentam aos usuários.
  • Controllers (src/controllers/catalog/, src/controllers/index.js): Lidam com requisições web, usam modelos para obter dados e decidem quais views renderizar.

Esta separação torna seu código mais fácil de entender, manter e expandir. Quando você precisa adicionar novas funcionalidades, sabe exatamente onde cada tipo de código deve ficar.

A estrutura de diretórios que você criou também segue convenções profissionais. Funcionalidades relacionadas são agrupadas e cada arquivo tem um nome claro e descritivo que indica seu propósito.

Resumo dos Conceitos-Chave

A arquitetura MVC fornece uma separação clara de responsabilidades que torna as aplicações mais fáceis de manter. Os dados dos seus cursos ficam nos modelos, sua lógica de apresentação fica nas views e a manipulação de requisições fica nos controladores.

O processo de refatoração que você acabou de concluir é uma habilidade profissional valiosa. Você pegou um código funcional e o reorganizou para torná-lo mais fácil de manter sem alterar sua funcionalidade. Esse tipo de organização de código torna-se crucial à medida que as aplicações crescem em tamanho e complexidade.

Você também aprendeu a usar o Express Router, que permite organizar rotas em módulos lógicos. Isso facilita o gerenciamento de diferentes áreas da sua aplicação e mantém o arquivo principal do servidor focado em configuração em vez de lógica de negócios.

Com esse fundamento estabelecido, você está pronto para construir funcionalidades mais sofisticadas e, eventualmente, conectar-se a bancos de dados reais, já que os modelos fornecem uma interface limpa que pode ser atualizada sem afetar o restante da sua aplicação.

Abordagem Alternativa: MVC Orientado a Domínio

No desenvolvimento profissional, você pode encontrar Design Orientado a Domínio, onde cada domínio de negócios (como cursos, contas ou administração) possui sua própria estrutura MVC completa. Em vez de organizar por camadas (todos os controladores juntos), tudo para um único domínio permanece junto.

MVC baseado em camadas (o que você acabou de construir): 


            src/
            ├── controllers/
            │   ├── catalog/
            │   └── index.js
            ├── models/
            │   └── catalog/
            └── views/
                └── catalog/

MVC baseado em domínios (abordagem alternativa): 


            src/
            ├── catalog/
            │   ├── controllers/
            │   ├── models/
            │   └── views/
            └── accounts/
                ├── controllers/
                ├── models/
                └── views/

Ambas as abordagens usam princípios MVC, mas organizam os arquivos de forma diferente. A abordagem baseada em camadas (a que você aprendeu) é mais comum para aprender conceitos de MVC, enquanto a baseada em domínios pode ser útil para aplicações grandes com áreas de negócios distintas.

Experimente e Estenda

Agora que você tem a estrutura MVC estabelecida, considere estas melhorias para aprofundar seu entendimento:

  1. Adicionar uma Página de Departamentos: Use a getCoursesByDepartment() função para criar uma página que liste os cursos agrupados por departamento. Você precisará de um novo controlador, rota e view.
  2. Expanda seus Controladores: Adicione uma lógica mais sofisticada para manipular diferentes tipos de requisições ou preferências de usuário, como filtragem por horas de crédito ou professor.
  3. Pratique Mais Refatoração: Deixamos os manipuladores de erro no arquivo server.js. Mova-os para controllers em algum lugar lógico e, em seguida, importe e registre-os na seção de rotas do seu arquivo server.js.

Estes experimentos ajudam você a entender como a arquitetura MVC se escala para dar suporte a funcionalidades mais complexas, mantendo seu código organizado e fácil de manter. Cada adição deve se encaixar de forma limpa na estrutura que você criou.

Conclusão

Você transformou com sucesso uma aplicação Express monolítica em uma arquitetura MVC bem organizada. Esta refatoração demonstra várias habilidades importantes de desenvolvimento profissional: organização de código, separação de responsabilidades e manutenção de funcionalidade enquanto melhora a estrutura.

O padrão MVC que você implementou fornece um fundamento sólido para construir aplicações web maiores e mais complexas. À medida que continua desenvolvendo suas habilidades, você descobrirá que essa abordagem organizada torna a depuração mais fácil, o desenvolvimento de funcionalidades mais previsível e a colaboração em equipe mais eficaz.

Em tarefas futuras, você se baseará nesse fundamento MVC para adicionar funcionalidades mais sofisticadas, como integração com banco de dados, autenticação de usuário e padrões avançados de roteamento.
