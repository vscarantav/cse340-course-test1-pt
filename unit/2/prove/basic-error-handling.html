Implementando o Tratamento de Erros no Express

Nesta tarefa, você construirá um sistema profissional de tratamento de erros para a sua aplicação Express. Em vez de permitir que os usuários vejam mensagens técnicas confusas ou telas em branco quando algo der errado, você criará páginas de erro personalizadas que mantêm o design do seu site e ajudam os usuários a entender o que aconteceu.

Você implementará o padrão de manipulador de erro global que aprendeu, criará modelos de erro dedicados para diferentes situações e configurará a rota genérica que garante que nenhuma requisição fique sem resposta. Ao final, sua aplicação tratará os problemas de forma elegante e fornecerá uma experiência do usuário aprimorada, mesmo quando as coisas não funcionarem como esperado.

Organizando Seus Modelos de Erro

Aplicações profissionais mantêm modelos de erro em um diretório dedicado para clareza e manutenibilidade. Se ainda não o fez, crie uma errors pasta dentro do seu views diretório. Se você já possui este diretório dos passos anteriores, basta continuar adicionando seus modelos de erro lá.

Sua estrutura de diretório deve ser assim: 


        src/
        └── views/
            ├── errors/
            ├── partials/
            └── [your existing pages]

Instruções da Tarefa

1. Crie sua Página de Erro 404

Comece criando o modelo que os usuários verão quando requisitarem uma página que não existe. Encontre uma imagem 404 envolvente ou um GIF animado online, salve-o em seu public/images/ diretório e crie um novo arquivo chamado 404.ejs no seu views/errors diretório. 


        <%- include('../partials/header') %>
        <main>
            <h1>Page Not Found</h1>
            <p>The page you are looking for does not exist.</p>
            <img src="/images/your-404-image.gif" alt="404 Not Found">
            <p>Return to the <a href="/">homepage</a> to continue browsing.</p>
        </main>
        <%- include('../partials/footer') %>

Substitua your-404-image.gif com o nome de arquivo real da sua imagem e atualize o texto alt para descrever sua imagem. Escolha algo que se adapte à personalidade do seu site – o humor geralmente funciona bem para páginas 404.

2. Crie sua Página de Erro 500

Quando sua aplicação encontrar problemas inesperados, os usuários precisam ver uma mensagem útil em vez de detalhes técnicos. Crie 500.ejs no seu views/errors diretório: 


        <%- include('../partials/header') %>
        <main>
            <h1>Something Went Wrong</h1>
            <p>We are experiencing technical difficulties. Our team has been notified and is working to fix the issue.</p>
            <p><a href="/">Return to homepage</a></p>
            
            <% if (NODE_ENV === 'development') { %>
                <details open>
                    <summary>Error Details (Development Only)</summary>
                    <pre><%= error %></pre>
                    <pre><%= stack %></pre>
                </details>
            <% } %>
        </main>
        <%- include('../partials/footer') %>

Este modelo mostra uma mensagem amigável ao usuário enquanto oculta detalhes técnicos dos usuários em produção. O details elemento cria uma seção expansível que só aparece durante o desenvolvimento.

3. Implemente a Rota Genérica

Adicione este middleware ao seu server.js arquivo após todas as suas rotas reais, mas antes de iniciar o servidor. Isso cria um erro 404 para qualquer requisição que não corresponda às suas rotas definidas: 


        // Catch-all route for 404 errors
        app.use((req, res, next) => {
            const err = new Error('Page Not Found');
            err.status = 404;
            next(err);
        });

Este middleware só é executado quando nenhuma outra rota corresponde, criando um erro 404 e encaminhando-o para o seu manipulador de erro global. Definir err.status = 404 diz ao seu manipulador de erro qual tipo de erro ocorreu.

4. Crie o Manipulador de Erro Global

Adicione este middleware de tratamento de erros após a sua rota genérica. Isso representa uma abordagem para o tratamento de erros centralizado no Express. Ao usar um único manipulador de erro com a assinatura de quatro parâmetros (err, req, res, next), podemos capturar erros de qualquer lugar em nossa aplicação e apresentá-los de forma consistente aos usuários: 


        // Global error handler
        app.use((err, req, res, next) => {
            // Prevent infinite loops, if a response has already been sent, do nothing
            if (res.headersSent || res.finished) {
                return next(err);
            }
            
            // Determine status and template
            const status = err.status || 500;
            const template = status === 404 ? '404' : '500';

            // Prepare data for the template
            const context = {
                title: status === 404 ? 'Page Not Found' : 'Server Error',
                error: NODE_ENV === 'production' ? 'An error occurred' : err.message,
                stack: NODE_ENV === 'production' ? null : err.stack,
                NODE_ENV // Our WebSocket check needs this and its convenient to pass along
            };

            // Render the appropriate error template with fallback
            try {
                res.status(status).render(`errors/${template}`, context);
            } catch (renderErr) {
                // If rendering fails, send a simple error page instead
                if (!res.headersSent) {
                    res.status(status).send(`<h1>Error ${status}</h1><p>An error occurred.</p>`);
                }
            }
        });

Este manipulador captura todos os erros, registra logs deles para os desenvolvedores e renderiza o modelo apropriado com base no código de status do erro. O registro de logs ajuda você na depuração de problemas, enquanto os modelos fornecem uma experiência aprimorada para os usuários.

Principais funcionalidades desta abordagem:

  • Usa o código de status do erro ou usa 500 como padrão
  • Oculta detalhes sensíveis de erros em ambientes de produção
  • Inclui um callback para capturar erros de renderização, prevenindo falhas recursivas
  • Se o próprio modelo de erro falhar, recorre a uma resposta HTML simples como alternativa de contingência

Neste curso, manteremos nosso manipulador de erros simples e nos concentraremos em outros conceitos fundamentais. No entanto, você pode expandi-lo lançando erros personalizados com códigos de status específicos (como 401 para não autorizado ou 403 para acesso proibido) e criando visualizações de erro exclusivas para cada um. Basta definir a propriedade status do erro antes de lançá-lo, e este manipulador renderizará o modelo apropriado.

5. Teste Seu Tratamento de Erros

Crie uma rota de teste para disparar um erro 500. Adicione esta rota antes do seu middleware genérico (catch-all): 


        // Test route for 500 errors
        app.get('/test-error', (req, res, next) => {
            const err = new Error('This is a test error');
            err.status = 500;
            next(err);
        });

Agora teste ambos os tipos de erro:

  • Erro 404: Visite qualquer página inexistente como http://127.0.0.1:3000/does-not-exist
  • Erro 500: Visite http://127.0.0.1:3000/test-error

Ambos devem exibir suas páginas de erro personalizadas em vez das mensagens de erro padrão do navegador. Verifique o console do seu servidor para confirmar que os erros estão sendo registrados no log adequadamente.

A Ordem Importa

A rota genérica (catch-all) deve vir depois das suas rotas reais, mas antes do seu manipulador de erros. O Express processa os middlewares em ordem, portanto, posicioná-los incorretamente impedirá que funcionem adequadamente.

Resumo dos Conceitos-Chave

Você implementou com sucesso um sistema profissional de tratamento de erros que transforma a maneira como sua aplicação responde a problemas. Em vez de confundir os usuários com mensagens técnicas ou falhar completamente, sua aplicação agora fornece páginas de erro úteis e personalizadas com a sua marca, mantendo a confiança do usuário e guiando-o de volta às partes funcionais do seu site.

O padrão de manipulador de erros global centraliza todo o processamento de erros, tornando sua aplicação mais fácil de manter e garantindo respostas consistentes. A rota genérica (catch-all) garante que os erros 404 fluam pelo mesmo sistema que outros erros, criando uma abordagem unificada para o gerenciamento de erros.

Este fundamento prepara você para técnicas mais avançadas de tratamento de erros, incluindo o registro de erros em log para serviços externos, a criação de diferentes respostas de erro para requisições de API versus páginas da web e a implementação de funcionalidades amigáveis de recuperação de erros.

O código que fornecemos para você nesta Tarefa inclui um efeito colateral significativo do qual você deve estar ciente. Conforme escrito atualmente, ele suporta explicitamente apenas erros 404 e 500. Se você lançar qualquer outro erro no intervalo de 400 a 599, ele será tratado como um erro 500, o que pode ocultar o problema real e tornar a depuração mais difícil.

Além disso, se o seu modelo de erro lançar um erro durante a renderização (por exemplo, devido a um bug ou dados ausentes), o servidor falhará completamente. Esse tipo de falha não é tratado pelo nosso código e pode derrubar toda a aplicação em produção.

Experimente e Estenda

Agora que seu sistema de tratamento de erros funciona, tente estas melhorias usando os conceitos que você acabou de aprender:

  1. Teste Diferentes Tipos de Erros: Crie rotas de teste adicionais que disparem diferentes tipos de erros e observe como seu manipulador global os processa.
  2. Personalize Suas Páginas de Erro: Adicione mais estilos, links úteis ou funcionalidade de busca para tornar suas páginas de erro mais úteis.
  3. Adicione Logs Mais Detalhados: Aprimore seu registro de erros em log para incluir marcações de data/hora, URLs de requisição e informações do agente do usuário.

Estes experimentos ajudam você a entender como o tratamento de erros se comporta em diferentes situações e oferecem prática personalizando o sistema para suas necessidades específicas.
