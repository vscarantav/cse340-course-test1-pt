Middleware Revisitado: Entendendo o Coração do Express

À medida que suas aplicações Express se tornam mais complexas, você enfrenta desafios recorrentes: Como autenticar usuários em várias rotas? Como registrar logs de requisições de forma consistente? Como validar dados de entrada sem repetir o mesmo código em todos os lugares? Como tratar erros de forma elegante em toda a sua aplicação?

Esses desafios têm uma solução comum no Express: middleware. Você já usou middleware sem perceber toda vez que chamou app.use(express.static()) ou criou manipuladores de erros. Agora é hora de entender o middleware em profundidade, aprendendo como ele funciona e como criar suas próprias funções de middleware que tornam suas aplicações mais organizadas, fáceis de manter e poderosas.

O Problema que o Middleware Resolve

Imagine construir um site de e-commerce onde certas rotas exigem autenticação de usuário, outras precisam de privilégios de administrador, algumas precisam de log de requisição e todas precisam de tratamento de erros. Sem o middleware, você acabaria copiando o mesmo código de autenticação, código de log e código de tratamento de erros em cada manipulador de rota. Seu código se tornaria repetitivo, difícil de manter e propenso a inconsistências.

O middleware resolve isso criando um sistema de pipeline onde cada requisição passa por uma série de funções antes de atingir seu destino final. Cada função no pipeline pode realizar tarefas específicas, como verificar a autenticação, registrar logs de requisições, validar dados ou tratar erros. Isso cria uma separação limpa de responsabilidades, onde cada parte da funcionalidade tem sua própria função dedicada.

O que é Exatamente Middleware?

O middleware no Express é qualquer função que tem acesso à requisição (req) e resposta (res) objetos, além da capacidade de passar o controle para a próxima função no pipeline. Pense no middleware como pontos de verificação pelos quais toda requisição deve passar em sua jornada desde a chegada ao seu servidor até o envio de uma resposta de volta ao usuário.

Cada função de middleware pode examinar a requisição, modificá-la, realizar operações como consultas ao banco de dados ou chamadas de API externas e, em seguida, enviar uma resposta imediatamente ou passar o controle para a próxima função de middleware. Isso cria um sistema flexível e modular onde você pode compor comportamentos complexos da aplicação a partir de funções simples e focadas.

Middleware como uma Linha de Montagem de Fábrica

Pense no middleware como estações em uma linha de montagem. Cada estação (função de middleware) realiza uma tarefa específica no produto (requisição HTTP) à medida que ele avança na linha. Algumas estações podem adicionar componentes, outras podem inspecionar a qualidade e a estação final empacota o produto acabado (envia a resposta). Cada estação pode continuar o processo ou interrompê-lo se algo estiver errado.

Três Tipos de Funções de Middleware

O Express reconhece diferentes tipos de middleware com base em suas assinaturas de função, permitindo lidar com cada tipo adequadamente no ciclo de requisição-resposta:

Middleware Genérico

Assinatura: (req, res, next) => { ... }

Este é o tipo mais comum de middleware, usado para qualquer lógica que precise de acesso aos objetos de requisição e resposta, mas que não seja o manipulador final. O middleware genérico normalmente realiza operações como autenticação, log, validação de dados ou modificação de requisições, e então chama next() para continuar o pipeline.

Manipuladores de Rota

Assinatura: (req, res) => { ... }

Os manipuladores de rota são o destino final no pipeline de middleware para requisições bem-sucedidas. Eles normalmente enviam a resposta usando métodos como res.send(), res.render(), ou res.json(). Como eles encerram o ciclo de requisição-resposta, eles não precisam de acesso à função next.

Middleware de Tratamento de Erros

Assinatura: (err, req, res, next) => { ... }

O middleware de tratamento de erros tem quatro parâmetros em vez de três, com o objeto de erro como primeiro parâmetro. O Express usa essa assinatura para identificar manipuladores de erro e só os invoca quando ocorre um erro. Essas funções fornecem um processamento de erros centralizado para toda a sua aplicação. 


        // Generic middleware - logs all requests
        app.use((req, res, next) => {
            console.log(`${req.method} ${req.url}`);
            next(); // Continue to next middleware
        });
        
        // Route handler - ends the request-response cycle
        app.get('/home', (req, res) => {
            res.send('Welcome home!');
        });
        
        // Error handler - processes errors
        app.use((err, req, res, next) => {
            console.error(err.message);
            res.status(500).send('Something went wrong!');
        });

O Papel Crítico de next()

A next() função é o que conecta os middlewares, criando o pipeline que processa requisições. Quando uma função de middleware chama next(), ela informa ao Express para continuar para o próximo middleware ou manipulador de rota na cadeia. Se next() nunca for chamada, o ciclo de requisição-resposta para prematuramente, deixando o cliente esperando indefinidamente.

A next() função tem comportamentos diferentes dependendo do que você passa para ela:

  • next() – Continuar para o próximo middleware que não seja de erro
  • next(err) – Ignorar todos os middlewares restantes que não sejam de erro e pular para o primeiro manipulador de erro
  • next('route') – Ignorar os middlewares restantes para a rota atual e tentar a próxima rota 

        // Middleware that conditionally continues or stops
        app.use((req, res, next) => {
            if (!req.headers['authorization']) {
                // Create error and skip to error handler
                const err = new Error('Authorization header required');
                err.status = 401;
                return next(err);
            }
            
            // All good, continue to next middleware
            next();
        });
        
        // This only runs if authorization header exists
        app.use((req, res, next) => {
            console.log('User is authenticated');
            next();
        });
        
        // Error handler catches authentication failures
        app.use((err, req, res, next) => {
            res.status(err.status || 500).send(err.message);
        });
Erro Comum de Middleware

Esquecer de chamar next() é um dos erros de middleware mais comuns. Se você não chamar next() e não enviar uma resposta, o cliente ficará travado esperando por uma resposta que nunca chega. Certifique-se sempre de que seu middleware chame next() ou envie uma resposta.

Compartilhando Dados Entre Middlewares: req e res.locals

Os req e res objetos são compartilhados entre todas as funções de middleware no pipeline, tornando-os perfeitos para passar dados entre middlewares. Embora você possa anexar propriedades diretamente ao objeto req, o Express fornece res.locals como uma abordagem mais organizada e convencional para armazenar dados que devem estar disponíveis para outros middlewares e modelos. 


        // Middleware to determine user role
        app.use((req, res, next) => {
            // Set user role based on query parameter or default to guest
            res.locals.userRole = req.query.role || 'guest';
            res.locals.timestamp = new Date().toISOString();
            next();
        });
        
        // Middleware that uses the role data
        app.use((req, res, next) => {
            console.log(`User role: ${res.locals.userRole}`);
            next();
        });
        
        // Route handler that uses the data
        app.get('/dashboard', (req, res) => {
            res.send(`
                <h1>Dashboard</h1>
                <p>Role: ${res.locals.userRole}</p>
                <p>Time: ${res.locals.timestamp}</p>
            `);
        });
Por que o res.locals é Especial

Os dados armazenados em res.locals são automaticamente acessíveis por motores de modelos como o EJS sem a necessidade de passá-los explicitamente na chamada de res.render(). Isso o torna perfeito para dados de que múltiplos modelos precisam, como informações do usuário ou configuração do site. No entanto, esteja ciente de que todos os modelos podem acessar esses dados, portanto, evite armazenar informações confidenciais neles.

Middleware Global: Afetando Cada Requisição

O middleware global se aplica a cada requisição de entrada e é normalmente usado para funcionalidades em todo o aplicativo, como registro de log, cabeçalhos de segurança ou configuração de dados comuns. O middleware global deve ser definido logo no início da sua aplicação, antes da lógica específica da rota, para que possa afetar todas as requisições subsequentes. 


        // Global request logging
        app.use((req, res, next) => {
            const timestamp = new Date().toISOString();
            console.log(`[${timestamp}] ${req.method} ${req.url}`);
            next();
        });
        
        // Global security headers
        app.use((req, res, next) => {
            res.setHeader('X-Frame-Options', 'DENY');
            res.setHeader('X-Content-Type-Options', 'nosniff');
            next();
        });
        
        // Global user context setup
        app.use((req, res, next) => {
            // Set default user context
            res.locals.isLoggedIn = false;
            res.locals.userName = 'Guest';
            // In a real app, you'd check authentication here
            next();
        });
        
        // All routes defined after this point will have these middleware applied
        app.get('/', (req, res) => {
            res.send(`Hello, ${res.locals.userName}!`);
        });

Middleware Específico de Rota: Aplicação Seletiva

O middleware específico de rota é executado apenas para rotas específicas, permitindo aplicar a lógica de forma seletiva em vez de global. Isso é particularmente útil para funcionalidades como verificações de autenticação, validação de entrada ou registro de log especializado que se aplica apenas a determinados endpoints.

Você pode aplicar middleware a rotas específicas passando funções de middleware como argumentos para métodos de rota antes do manipulador de rota final. O Express as executará em ordem, e cada uma deve chamar next() para continuar para a próxima função. 


        // Define reusable middleware functions
        const logAccess = (req, res, next) => {
            console.log(`Access attempt to ${req.url}`);
            next();
        };
        
        const requireAdmin = (req, res, next) => {
            // In a real app, you'd check actual authentication
            if (req.headers.role !== 'admin') {
                return res.status(403).send('Admin access required');
            }
            next();
        };
        
        const requireAuth = (req, res, next) => {
            if (!req.headers.authorization) {
                return res.status(401).send('Authentication required');
            }
            next();
        };
        
        // Public route - no middleware needed
        app.get('/', (req, res) => {
            res.send('Welcome to our site!');
        });
        
        // Protected route - requires authentication
        app.get('/profile', requireAuth, (req, res) => {
            res.send('Your profile information');
        });
        
        // Admin route - requires both logging and admin check
        app.get('/admin', logAccess, requireAdmin, (req, res) => {
            res.send('Admin dashboard');
        });
        
        // Multiple middleware functions in sequence
        app.get('/secure-admin', logAccess, requireAuth, requireAdmin, (req, res) => {
            res.send('Super secure admin area');
        });
A Magia da Composição de Middleware

Você pode passar quantas funções de middleware quiser para uma rota, e o Express as executará em ordem. Cada uma atua como um ponto de verificação que deve aprovar a requisição antes que ela continue. Isso permite compor lógicas complexas de autorização e validação a partir de funções simples e reutilizáveis. Pense nisso como construir com blocos de LEGO – cada middleware é um bloco simples que você pode combinar para criar estruturas complexas.

Middleware de Tratamento de Erros: Processamento Centralizado de Erros

O middleware de tratamento de erros fornece um local centralizado para processar todos os erros em sua aplicação. Essas funções especiais de middleware possuem quatro parâmetros e só são invocadas quando ocorre um erro, seja por meio de chamadas de next(err) ou exceções não capturadas em código síncrono. 


        // Regular middleware that might generate errors
        app.get('/risky-operation', (req, res, next) => {
            try {
                // Simulate an operation that might fail
                if (Math.random() < 0.5) {
                    throw new Error('Random failure occurred');
                }
                res.send('Operation succeeded!');
            } catch (error) {
                // Forward error to error handler
                next(error);
            }
        });
        
        // Error-handling middleware (must come after regular routes)
        app.use((err, req, res, next) => {
            // Log error details for developers
            console.error('Error occurred:', err.message);
            console.error('Stack trace:', err.stack);
            
            // Send appropriate response to user
            const status = err.status || 500;
            const message = status === 500 
                ? 'Internal server error' 
                : err.message;
                
            res.status(status).send(message);
        });

Entendendo o Fluxo do Middleware: A Ordem Importa

A ordem em que você define o middleware é crucial porque o Express os executa sequencialmente. O middleware definido anteriormente em seu código é executado antes do middleware definido posteriormente. Isso significa que o middleware global deve vir primeiro, seguido pelo middleware específico de rota, depois as rotas e, finalmente, o middleware de tratamento de erros. 


        // 1. Global middleware (runs for all requests)
        app.use((req, res, next) => {
            console.log('Global middleware executed');
            next();
        });
        
        // 2. Route with specific middleware
        app.get('/example', 
            (req, res, next) => {
                console.log('Route-specific middleware executed');
                next();
            },
            (req, res) => {
                console.log('Route handler executed');
                res.send('Response sent');
            }
        );
        
        // 3. Catch-all for 404 errors (after all real routes)
        app.use((req, res, next) => {
            const err = new Error('Page not found');
            err.status = 404;
            next(err);
        });
        
        // 4. Error handler (must come last)
        app.use((err, req, res, next) => {
            console.log('Error handler executed');
            res.status(err.status || 500).send(err.message);
        });

Quando uma requisição chega a /example, você verá esta saída no console: 


        Global middleware executed
        Route-specific middleware executed  
        Route handler executed

Melhores Práticas de Middleware

Seguir padrões estabelecidos torna seu middleware mais fácil de manter e de entender:

  • Use nomes descritivos: Nomeie suas funções de middleware de forma clara para indicar seu propósito (ex.: authenticateUser, logRequest, validateInput).
  • Mantenha o middleware focado: Cada função de middleware deve ter uma responsabilidade única e clara, em vez de tentar fazer várias coisas.
  • Use res.locals para dados compartilhados: Armazene dados de que múltiplos middlewares ou modelos precisam em res.locals em vez de modificar req diretamente.
  • Ordene os middlewares com atenção: Coloque o middleware global primeiro, o middleware específico de rota antes das rotas e os manipuladores de erro por último.
  • Sempre controle o fluxo: Todo middleware deve chamar next(), enviar uma resposta ou encaminhar um erro. Nunca deixe requisições pendentes.
  • Torne o middleware reutilizável: Escreva middlewares que possam ser aplicados a múltiplas rotas em vez de duplicar a lógica.
  • Trate erros com elegância: Use blocos try-catch para operações que possam falhar e encaminhe erros para manipuladores de erro usando next(err).

Exemplo Prático de Middleware

Aqui está um exemplo completo mostrando como partes do middleware funcionam juntas em uma aplicação realista: 


        import express from 'express';
        const app = express();
        
        // Global logging middleware
        app.use((req, res, next) => {
            const timestamp = new Date().toISOString();
            console.log(`[${timestamp}] ${req.method} ${req.url}`);
            next();
        });
        
        // Global user context setup
        app.use((req, res, next) => {
            res.locals.currentYear = new Date().getFullYear();
            res.locals.siteName = 'My Awesome App';
            next();
        });
        
        // Authentication middleware
        const authenticate = (req, res, next) => {
            const authHeader = req.headers.authorization;
            if (!authHeader) {
                const err = new Error('Authentication required');
                err.status = 401;
                return next(err);
            }
            
            // In a real app, you'd verify the token
            res.locals.user = { name: 'John Doe', role: 'user' };
            next();
        };
        
        // Admin check middleware
        const requireAdmin = (req, res, next) => {
            if (res.locals.user.role !== 'admin') {
                const err = new Error('Admin access required');
                err.status = 403;
                return next(err);
            }
            next();
        };
        
        // Public routes
        app.get('/', (req, res) => {
            res.send(`Welcome to ${res.locals.siteName}!`);
        });
        
        // Protected routes
        app.get('/dashboard', authenticate, (req, res) => {
            res.send(`Hello, ${res.locals.user.name}!`);
        });
        
        // Admin routes
        app.get('/admin', authenticate, requireAdmin, (req, res) => {
            res.send('Admin dashboard');
        });
        
        // 404 handler
        app.use((req, res, next) => {
            const err = new Error('Page not found');
            err.status = 404;
            next(err);
        });
        
        // Error handler
        app.use((err, req, res, next) => {
            console.error('Error:', err.message);
            res.status(err.status || 500).send(err.message);
        });
        
        app.listen(3000, () => {
            console.log('Server running on port 3000');
        });

Resumo dos Principais Conceitos

O middleware é o fundamento que torna as aplicações Express modulares, de fácil manutenção e poderosas. Ao entender como as funções de middleware funcionam juntas para criar um pipeline de processamento de requisições, você pode construir aplicações sofisticadas e organizadas.

As principais ideias que você aprendeu servirá ao longo de sua jornada de desenvolvimento com Express: funções de middleware processam requisições em sequência, a next() função controla o fluxo através do pipeline, res.locals fornece uma maneira limpa de compartilhar dados entre middlewares, e a ordenação adequada garante que sua aplicação se comporte de forma previsível.

Com esse profundo entendimento sobre middleware, você pode criar funções reutilizáveis que lidam com autenticação, registros de log, validação, processamento de erros e quaisquer outras preocupações transversais de que suas aplicações precisem. Essa abordagem modular torna seu código mais fácil de testar, de manter e de compreender à medida que suas aplicações aumentam em complexidade.

Explore Mais

Para aprofundar seu entendimento sobre middleware, tente criar suas próprias funções de middleware. Comece com ideias simples e avance gradualmente para funcionalidades mais complexas:

  • Crie um middleware de tempo de requisição que registra logs indicando quanto tempo cada requisição leva para ser processada
  • Construa um middleware simples de limitação de taxa (rate limiting) que rastreia requisições por endereço IP
  • Escreva um middleware de validação de tipo de conteúdo que garanta que requisições POST contenham o formato de dados esperado
  • Desenvolva um middleware personalizado de autenticação que verifique cabeçalhos ou parâmetros de consulta específicos

Estes exercícios ajudarão você a entender como funcionam os fluxos de middleware e como diferentes funções de middleware podem cooperar para criar comportamentos de aplicação sofisticados. A documentação do Express sobre como escrever middlewares fornece exemplos adicionais e padrões avançados para explorar.
